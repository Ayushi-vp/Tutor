How to build a new track (applies to every track below):
- Write prep-console/content/tracks/<key>.json. Each topic is
  { id, t, tag, sum, primer, body, deep, viz?, drill, qa, refs } — see prep-console/README.md and
  .claude/skills/topic-writer/references/schema.md. Use the topic-writer skill for style and length
  (same standard as the rewritten Networking, Python, Scale, GPU, ML and DL tracks).
- Ids must be unique across the whole app and never change once published (progress is keyed by id).
  Use the id prefix listed for each track.
- Check links: python prep-console/scripts/check_links.py tracks/<key>.json
- Register once: python prep-console/scripts/add_track.py <key> ... (see its docstring).
- Run the checks: backend pytest, frontend `npm test` and `npm run typecheck`.

1. Operating Systems        key: os     ids: os1–os14     group: Engineering    prereq: none
──────────────────────────────────────────────────────────────────────────────────────────────────
  os1   What an OS does: kernel vs user mode, system calls, context switches
  os2   Processes and threads: lifecycle, PCB, fork/exec, zombies and orphans
  os3   CPU scheduling: FCFS, SJF, round robin, priority, MLFQ, Linux CFS and EEVDF
  os4   Synchronization: race conditions, mutexes, semaphores, monitors, condition variables, spinlocks
  os5   Classic synchronization problems: producer-consumer, readers-writers, dining philosophers
  os6   Deadlocks: the four conditions, prevention, avoidance (Banker's algorithm), detection, recovery
  os7   Memory management: address spaces, paging, segmentation, page tables, TLB
  os8   Virtual memory: demand paging, page faults, replacement (FIFO, LRU, Clock), thrashing
  os9   Memory allocation: malloc, mmap, copy-on-write, fragmentation, OOM killer
  os10  File systems: inodes, directories, journaling, ext4/XFS, VFS, page cache
  os11  I/O: interrupts, DMA, blocking vs non-blocking, select/poll/epoll, io_uring  (link net13)
  os12  Inter-process communication: pipes, shared memory, message queues, signals, Unix sockets
  os13  Linux isolation: namespaces, cgroups, capabilities, seccomp  (sets up the Docker/K8s track)
  os14  Linux performance and debugging: top, vmstat, iostat, strace, perf, eBPF
  Labs: small C or Python scripts (a scheduler simulator, a page-replacement simulator, a
  producer-consumer with condition variables, reading /proc).
  Interview focus: classic OS theory questions (asked in SDE/campus loops) plus Linux in production.

──────────────────────────────────────────────────────────────────────────────────────────────────
2. Database Management Systems   key: db   ids: db1–db15   group: Engineering   prereq: sc4, sc5
──────────────────────────────────────────────────────────────────────────────────────────────────
  db1   The relational model: relations, keys (primary, candidate, foreign), ER modelling
  db2   Normalization: functional dependencies, 1NF to BCNF, and when to denormalize
  db3   SQL fundamentals: SELECT, joins of every kind, GROUP BY/HAVING, NULL semantics
  db4   Advanced SQL: subqueries, CTEs, recursive CTEs, window functions, pivoting
  db5   Storage engines: pages, heap files, B+ trees vs LSM trees, write and read amplification
  db6   Indexing in depth: clustered vs secondary, composite, covering, partial, hash, GIN/GiST, bitmap
  db7   Query processing: parsing, join algorithms (nested loop, hash, merge), cost-based optimizer, EXPLAIN
  db8   Transactions and ACID: WAL, checkpoints, ARIES-style recovery
  db9   Concurrency control: 2PL, MVCC, optimistic locking, SELECT FOR UPDATE, deadlocks in databases
  db10  PostgreSQL vs MySQL (InnoDB) internals: MVCC, vacuum, clustered index, replication options
  db11  NoSQL data models: document, key-value, wide-column, graph — and modelling for each
  db12  OLTP vs OLAP: columnar storage, data warehouses, star and snowflake schemas
  db13  Using databases from applications: connection pooling, ORMs, N+1 queries, pagination
  db14  Schema migrations without downtime: expand-contract, backfills, online index builds
  db15  Vector search in databases: pgvector, HNSW/IVF indexes inside a DBMS  (link lm10)
  Do not repeat sc4/sc5/sc8; those are system-design views. This track is the theory and internals.

  k8s10  Scheduling and resources: requests and limits, QoS classes, affinity, taints and tolerations
  k8s11  Autoscaling: HPA, VPA, Cluster Autoscaler, Karpenter, KEDA
  k8s12  Packaging and delivery: Helm, Kustomize, GitOps with Argo CD or Flux

  Labs: a Dockerfile to optimise, a kind/minikube manifest walkthrough. Mark clearly which steps
  need Docker installed; verify commands against current official docs.
