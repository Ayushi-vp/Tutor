25. PyTorch in practice  (new track: key torch, ids pt1–pt14, group Learn, pillar dl)
──────────────────────────────────────────────────────────────────────────────────────────────────
Create a NEW "PyTorch in practice" track in the Prep Console: prep-console/content/tracks/torch.json,
topic ids pt1–pt14, sources in prep-console/content/topics/torch/. Nav label "PyTorch", icon PT,
group Learn, placed after dl (--group Learn --after dl), pillar dl.

Why this track exists: every ML-coding problem in the app (designs/mlc.json, mc1–mc23) is pure
NumPy, but senior ML / AI-engineer loops and frontier-lab ML-debugging rounds are done in PyTorch:
"here is a small transformer training loop; the loss never improves or goes NaN; find every bug".
The senior question this track answers: "Can you write, debug and speed up real PyTorch training and
inference code under interview pressure?"

  pt1   Tensors for real: dtype, device, shape, strides and storage, views vs copies, contiguous(),
        in-place ops and when they break autograd, the NumPy bridge
  pt2   Shapes without tears: broadcasting rules, advanced indexing, gather/scatter, masked ops,
        einsum, reshape vs view vs permute, and a method for debugging shape errors
  pt3   Autograd: the dynamic graph, requires_grad, leaf tensors, .grad accumulation, no_grad vs
        inference_mode, detach, retain_graph, gradient hooks, a custom torch.autograd.Function
  pt4   nn.Module: parameters vs buffers, state_dict, train()/eval() and what changes, hooks,
        initialisation schemes, weight tying, counting parameters, ModuleList/ModuleDict pitfalls
  pt5   Data loading: Dataset and IterableDataset, DataLoader, workers and the GIL/fork story,
        pin_memory, collate_fn and padding, samplers, and finding an input-pipeline bottleneck
  pt6   The training loop done right: zero_grad placement, loss reduction, LR schedulers and warmup,
        gradient clipping, gradient accumulation (and the loss-scaling bug), the eval loop, seeding
        and determinism
  pt7   Mixed precision and memory: autocast, bf16 vs fp16, GradScaler, where activations live,
        activation checkpointing, reading memory stats, and debugging CUDA OOM
  pt8   Checkpointing and resuming: model + optimiser + scheduler + scaler + RNG + data position,
        safetensors vs pickle, sharded/distributed checkpoints, and a resume that is truly exact
  pt9   Debugging training: a catalogue of silent bugs (softmax over the wrong dim, wrong mask
        dtype/polarity, off-by-one label shift, forgetting eval(), BatchNorm with tiny batches,
        double softmax before CrossEntropyLoss, broadcasting a loss to the wrong shape, data leakage),
        overfit-one-batch, per-layer gradient norms, anomaly detection, and NaN hunting
  pt10  A GPT in PyTorch: embeddings, attention via F.scaled_dot_product_attention, causal masks,
        pre-norm blocks, weight tying, a KV cache for generation, and checking the parameter count
  pt11  Distributed training from the API side: torch.distributed, process groups, torchrun, DDP
        (gradient buckets, overlap, find_unused_parameters, no_sync), DistributedSampler, and FSDP2
        (fully_shard) — what each call does on the wire
  pt12  Making it fast: the profiler, host–device syncs (.item(), printing, Python control flow on
        tensors), torch.compile (graph breaks, recompiles, modes), CUDA graphs, channels_last, and
        fused optimisers
  pt13  Inference and export: inference_mode, batching and padding, torch.export, ONNX, quantisation
        in PyTorch (torchao — verify current API), and handing a model to a serving stack
  pt14  JAX for PyTorch users: pure functions, jit/grad/vmap, PRNG keys, pytrees, sharding, Flax
        NNX vs Linen (verify which is current), and how to answer "PyTorch or JAX, and why?"

Overlap (prerequisites — read them first, link them, go deeper on the PyTorch side, don't re-teach the
theory): dl1–dl11 (backprop, normalisation, optimisers, distributed training), gpu4 (numerical
formats), gpu5–gpu11 (CUDA model, torch.compile/Triton, FlashAttention, collectives, FSDP/ZeRO,

  ps2   From product goal to metrics: north-star, driver/input metrics, guardrail and counter-metrics,

  ps6   Experiment design as a product decision: what to randomise and at which unit, duration and

  ps7   Reading results and making the call: conflicting primary vs guardrail metrics, segment
        heterogeneity, practical vs statistical significance, launch criteria written in advance,
        long-term effects, and writing the decision memo
  ps8   Should this be ML — or an LLM — at all? Heuristic baselines, error tolerance, cost per query vs
        value per query, latency, build vs buy vs API, and a worked "is the AI feature worth it" model
  ps9   Designing an LLM feature as a product: UX for uncertainty, human-in-the-loop, graceful
        fallbacks, capturing feedback, trust and safety, abuse, and cost per active user
  ps10  Measuring AI features: success metrics for assistants, copilots and agents (acceptance and

28. Data engineering for ML  (new track: key dataeng, ids de1–de13, group Engineering, pillar eng)

Why this track exists: Spark, Parquet, Iceberg and Airflow are mentioned across the app but never
taught, and ML / AI-engineer loops at product companies regularly include a data-pipeline design or a

  de1   The data stack for ML: OLTP sources, CDC, the lake, the warehouse and the lakehouse, batch vs
        streaming, ETL vs ELT, and who owns what; one diagram of a whole real pipeline
  de2   File formats: CSV/JSON vs Avro vs Parquet/ORC — row groups, column chunks, pages, dictionary
        and run-length encoding, compression codecs, statistics and predicate pushdown, and the
        small-files problem, with byte counts for one real table
  de3   Partitioning and layout: partition columns and pruning, too many vs too few partitions,
        bucketing, sort order and clustering (Z-order / Hilbert), compaction
  de4   Table formats: Apache Iceberg, Delta Lake and Hudi — metadata and manifests, snapshots, ACID

  de5   Spark execution: driver and executors, the DAG, stages and tasks, narrow vs wide

        reading the Spark UI
  de6   Joins and skew at scale: broadcast vs sort-merge vs shuffle-hash joins, skew detection,
        salting, AQE skew handling, spill and executor OOM, with worked sizes
  de7   Batch pipelines and orchestration: DAGs, Airflow/Dagster concepts (tasks vs assets),
        idempotent and re-runnable tasks, backfills, late-arriving data, retries, SLAs and alerting
  de8   Ingestion and change data capture: log-based CDC (Debezium-style), snapshots + streams, the
        outbox pattern, schema registries and compatibility modes, and delivery guarantees end to end
  de9   Stream processing: event time vs processing time, windows, watermarks and late data, keyed
