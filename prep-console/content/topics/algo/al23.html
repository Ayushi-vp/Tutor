The DPs in the previous two lessons had natural states: an index into an array, or a pair of indices into two strings. Hard problems need more imagination. "Burst balloons in the order that maximises coins" — the value of each burst depends on which neighbours are still there, which depends on everything burst before. "Visit all 12 nodes of a graph by the shortest walk" — what matters is not only where you are but which nodes you have already seen. "Maximise trading profit with a one-day cooldown after selling" — the same price on the same day is a good or bad move depending on whether you hold a share and whether you sold yesterday. "Count numbers up to 10⁹ with no repeated digits" — you cannot loop over a billion numbers.

Each of these becomes a standard DP once you choose the right shape of state. There are a handful of shapes that cover almost every hard DP in interviews:

  • Interval DP: the state is a range [i, j], and the decision is where to split it or which element to handle last.
  • Bitmask DP: the state includes a subset of items, encoded as the bits of an integer, for problems with up to about 20 items.
  • State-machine DP: the state includes a mode (holding a share, cooling down, transactions used), with transitions between modes each step.
  • Tree DP: each node returns a small summary (a pair or triple) to its parent.
  • DP on implicit DAGs: memoised DFS when moves only go "upwards" in some quantity.
  • Digit DP: counting numbers up to N by processing digits with a "tight" flag.

This lesson teaches each shape with its signature problem, the reasoning that leads to the state, and the fill order. It ends with the most common transition speed-ups. These are the problems that separate a strong DP candidate from an average one, and they reward the habit built in al21: ask what the future depends on, and put exactly that in the state.

The mental model: choose the right "bookmark"

A DP state is a bookmark: it records where you are in the problem precisely enough that you could hand the rest of the work to someone else, and they would not need to know your history. For a single array, "I have processed the first i elements" is a good bookmark. For harder problems, the right bookmark has a different shape, and recognising the shape is most of the battle.

If the problem repeatedly merges or splits a contiguous sequence — combining stones, cutting a stick, multiplying a chain of matrices, bursting balloons — the bookmark is a range: "the answer for the piece from i to j". If the problem is about which items have been used, and there are few of them, the bookmark is a set, stored as a bitmask. If the problem walks through time with a small number of modes, the bookmark is (time, mode). If the input is a tree, the bookmark is a subtree, plus a flag about its root. If you are counting numbers, the bookmark is (digit position, whether you are still matching the upper bound, what the property needs).

A practical way to find the shape is to look at what the brute force would have to remember. A brute force for Burst Balloons tries every order and must remember which balloons are still present — but if you decide the last balloon in a range, you only need the range's two ends. A brute force for TSP tries every order and must remember the cities visited and where you are — a set and a city, which for 16 cities fits in a bitmask and an index. A brute force for stock trading simulates every buy/sell decision and must remember whether you hold a share and whether you just sold — a mode. In each case the DP state is the brute force's memory, compressed to what the future actually depends on.

Whatever the shape, the rest of the recipe from al21 is unchanged: write the recurrence by thinking about the last decision, set base cases, pick an order in which dependencies come first, and identify the answer. The order is where these shapes differ most: ranges are filled by increasing length; masks by increasing value (adding a bit makes the number larger, so subsets come before supersets); trees in post-order; implicit DAGs by memoised DFS; digits from the most significant.

Where the bookmark analogy breaks: a real bookmark is tiny, but some DP states are big — 2ⁿ masks, n² ranges, n·k (day, transactions) pairs. The cost of a DP is always (number of states) × (work per transition), and with these richer states that product is what tells you whether the approach fits the constraints. A bitmask DP for n = 25 has 3.3 × 10⁷ masks, and multiplying by n for a "last element" makes it too slow; the constraints usually stop at 16–20 for exactly that reason.

Interval DP: split points

The classic is matrix chain multiplication: multiplying matrices A₁A₂…Aₙ, where the order of multiplication (the parenthesisation) changes the cost dramatically. dp[i][j] = the minimum cost to multiply Aᵢ..Aⱼ. The last multiplication splits the chain at some k: (Aᵢ..Aₖ)(Aₖ₊₁..Aⱼ), costing dp[i][k] + dp[k+1][j] + rows(Aᵢ)·cols(Aₖ)·cols(Aⱼ). Try every k. Every term is a shorter range, so fill by increasing length:

for length in range(2, n + 1):
    for i in range(0, n - length + 1):
        j = i + length - 1
        dp[i][j] = min(dp[i][k] + dp[k + 1][j] + cost(i, k, j) for k in range(i, j))

n² states × n choices of k = O(n³). Minimum Cost to Cut a Stick is the same shape: sort the cut positions, add the stick's ends, and let dp[i][j] be the minimum cost of making all cuts strictly between positions cuts[i] and cuts[j]. The first cut k in that piece costs the piece's length, cuts[j] − cuts[i], and leaves two independent pieces: dp[i][j] = cuts[j] − cuts[i] + min(dp[i][k] + dp[k][j]).

Interval DP: the last action — Burst Balloons

Bursting balloon k earns v[left]·v[k]·v[right], where left and right are its current neighbours. If you choose the first balloon to burst in a range, the neighbours of the rest depend on everything that happens later — the subproblems are tangled. Flip the question: which balloon in the open range (i, j) is burst last? When it bursts, every other balloon in (i, j) is gone, so its neighbours are exactly i and j — known boundaries. And the balloons on its left, between i and k, are burst before it with k standing as their right wall; likewise on the right. The two sides are independent.

def max_coins(nums):
    v = [1] + nums + [1]
    n = len(v)
    dp = [[0] * n for _ in range(n)]
    for gap in range(2, n):                   # j - i
        for i in range(0, n - gap):
            j = i + gap
            dp[i][j] = max(dp[i][k] + dp[k][j] + v[i] * v[k] * v[j]
                           for k in range(i + 1, j))
    return dp[0][n - 1]

On [3, 1, 5, 8] the answer is 167 (burst 1, 5, 3, 8: 3·1·5 + 3·5·8 + 1·3·8 + 1·8·1 = 15 + 120 + 24 + 8). Padding with 1s turns the edges into ordinary boundaries. The general lesson: when "first choice" tangles the subproblems, try "last choice" — it often fixes the boundary conditions.

Bitmask DP: subsets as states

When a problem asks for the best ordering or assignment of a small number of items (n ≤ 20), the state "which items are already used" is a subset, stored as an integer mask whose bit i is 1 if item i is used. Adding item i is mask | (1 << i); testing it is mask >> i & 1. Because adding a bit always makes the number larger, iterating masks from 0 upwards processes every subset before its supersets — a valid fill order.

Travelling salesman (Held–Karp): dp[mask][v] = the shortest path that starts at city 0, visits exactly the cities in mask, and ends at v. Transition: dp[mask | 1 << u][u] = min(dp[mask][v] + dist[v][u]) for u not in mask. The answer closes the tour: min over v of dp[full][v] + dist[v][0]. That is 2ⁿ·n states with n transitions each, O(2ⁿ·n²) — about 1.7 × 10⁷ for n = 16, compared with 15! ≈ 1.3 × 10¹² orderings.

Shortest Path Visiting All Nodes (unweighted graph, n ≤ 12) is the same idea with BFS instead of a min-DP, because every edge costs 1: BFS over (node, mask) states, starting from every node with its own bit set, and stop at the first full mask.

Partition to K Equal Sum Subsets needs only the mask: dp[mask] = how full the current bucket is after placing exactly the elements in mask (or −1 if impossible). Placing element i is allowed if it fits in the current bucket: dp[mask | bit] = (dp[mask] + nums[i]) % target. When the bucket fills exactly, the modulo resets it to 0 for the next bucket. The answer is dp[full] == 0. O(2ⁿ·n).

def can_partition_k(nums, k):
    total = sum(nums)
    if total % k: return False
    target, n = total // k, len(nums)
    dp = [-1] * (1 << n); dp[0] = 0
    for mask in range(1 << n):
        if dp[mask] < 0: continue
        for i in range(n):
            if not mask >> i & 1 and dp[mask] + nums[i] <= target:
                nxt = mask | 1 << i
                if dp[nxt] < 0:
                    dp[nxt] = (dp[mask] + nums[i]) % target
    return dp[-1] == 0

State-machine DP: the stock family

Six "Best Time to Buy and Sell Stock" problems are one idea: the state is (day, mode), and each day each mode takes the best of the transitions into it (the figure). With one transaction, track the best "hold" (−min price so far) and "sold". With unlimited transactions, hold = max(hold, sold − p), sold = max(sold, hold + p). With a fee, subtract it on selling. With a cooldown, add a third mode for "sold today":

def max_profit_cooldown(prices):
    hold, sold, rest = float("-inf"), 0, 0
    for p in prices:
        hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)

All three new values are computed from the old ones in one tuple assignment, so no state reads a value already updated today. Trace [1, 2, 3, 0, 2]: the best plan is buy 1, sell 2, cool down, buy 0, sell 2 = 3.

With at most k transactions, the mode includes a counter: buy[t] and sell[t] for t = 1..k, where buy[t] = max(buy[t], sell[t−1] − p) and sell[t] = max(sell[t], buy[t] + p). O(n·k). If k ≥ n/2, the limit cannot bind (you can never make more than n/2 transactions), so fall back to the unlimited version in O(n).

Tree DP: return a tuple

On trees, the natural order is post-order: compute children first, then the parent. When one value per node is not enough, return a small tuple. House Robber III (no parent and child both robbed): each node returns (best with this node robbed, best with it not robbed).

def rob_tree(root):
    def go(node):
        if not node: return (0, 0)
        l, r = go(node.left), go(node.right)
        rob = node.val + l[1] + r[1]                 # children must be skipped
        skip = max(l) + max(r)                       # children free to choose
        return (rob, skip)
    return max(go(root))

Binary Tree Cameras (minimum cameras so every node is watched by itself, its parent or a child) uses three states per node: "has a camera", "covered without a camera", "not covered (needs the parent to cover it)". A greedy version of the same idea places cameras at parents of uncovered leaves. More generally, any "choose a set of nodes with constraints between neighbours" problem on a tree is a tree DP with a few states per node, O(n).

DP on implicit DAGs: memoised DFS

Longest Increasing Path in a Matrix: from any cell, move to a 4-neighbour with a strictly larger value; find the longest path. There is no obvious fill order — the longest path from a cell depends on its larger neighbours, which may be anywhere. But because moves go strictly upwards in value, there are no cycles: the moves form a DAG. Memoised DFS computes each cell's answer once, recursing into neighbours as needed.

from functools import cache
def longest_increasing_path(m):
    R, C = len(m), len(m[0])
    @cache
    def best(r, c):
        return 1 + max([best(nr, nc) for nr, nc in ((r+1, c), (r-1, c), (r, c+1), (r, c-1))
                        if 0 <= nr < R and 0 <= nc < C and m[nr][nc] > m[r][c]],
                       default=0)
    return max(best(r, c) for r in range(R) for c in range(C))

O(R·C) states with four transitions each. No visited set is needed — strictness rules out returning to a cell. On a large grid the recursion can be deep (a long increasing path), so an iterative alternative is to sort cells by value and process them in decreasing order, or peel cells with no larger neighbours level by level (Kahn's algorithm, al18).

Digit DP: counting numbers up to N

"How many integers in [1, N] have property P?", with N up to 10¹⁸. You cannot enumerate them, but you can build them digit by digit. The state is (position, tight, extra), where tight says whether the digits chosen so far equal N's prefix — if so, the next digit cannot exceed N's digit at this position; if not, any digit 0–9 is allowed. "extra" is whatever the property needs: a count of 1s so far, a mask of digits used, the remainder modulo something.

from functools import cache
def count_no_repeat(N):                    # numbers in [1, N] with all distinct digits
    digits = list(map(int, str(N)))
    @cache
    def go(pos, tight, mask, started):
        if pos == len(digits):
            return 1 if started else 0
        limit = digits[pos] if tight else 9
        total = 0
        for d in range(limit + 1):
            if started and mask >> d & 1: continue          # repeated digit
            now_started = started or d != 0
            total += go(pos + 1, tight and d == limit,
                        mask | (1 << d) if now_started else mask, now_started)
        return total
    return go(0, True, 0, False)

The started flag handles leading zeros (007 is really 7, and its zeros should not count as repeated digits). States: positions × 2 × 2¹⁰ × 2 — tiny. "Numbers with Repeated Digits" is N minus this count. "Number of Digit One" can be done with a general digit DP (extra = number of 1s so far) or with the per-position formula in the Q&A.

Speeding up transitions

Sometimes the state is right but each transition loops over many previous states. Three common fixes keep the same DP and make transitions cheaper. Prefix sums: if dp[i] = Σ dp[j] over a range of j, maintain a prefix-sum array of dp so the range sum is O(1). Monotonic deque: if dp[i] = a[i] + max(dp[j]) over a sliding window of j, keep a deque of candidate indices with decreasing dp values (al6) — Jump Game VI and Constrained Subsequence Sum are O(n) this way. Binary search: if the best j is the last one satisfying some sorted condition, find it with bisect, as in weighted interval scheduling (al11) and the tails array of LIS (al21).

Recognising the shape

Merging or splitting contiguous pieces, or "the order in which elements are removed" → interval DP (try "last action" if "first" tangles). Few items (≤ 20) and "which have been used" matters → bitmask DP. Time steps with modes (holding, cooling, transactions) → state machine. Tree input with neighbour constraints → tree DP with a tuple per node. Moves that only go up in some quantity → memoised DFS on the implicit DAG. Counting numbers up to a huge N with a digit property → digit DP.

Why "last action" untangles interval problems

An interval DP is valid only if the subproblems for the two sides are independent: the best way to handle the left part must not depend on choices made on the right. In Burst Balloons, if k bursts first, then the left part's rightmost balloon later has a neighbour from the right part — the sides interact. If k bursts last, then for every balloon on the left, k is a wall that is still standing, so the right part is invisible to it. Many problems share this structure ("remove boxes", "strange printer", "minimum score triangulation of a polygon"), and the move from "what happens first" to "what happens last" is the recurring insight. A good test: after fixing your decision k, can you describe the left and right subproblems using only i, k and j? If yes, the decomposition works.

The limits of bitmask DP

Bitmask DP is exponential, so constraints decide everything. 2²⁰ ≈ 10⁶ masks is comfortable; with a "last element" dimension, 2²⁰ × 20 = 2 × 10⁷ states is fine in a compiled language and borderline in Python; with an n² transition, Held–Karp TSP is practical up to n ≈ 15–18 in Python. Iterating only over submasks of a mask (sub = (sub - 1) & mask) visits all pairs (mask, submask) in O(3ⁿ) total — the cost of "partition a set into groups" DPs. When n is around 40, split the set in half and meet in the middle (al13). Seeing "n ≤ 16" or "n ≤ 20" in the constraints of an optimisation problem is a strong hint that bitmask DP is intended.

Rerooting: tree DP for every root

Some tree problems ask for an answer for every node as the root — for example, the sum of distances from each node to all others. Running a tree DP from every root is O(n²). Rerooting does it in O(n): first a post-order pass computes subtree information for one root (subtree sizes and the sum of distances within each subtree); then a pre-order pass moves the root from a parent to each child, adjusting the answer with a formula — for sum of distances, moving the root from p to child c changes it by (n − size[c]) − size[c], because size[c] nodes get one step closer and the rest one step farther. "Sum of Distances in Tree" is the classic interview hard for this technique.

Classic DP optimisations, briefly

Beyond prefix sums and monotonic deques, competitive programming has a toolbox for speeding up specific recurrence shapes. Knuth's optimisation reduces some O(n³) interval DPs (such as optimal binary search trees) to O(n²) when the best split point is monotone. Divide-and-conquer optimisation applies when the best transition index is monotone across i. The convex hull trick handles transitions of the form min over j of (m_j·x_i + b_j) in O(log n) or amortised O(1). These are rarely required in interviews, but recognising "the best split point moves monotonically" and saying that it could reduce the complexity is a strong signal in a senior loop.

Profile DP: bitmasks over a moving frontier

Tiling problems ("how many ways to tile a 3 × n board with dominoes?", "count ways to place non-attacking kings on a grid") use a bitmask not for a set of items but for the shape of a frontier: which cells of the current column are already filled by pieces sticking out of the previous column. The DP walks column by column (or cell by cell, the "broken profile" variant), and transitions enumerate how pieces can be placed given the incoming profile. For a board of height h there are 2^h profiles, so this works for small h and any length. It is the same idea as bitmask DP — compress the exact information the future depends on into the bits of an integer — applied to geometry.

Choosing between top-down and bottom-up for rich states

With rich states, memoisation often wins on clarity: digit DP and memoised DFS on implicit DAGs are much easier to write top-down because the reachable states are irregular. Bottom-up wins when the fill order is simple (intervals by length, masks by value), when recursion depth is a risk, and when you want to compress memory (stock problems collapse to a handful of variables). In Python, top-down with @cache also carries a hashing cost per call, so a bottom-up loop over a dense table can be several times faster for the same state count — worth mentioning if performance is tight.

In the interview room

Hard DP rounds are graded on whether you can name the state and justify it. Say the shape explicitly: "this is interval DP; dp[i][j] is the best for the open range between i and j; I'll choose the last balloon burst". If you cannot find the shape, write the brute-force recursion and look at its arguments — then ask which of them can be compressed (a set into a bitmask, a path into a range, a history into a mode). Interviewers often give credit for a correct memoised recursion even if you do not reach the optimal tabulation.

Common bugs: filling an interval table in the wrong order (reading a range that is not computed yet); forgetting padding or boundary elements (Burst Balloons without the 1s); bitmask precedence errors in Python (mask >> i & 1 works because >> binds tighter than &, but mask & 1 << i also works for the same reason — when in doubt, add parentheses); updating stock states in place so that a buy and a sell happen on the same day; recursion depth in memoised DFS on large grids; and in digit DP, mishandling leading zeros. Test on the smallest inputs and on one with known answer from the problem statement.

State the complexity as states × transitions and check it against the constraints out loud: "n ≤ 300, interval DP is O(n³) = 2.7 × 10⁷, fine" or "n ≤ 16, 2¹⁶ × 16 × 16 ≈ 1.7 × 10⁷, fine". That habit reassures interviewers that you chose the approach for a reason.

On online assessments, the constraints are usually the strongest hint for these shapes. n ≤ 500 with a "merge" or "remove" story suggests interval DP; n ≤ 20 with "assign" or "visit all" suggests bitmask DP; N up to 10¹⁸ with a counting question about digits suggests digit DP; a tree with up to 10⁵ nodes suggests tree DP in O(n). Reading the constraints before the story often reveals the intended state.

Finally, when stuck in the room, it is fine to say "I think this is an interval DP but I'm not sure whether to choose the first or the last action — let me test both on the example". Working one small example by hand with each choice usually reveals which decomposition keeps the sides independent.

In real systems

These DP shapes appear in practical systems. Interval DP underlies optimal parenthesisation in database query planners and in tensor libraries: numpy.einsum_path and the opt_einsum package choose the order of contractions in a chain of tensor products, a direct descendant of matrix chain multiplication, which matters for the cost of large ML computations. Parsing with context-free grammars (the CYK algorithm) is interval DP over spans of a sentence. Bitmask DP appears in vehicle routing for small fleets, in chip design, and in exact solvers for small travelling-salesman instances. State-machine DPs are the Viterbi algorithm in speech recognition and the hidden Markov models in bioinformatics. Tree DP is used in phylogenetics (Felsenstein's algorithm computes likelihoods over evolutionary trees) and in compilers for optimal instruction selection over expression trees. Reinforcement learning's value iteration is a state-machine DP over environment states.

    import random
from itertools import permutations
from functools import cache

def burst_dp(nums):
    v = [1] + nums + [1]; n = len(v); dp = [[0] * n for _ in range(n)]
    for gap in range(2, n):
        for i in range(n - gap):
            j = i + gap
            dp[i][j] = max(dp[i][k] + dp[k][j] + v[i] * v[k] * v[j] for k in range(i + 1, j))
    return dp[0][n - 1]

def burst_brute(nums):
    best = 0
    for order in permutations(range(len(nums))):
        alive, coins = list(range(len(nums))), 0
        for b in order:
            p = alive.index(b)
            left = nums[alive[p - 1]] if p > 0 else 1
            right = nums[alive[p + 1]] if p + 1 < len(alive) else 1
            coins += left * nums[b] * right; alive.pop(p)
        best = max(best, coins)
    return best

def stock_cooldown(prices):
    hold, sold, rest = float("-inf"), 0, 0
    for p in prices: hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)

def stock_brute(prices):
    @cache
    def go(i, holding, cool):
        if i == len(prices): return 0
        best = go(i + 1, holding, False)                       # do nothing
        if holding: best = max(best, prices[i] + go(i + 1, False, True))
        elif not cool: best = max(best, -prices[i] + go(i + 1, True, False))
        return best
    return go(0, False, False)

def distinct_digits_count(N):
    return sum(len(set(str(x))) == len(str(x)) for x in range(1, N + 1))

for _ in range(300):

    assert burst_dp(nums) == burst_brute(nums), nums
    prices = [random.randint(0, 9) for _ in range(random.randint(0, 10))]
    assert stock_cooldown(prices) == stock_brute(prices), prices
print("interval DP and state-machine DP match brute force")
print("distinct-digit numbers up to 1000:", distinct_digits_count(1000))

Name the shape, then the state

For each problem, name the DP shape and define the state in one sentence. (a) Merge piles of stones in a row, two adjacent piles at a time, each merge costing the sum of the two piles; minimise the total cost. (b) Assign n ≤ 15 workers to n jobs, one each, minimising total cost from a cost matrix. (c) A robot on a number line receives commands; each day it may hold position, or move, but cannot move two days in a row; maximise reward. (d) Count integers in [1, N] (N ≤ 10¹⁵) whose digit sum is divisible by 7. (e) In a tree, choose the maximum-weight set of nodes such that no two chosen nodes are adjacent.

Answer

(a) Interval DP: dp[i][j] = the minimum cost to merge piles i..j into one pile; the last merge combines the merged left part i..k with the merged right part k+1..j, costing dp[i][k] + dp[k+1][j] + sum(i..j) (prefix sums make the range sum O(1)). O(n³). (b) Bitmask DP: dp[mask] = the minimum cost of assigning the first popcount(mask) workers to the jobs in mask; worker number popcount(mask) takes some job not in mask. O(2ⁿ·n) ≈ 5 × 10⁵ for n = 15. (c) State machine: dp[day][moved_yesterday ∈ {0, 1}] with transitions "hold" (to state 0) and "move" (only from state 0, to state 1); O(days). (d) Digit DP: state (position, tight, digit_sum mod 7, started); count completions where the final remainder is 0. About 16 × 2 × 7 × 2 states with 10 transitions each. (e) Tree DP: each node returns (best if chosen, best if not chosen); chosen = weight + Σ child.not_chosen, not chosen = Σ max(child.chosen, child.not_chosen). O(n) — the tree version of House Robber.
