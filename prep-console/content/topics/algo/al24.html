A file on a Unix system has permissions like rwxr-x---: read, write and execute for the owner, the group and everyone else. The system stores all nine flags in the bits of one small integer, and checking "can the group execute this?" is a single AND with a mask. A database answers "customers who are in Mumbai AND bought in the last week AND have opted into email" by AND-ing three bitmaps of millions of bits each — one CPU instruction handles 64 customers at a time. A chess engine stores the position of all white pawns as one 64-bit integer, one bit per square, and computes all their possible captures with two shifts and an AND.

Bit manipulation is the art of treating an integer as a row of 32 or 64 independent switches and operating on all of them at once. In interviews it appears in three ways. There are direct puzzles — Single Number, Missing Number, Counting Bits, Reverse Bits, Sum of Two Integers, Bitwise AND of a Range — each solved by one or two identities. There are bitmasks as compact sets, which you have already used for subsets (al13) and bitmask DP (al23). And there are optimisations, where packing booleans into bits makes a dynamic programme or a set operation many times faster.

The good news is that a small toolkit covers almost all of it: how numbers look in binary and two's complement, the five operators, and a handful of identities — x & (x − 1) clears the lowest set bit, x & −x isolates it, a ^ a = 0. This lesson builds that toolkit, applies it to each classic problem with a trace, and points out the traps specific to Python, whose integers never overflow and whose ~x does not mean what it means in C.

The mental model: a row of light switches

Picture a row of light switches, numbered from the right starting at 0. Switch i, when on, contributes 2ⁱ to the total. The number 13 is switches 3, 2 and 0 on: 8 + 4 + 1, written 1101 in binary. Every non-negative integer is exactly one pattern of switches. Bitwise operators act on every switch position independently and simultaneously:

OperatorRule per positionExample (12 op 10 = 1100 op 1010)
AND &1 if both are 11000 = 8
OR |1 if either is 11110 = 14

With these, single switches are easy to handle. Test bit i: (x >> i) & 1. Turn it on: x | (1 << i). Turn it off: x & ~(1 << i). Flip it: x ^ (1 << i).

Negative numbers: two's complement

Computers store signed integers in two's complement: to negate x, flip all its bits and add one. In 8 bits, 5 is 00000101 and −5 is 11111011. The top bit acts as the sign. Two consequences matter constantly. First, ~x = −x − 1 (flipping is "negate and subtract one"). Second, x & −x isolates the lowest set bit: −x flips every bit above the lowest 1 of x and keeps that 1 and the zeros below it, so AND-ing leaves only that single bit.

Where the light-switch analogy breaks: real switch panels have a fixed number of switches, but Python integers have unlimited precision. There is no 32nd bit that falls off when you shift left, no overflow, and negative numbers behave as if they had infinitely many leading 1s. So ~5 is −6, not 4294967290, and 1 << 100 is a perfectly good integer. Most interview problems assume 32-bit integers; in Python you emulate that by AND-ing with 0xFFFFFFFF (32 ones) and, if a signed result is wanted, converting values of 2³¹ or more back to negatives with x − (1 << 32). We will need this for Sum of Two Integers and Single Number II.

It also helps to remember a few values by sight: 0xFF is eight 1s (255), 0xFFFFFFFF is thirty-two 1s (4,294,967,295), 2¹⁰ ≈ 10³, 2²⁰ ≈ 10⁶, 2³⁰ ≈ 10⁹, and 2³¹ − 1 = 2,147,483,647 is the largest signed 32-bit integer. These come up whenever you reason about masks, overflow or whether a value fits in a bitmask.

A last piece of intuition: XOR is "addition without carrying" — 1 ^ 1 = 0 drops the carry that ordinary addition would produce. That one view explains both the XOR cancellation tricks and the carry-based addition algorithm below.

The toolkit, in one place

(x >> i) & 1          # bit i of x
x | (1 << i)           # set bit i
x & ~(1 << i)          # clear bit i
x ^ (1 << i)           # toggle bit i
x & (x - 1)            # clear the lowest set bit
x & -x                 # isolate the lowest set bit
(1 << n) - 1           # n ones: the full set of n items
x.bit_length()         # number of bits needed (position of highest 1, plus 1)
x.bit_count()          # number of 1 bits (Python 3.10+)
a ^ a == 0, a ^ 0 == a # XOR cancels and is its own inverse

Learn these as phrases. In an interview you should be able to say "clear the lowest set bit with x & (x − 1)" without deriving it, then explain the derivation if asked.

Powers of two and counting bits

A power of two has exactly one set bit. Clearing it leaves zero, so n > 0 and n & (n − 1) == 0 tests it. The n > 0 guard matters: 0 & −1 is 0 too, and 0 is not a power of two.

Counting set bits (the popcount) can loop over all bit positions, but Kernighan's method loops once per set bit:

def hamming_weight(n):
    count = 0
    while n:
        n &= n - 1          # drop the lowest 1
        count += 1
    return count

For 44 (101100): 44 → 40 → 32 → 0, three iterations. Counting Bits asks for the popcount of every number from 0 to n. Recomputing each is O(n log n); a DP over integers is O(n). Shifting i right by one drops its lowest bit, so bits[i] = bits[i >> 1] + (i & 1). Or remove the lowest set bit: bits[i] = bits[i & (i − 1)] + 1. Both read an already-computed smaller index.

XOR cancellation: Single Number and Missing Number

XOR has three properties that make it a cancellation machine: a ^ a = 0, a ^ 0 = a, and order does not matter (it is commutative and associative). XOR a list where every value appears twice except one, and every pair vanishes:

def single_number(nums):
    x = 0
    for v in nums:
        x ^= v
    return x

[4, 1, 2, 1, 2]: 4 ^ 1 ^ 2 ^ 1 ^ 2 = 4 ^ (1 ^ 1) ^ (2 ^ 2) = 4. O(n) time and O(1) space — the reason interviewers ask it is to see whether you know XOR, since a hash set is the obvious O(n)-space answer. Missing Number (n distinct numbers from 0..n, one missing) XORs all indices 0..n together with all values: every present number cancels with its own index, and the missing one remains.

Two unique numbers: split by a differing bit

"Every number appears twice except two; find both." XOR everything and you get x = a ^ b — not either number, but their difference pattern. Since a ≠ b, x has at least one set bit, and at any set bit of x, a and b differ. Take the lowest one, d = x & −x, and split all numbers into two groups by whether they have that bit. a and b land in different groups; every duplicate pair lands together in one group. XOR each group separately:

def single_number_iii(nums):
    x = 0
    for v in nums: x ^= v
    d = x & -x                       # a bit where the two singles differ
    a = 0
    for v in nums:
        if v & d: a ^= v
    return [a, x ^ a]

This works with negative numbers in Python too, because Python's & and − follow two's complement with infinite sign extension.

Three of each: count bits modulo 3

"Every number appears three times except one." XOR no longer cancels triples. Look at one bit position: among the tripled numbers, the count of 1s at that position is a multiple of 3, so the total count modulo 3 is exactly the unique number's bit there. Do this for all 32 positions:

def single_number_ii(nums):
    result = 0
    for i in range(32):
        if sum((v >> i) & 1 for v in nums) % 3:
            result |= 1 << i
    return result - (1 << 32) if result >= 1 << 31 else result   # back to signed

The final line converts a 32-bit two's complement pattern back to a Python negative number. A cleverer O(n) version keeps two variables, ones and twos, as a per-bit counter that cycles 0 → 1 → 2 → 0: ones = (ones ^ v) & ~twos; twos = (twos ^ v) & ~ones. After all numbers, ones holds the bits that appeared once (mod 3) — the answer. It is worth knowing exists; the bit-count version is easier to explain.

Reversing bits

Reverse a 32-bit unsigned integer: take bits off the right of n and push them onto the right of the result, 32 times.

def reverse_bits(n):
    r = 0
    for _ in range(32):
        r = (r << 1) | (n & 1)
        n >>= 1
    return r

Looping exactly 32 times (not "while n") matters: the zeros in the high positions of n must become zeros in the low positions of r, and stopping as soon as n reaches zero would leave r too short — reversing 1 would give 1 instead of 2³¹. The interview follow-up "called millions of times?" has two answers: a 256-entry table of reversed bytes, combining four lookups; or the divide-and-conquer swap — swap the 16-bit halves, then the bytes within each half, then the nibbles, pairs and single bits, each with a mask and two shifts, five steps in total.

Adding without +

"Sum of Two Integers" forbids + and −. Binary addition at each position produces a sum bit (a XOR b, ignoring carry) and a carry bit (a AND b) that moves one place left. So repeat: compute the carry-free sum and the carries, then add those two numbers the same way, until there are no carries.

def get_sum(a, b):
    MASK, MAX = 0xFFFFFFFF, 0x7FFFFFFF
    while b & MASK:
        a, b = (a ^ b) & MASK, ((a & b) << 1) & MASK
    a &= MASK
    return a if a <= MAX else ~(a ^ MASK)        # reinterpret as signed 32-bit

Trace 5 + 3: a = 101, b = 011 → sum 110, carry 010 → sum 100, carry 100 → sum 000, carry 1000 → sum 1000, carry 0. Result 8. In a fixed-width language, the carry eventually shifts out of the top and the loop ends. In Python, without the mask, adding a negative number sends the carry marching left forever, because negative numbers have infinitely many 1s. Masking to 32 bits restores the fixed width, and the last line turns a pattern with the top bit set back into a negative Python integer (~(a ^ MASK) equals a − 2³²).

AND over a range

"Bitwise AND of all numbers from left to right." Iterating could be 2³¹ steps. Think per bit: if left and right differ at some bit position, then somewhere between them that bit goes from 0 to 1 or wraps, and in fact every lower position takes both values; the AND of a range that contains both a 0 and a 1 at a position is 0 there. So only the common binary prefix of left and right survives.

def range_bitwise_and(left, right):
    shift = 0
    while left != right:
        left >>= 1; right >>= 1; shift += 1
    return left << shift

For [5, 7] = [101, 111]: the common prefix is 1, followed by two zeros → 100 = 4. O(log right).

Masks as sets

A bitmask represents a subset of up to ~60 items in one integer: union is |, intersection &, difference a & ~b, membership a test of one bit, size a popcount. Enumerating all subsets of n items is for mask in range(1 << n). Enumerating all submasks of a given mask — every subset of a subset — uses a neat loop that visits each exactly once:

sub = mask
while sub:
    ...                       # process sub
    sub = (sub - 1) & mask    # next smaller submask
# (process the empty submask separately if needed)

Subtracting one flips the lowest set bit and the bits below it; AND-ing with mask throws away bits not in the mask, giving the next smaller subset. Summed over all masks of n bits, this visits 3ⁿ (mask, submask) pairs — the cost of DPs that partition a set into groups. Masks also encode small state in searches: keys collected in a maze (al17), visited nodes in TSP (al23), letters present in a word ("maximum product of word lengths" checks that two words share no letters with a single AND of their 26-bit masks).

Bitsets: many booleans per operation

A Python integer can act as a bitset of any length: bit s is one boolean. Operations on it run in C over 30- or 64-bit chunks, so one Python-level operation processes thousands of booleans. The classic use is subset-sum feasibility: "which sums can a subset of these numbers make?".

def can_reach(nums, target):
    bits = 1                         # only sum 0 is reachable at first
    for x in nums:
        bits |= bits << x            # every reachable s makes s + x reachable
    return (bits >> target) & 1 == 1

The shift-and-OR is the whole 0/1 knapsack inner loop (al22) in one expression, and in Python it is typically tens of times faster than iterating over a list. The same idea speeds up "which pairs of rows share a 1" (AND two bitsets and test for non-zero), graph reachability with adjacency rows as bitsets, and Floyd–Warshall-style transitive closure.

Checking letters and flags with masks

A 26-bit mask summarises which letters a word contains, and many string questions become one AND or one comparison. Two words share no letters when their masks AND to zero. A word is a permutation of the letters available on a keyboard row when its mask is a subset of the row's mask: word_mask & ~row_mask == 0. "Count the strings that can be rearranged into a palindrome" uses a parity mask instead: toggle bit c for every occurrence of letter c (XOR), and the string qualifies when at most one bit remains set — m & (m − 1) == 0. The same parity-mask idea, combined with prefix XORs and a hash map, counts substrings in which every vowel appears an even number of times (al3): two prefixes with the same parity mask bound such a substring.

Recognising the pattern

Think bits when the problem mentions XOR, binary, powers of two, "appears twice/three times", "without using + or ×", flags or permissions, small sets of items, or when a boolean DP or set operation is too slow. Then reach for the toolkit: cancellation with XOR, per-bit counting, lowest-set-bit tricks, masks as sets, or a bitset.

Two's complement, precisely

In n-bit two's complement, the bit pattern b represents b if the top bit is 0 and b − 2ⁿ if it is 1. That single rule explains everything: addition and subtraction work identically for signed and unsigned numbers (the hardware does not care), −x = 2ⁿ − x = ~x + 1, the range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1, and the most negative number has no positive counterpart (−(−128) overflows back to −128 in 8 bits). Overflow is "wrapping modulo 2ⁿ", which is defined behaviour for unsigned integers in C but undefined for signed ones — a real source of security bugs. Python sidesteps it by having no fixed width; conceptually, a Python negative number is a two's complement pattern with infinitely many leading 1s, which is why &, |, ^ and shifts behave consistently on negatives.

Popcount and friends in hardware

Modern CPUs implement several of this lesson's operations as single instructions: popcount (POPCNT on x86), count leading zeros (LZCNT) and count trailing zeros (TZCNT), which give the position of the highest and lowest set bit. Compilers expose them as built-ins, and Python's int.bit_count() and int.bit_length() use them. Without hardware support, popcount on a 64-bit word can be done in about a dozen operations by summing bits in parallel: add adjacent bits, then adjacent pairs, then nibbles, using masks like 0x5555… and 0x3333… — the "SWAR" (SIMD within a register) technique from Hacker's Delight. Knowing that popcount is O(1) in practice justifies treating bitmask DP transitions as constant time.

XOR as linear algebra

XOR is addition modulo 2 in each bit, so a set of numbers is a set of vectors over the field with two elements, and XOR-ing a subset is a linear combination. This view solves "maximum XOR of any subset": build a linear basis (Gaussian elimination over bits, keeping at most one basis vector per leading bit), then greedily XOR basis vectors into the answer from the top bit down. It also answers "can x be formed as an XOR of some subset?" and "how many distinct subset XORs are there?" (2^rank). These are competitive-programming staples and occasionally appear as hard interview questions; recognising XOR as linear algebra is the key.

Gray code and other orderings

The Gray code orders all n-bit numbers so that consecutive ones differ in exactly one bit: g = i ^ (i >> 1). It appears in rotary encoders (a mis-read between positions is off by one position, not wildly wrong), in error-tolerant communications, and in enumerating subsets so that each step adds or removes exactly one element — which lets some search algorithms update a running total in O(1) per subset. The inverse transformation recovers i from g by XOR-ing all right shifts. A "Gray Code" interview question is a direct application of the formula.

Bitboards: a whole board in one integer

Chess engines represent a position as a dozen 64-bit integers, one per piece type and colour, with bit i set if such a piece stands on square i. All white pawns' forward moves are (white_pawns << 8) & empty; their captures to one side are a shift by 7 or 9 with a mask that removes wrap-around across the board's edge. Sliding pieces use precomputed attack tables indexed by "magic" multiplications of the occupied-squares mask. One machine instruction then updates 64 squares at once, which is why bitboard engines like Stockfish evaluate tens of millions of positions per second. The general lesson is that when a state is a small grid of booleans, packing it into machine words turns loops over cells into single arithmetic operations.

When bit tricks hurt

Bit hacks can make code unreadable and, in high-level languages, slower than the obvious version, because the interpreter overhead dominates. In Python, bin(x).count("1") or x.bit_count() beats a hand-written Kernighan loop; a set of small integers is often clearer than a bitmask unless you need hashing or speed. Use bit manipulation where it is the natural model (flags, masks as DP state, XOR puzzles) or where it buys a real speed-up (bitsets), and explain it with a comment. Interviewers value correct, readable code over cleverness for its own sake.

In the interview room

Bit problems are short, so precision and explanation decide the score. The frequent bugs: operator precedence (in Python, & binds looser than == and comparisons, so x & 1 == 0 means x & (1 == 0) — always parenthesise: (x & 1) == 0); forgetting the n > 0 guard in power-of-two checks; looping "while n" instead of exactly 32 times in Reverse Bits; and, above all, assuming 32-bit overflow in Python, which leads to infinite loops in carry-based addition and wrong signs in Single Number II. Say explicitly when you are emulating 32 bits and why.

Expect "explain why that works" for every trick. Have the one-line justifications ready: x & (x − 1) — "subtracting one flips the lowest 1 and everything below it"; x & −x — "two's complement keeps the lowest 1 and flips everything above"; XOR cancellation — "a ^ a = 0, order does not matter". Interviewers are checking understanding, not memory.

Offer the non-bit alternative too: a Counter for Single Number II, arithmetic sum for Missing Number, a loop for popcount. Then explain what the bit version buys (O(1) space, or speed). That shows judgement.

On online assessments, bit problems sometimes hide behind constraints like "values up to 10⁹ and n up to 10⁵, find the pair maximising a ^ b" or "answer queries about subsets of at most 20 features". Recognising that 10⁹ fits in 30 bits (so per-bit reasoning is cheap) or that 20 features fit in a mask is often the whole trick.

When an interviewer asks for O(1) space on a counting problem (Single Number II, Find the Duplicate), per-bit counting is a reliable fallback: there are only 32 bit positions, so counting each position across the array is O(32·n) time and constant extra memory, and it adapts to "appears k times" for any k by taking counts modulo k.

In real systems

Bits are the native language of systems software. Unix file permissions (chmod 750) are three groups of three bits; network software tests and sets flags in packet headers with masks, and IP routing compares addresses under subnet masks (a /24 network is the top 24 bits). Feature flags and capability sets are often bitfields. Databases and search engines use bitmap indexes: Roaring Bitmaps, used by Apache Lucene, Spark, Druid and many others, compress sparse bitsets and perform AND/OR across millions of documents in microseconds. Bloom filters are a bit array plus hashing (al4). Chess and other board-game engines represent positions as bitboards — one 64-bit integer per piece type — and generate moves with shifts and masks, which is a major reason they search millions of positions per second. Hash functions and random-number generators (xorshift, FNV, MurmurHash) are built from XORs, shifts and multiplications. Compression formats pack variable-length codes into bit streams. The interview identities are the everyday tools of all of these.

Use bits to save memory or time

(a) "Maximum Product of Word Lengths": find the maximum len(a) × len(b) over pairs of words that share no letters; there are up to 1,000 words of up to 1,000 letters. (b) "Find the Duplicate Number" in an array of n + 1 values in 1..n with O(1) extra space and without modifying the array — give a bit-based solution as an alternative to Floyd's cycle detection. (c) Count the subsets of 25 items whose total weight is at most W, for many different W values up to 10⁶.

Answer

(a) Precompute a 26-bit mask per word (bit c set if letter c appears) in O(total letters). Two words share no letters exactly when mask[i] & mask[j] == 0, an O(1) check, so all pairs cost O(n²) = 10⁶ checks instead of comparing letter sets. Words with the same mask can be collapsed, keeping only the longest. (b) For each bit position i (about log₂ n of them), count how many array values have bit i set and how many numbers in 1..n have it set; if the array's count is larger, the duplicate has bit i set (the extra copies push the count up). Assemble the duplicate bit by bit: O(n log n) time, O(1) space. Floyd's algorithm is O(n), but this is a valid alternative that only uses counting. (c) 2²⁵ ≈ 3.4 × 10⁷ subsets is too many to enumerate per query. Meet in the middle (al13): split the items into halves of 12 and 13, enumerate each half's subset weights (4,096 and 8,192 of them, using bitmasks), and sort the second list. For a query W, for each weight s in the first list, count the second-list weights ≤ W − s with bisect, and add up: about 4,096 binary searches per query. With many queries, sort both lists and use a two-pointer sweep per query instead (O(4,096 + 8,192) each), or, since W ≤ 10⁶, precompute for every W the answer with a counting array over all pairwise sums processed in sorted order.
