A product team ships a feature where the model fills in a form: it returns JSON with a title, a summary, a list of tags and a confidence score. The first version waits for the whole response, parses it, and shows the form — six seconds of spinner. Users hate it. The second version streams the response and calls json.loads on the accumulated text every time a chunk arrives, ignoring errors until one succeeds. It feels faster but the CPU graph climbs with response length, the form appears all at once at the very end anyway, and one day, behind a corporate proxy, the stream starts producing garbled accented characters and the occasional event that is silently lost. The bugs are in two places nobody wrote tests for: the parser for the event stream itself, which assumed every network read was a whole line of whole characters, and the JSON handling, which had no notion of a partial value.

Streaming is the default way to consume large language models, because time to first token is the latency users feel. That makes parsing a stream a core AI-engineering skill, and machine-coding rounds increasingly ask for it: "here is a stream of bytes from a model API; parse the events" and then "the model is producing JSON; show the fields as they arrive". Both are classic incremental-parsing problems — state that survives between chunks, inputs that can be cut anywhere — with standards that define exactly what correct means: the HTML Living Standard for Server-Sent Events and RFC 8259 for JSON.

This lesson builds both parsers in interview order. It starts with what actually arrives on the wire and why chunks cannot be trusted; then an SSE parser that handles every line-ending form, comments, multi-line data, ids, retry, a byte-order mark, a CR separated from its LF by a chunk boundary, and UTF-8 characters split mid-sequence. Then an incremental JSON parser, a character-driven state machine with a stack, which shows strings growing, keys appearing when complete and numbers only once terminated, survives escapes and surrogate pairs split across chunks, and validates strictly at the end. The full solution is one Python 3.12 file with eight tests, including exhaustive split tests and a property test over 400 random documents in random chunk sizes, and an end-to-end test that streams a tool's arguments the way Claude's API does.

The analogy: reading a telegram delivered in torn strips

Imagine a long telegram delivered to you as strips of paper torn at random places — sometimes mid-word, sometimes mid-letter if the handwriting has letters that span two strips. You cannot read each strip on its own; you have to keep the unfinished end of the last strip in your hand and join it to the start of the next. The telegram has a format: each message ends with an empty line, and lines can be separated by different marks depending on which operator wrote them. When an empty line arrives, you hand the complete message to someone else. That is an SSE parser: a buffer for the unfinished part, a decoder for the letters, and a rule for when a message is complete.

Now suppose each message contains a form being filled in, written out as JSON. You want to show the form as it is being written, not after. You keep track of where you are — inside the main object, inside the "tags" list, in the middle of a string — like a finger on a nested outline. A name being written letter by letter can be shown letter by letter. A number cannot: "12" might be the start of "125". That is the incremental JSON parser: a stack of where you are, a little state for each level, and a rule for what is safe to show.

The analogy breaks in a helpful way: with paper you can see that a strip is torn mid-letter. With bytes you cannot, so the decoder needs to know the encoding's rules (UTF-8 says how many bytes each character takes) to hold back an incomplete character.

What arrives on the wire

A streamed model response is an HTTP response with content type text/event-stream. Its body is a sequence of SSE events. In Anthropic's Messages API, for example, each event has an event: line naming its type — message_start, content_block_start, content_block_delta, content_block_stop, message_delta, message_stop, and occasional pings — and a data: line holding JSON. Text arrives in content_block_delta events whose delta has type text_delta; a tool call's arguments arrive as deltas of type input_json_delta carrying a partial_json fragment. So there are three layers: bytes → SSE events; each event's data → a JSON object (complete within the event); and the concatenated text or partial_json fragments → a JSON document that is itself arriving piece by piece.

What the round expects

An SSEParser with feed(bytes) → events that follows the standard; an IncrementalJSON with feed(text), snapshot() and finish(); a clear rule for what partial values are shown; strict errors with positions; and tests that split inputs at every possible point. Interviewers listen for whether you test chunk boundaries deliberately, because that is where every real bug lives.

1 · Clarify the requirements

Ask: is the input bytes or already-decoded text? (Bytes — so UTF-8 decoding is our problem.) Which SSE features matter — event types, ids for resumption, retry? (All of them, per the standard.) What JSON will be streamed — any valid JSON, or a known schema? (Any valid JSON; a schema check at the end.) What should partial output look like, and how often is it needed? (A snapshot after each chunk, for a UI.) What happens on invalid input or a truncated stream? (A clear error with a position; never a silently repaired value.) Performance target? (Linear in input size; a chunk should cost time proportional to its own length.)

Keeping the two parsers separate matters: SSE is the transport format, JSON is the payload, and the same JSON parser serves a stream of plain text deltas, a stream of tool-argument fragments, or a file read in blocks.

3 · Stage one: the SSE parser

The rules, from the standard. The stream is UTF-8; one leading byte-order mark (U+FEFF) is stripped. Lines end with CRLF, a lone LF, or a lone CR. For each line: if it is empty, dispatch the event; if it starts with a colon, ignore it (a comment — servers send these as keep-alives); otherwise split at the first colon into field and value, and if the value starts with a space, remove exactly that one space; a line with no colon is a field with an empty value. Fields: data appends the value plus a newline to the data buffer; event sets the event type; id sets the last event ID unless the value contains a NUL character; retry sets the reconnection time if the value is all ASCII digits; anything else is ignored. Dispatch: if the data buffer is empty, reset and produce nothing; otherwise remove the final newline, produce an event of the given type (default message) with the data and the last event ID, and reset the data and type buffers — but not the last event ID, which persists. At end of stream, an event without its terminating blank line is discarded.

Bytes to text. Decoding each chunk with chunk.decode("utf-8") fails when a chunk ends in the middle of a multi-byte character: "ã" is two bytes, C3 A3, and if a chunk ends after C3 the decode raises (or, with errors="replace", silently produces "�" twice). Python's codecs.getincrementaldecoder("utf-8")() keeps incomplete sequences between calls and returns only whole characters. That one line fixes the "garbled accents behind the proxy" bug from the opening story.

Lines across chunks. Keep a text buffer. After appending a chunk, repeatedly find the first CR or LF; the text before it is a complete line; consume the line ending. The subtle case is a CR that is the last character of the buffer: it might be a lone CR (a line ending on its own) or the first half of CRLF whose LF is in the next chunk. The parser ends the line at the CR and sets pending_cr; when the next chunk arrives, if it starts with LF, that LF is dropped. Without this, the LF would be read as a second, empty line — a dispatch — and the event would be emitted early with partial data, or an empty-data dispatch would silently swallow the next field. The test test_sse_cr_at_chunk_end_is_one_line_ending feeds "data: a\r", then "\n" (nothing must happen), then "\r\n" (now the event dispatches).

A worked parse. Feed the stream ": keep-alive\nevent: content_block_delta\nid: 7\ndata: {"text": "Hel"}\n\n. Line 1 starts with a colon: ignored. Line 2 sets the type. Line 3 sets the last ID to 7. Line 4 appends {"text": "Hel"} plus a newline to the data buffer (one space after the colon removed). Line 5 is empty: dispatch — strip the trailing newline, emit SSEEvent("content_block_delta", '{"text": "Hel"}', "7"), reset data and type. A following data:no-space and data: two-spaces produce data "no-space\n two-spaces": no space to strip on the first, exactly one stripped on the second, joined with a newline.

4 · Stage two: JSON the naive way

buf = ""
for piece in fragments:
    buf += piece
    try:
        show(json.loads(buf))       # succeeds only when the document is complete
    except json.JSONDecodeError:
        pass

Three problems. It shows nothing until the end, which defeats the purpose. It re-parses everything every time: for a 40,000-character output in 5-character fragments, 8,000 parses averaging 20,000 characters is 160 million character visits instead of 40,000 — quadratic. And a popular patch, "repair" the partial text by closing open quotes and brackets and then parsing, works for simple cases but breaks on a fragment ending after a backslash or inside a \u escape, and still re-parses everything. The fix is a parser whose state survives between fragments.

5 · Stage three: the incremental JSON parser

The state. A stack of open containers. Each frame holds the container itself (a dict or list that is already attached to the partial value) and its state. An object frame is in one of: key_or_end (just opened: a key or }), key (after a comma: a key is required — this is what rejects a trailing comma), colon, value, in_string, or comma_or_end; plus the current key. An array frame is in value_or_end, value, in_string or comma_or_end. Separately, a token in progress: a string (its characters so far, whether it is a key, an escape in progress, a pending high surrogate) or the text of a number or literal.

One character at a time. feed loops over characters and calls _char. Inside a string, characters go to the string handler. Inside a number or literal, characters that can continue it are appended; any other character terminates it — the number is validated against JSON's grammar (-?(0|[1-9]\d*)(\.\d+)?([eE][+-]?\d+)?, which rejects 01, 1. and -), placed, and the terminating character is then processed normally. Outside tokens: whitespace is skipped; the frame's state says what is legal; { and [ create a container, attach it where a value is expected and push a frame; " starts a key or a string value; - or a digit starts a number; t, f, n start a literal; ,, :, } and ] move frame states or pop frames. Anything else raises JSONStreamError with the character position.

What becomes visible when. Containers are attached the moment they open, so the snapshot shows {} immediately. A key is not shown until its closing quote: half a key is useless. A string value is attached as "" when its opening quote arrives and re-set on every character, so the user watches it grow. A number or literal is attached only when terminated. Worked on the test stream, fed as {"na | me": "Ad | a", "age": 3 | 6, "tags": ["x | ", "y"], "ok": tr | ue}, the snapshots after each piece are: {}; {"name": "Ad"}; {"name": "Ada"} (36 is not shown — it is only "3" so far); {"name": "Ada", "age": 36, "tags": ["x"]} (the comma terminated 36); then "y" appears, then "ok": true once } terminates the literal.

6 · Stage four: escapes and surrogate pairs across chunks

JSON strings can contain escapes: \", \\, \/, \b, \f, \n, \r, \t, and \uXXXX with four hex digits. A chunk can end right after the backslash, or after \u00. So the parser keeps the escape in progress as a short string and completes it one character at a time; a \u escape is decoded only when the fourth hex digit arrives, and a non-hex digit raises an error.

Characters above U+FFFF — every emoji — are written in escaped JSON as a surrogate pair: json.dumps("😀") with ASCII escaping gives "😀". The first escape is a high surrogate (D800-DBFF) that is not a character by itself. The parser holds it, requires that the very next thing be a \u escape with a low surrogate (DC00-DFFF), and combines them: code point = 0x10000 + ((high − 0xD800) × 1024) + (low − 0xDC00). For D83D and DE00: 0x10000 + (0x3D × 0x400) + 0x200 = 0x1F600, 😀. A lone low surrogate, a high surrogate followed by anything else, or a string that ends with a pending high surrogate is an error. The test serialises a document with escapes, a surrogate pair and accented characters using ASCII escaping, then tries every split point and several three-way splits, requiring the exact same result each time.

Unescaped control characters (code points below 0x20, such as a raw newline) are not allowed inside JSON strings; the parser rejects them, which catches a common model mistake.

7 · Stage five: finishing and validating

finish() is strict. If a number or literal is still open (the document is just 42 at top level, with nothing after it), it is terminated and validated. Then, if a string is open, the stack is not empty, or no complete top-level value exists, the document is incomplete: raise with the position. Anything other than whitespace after the top-level value has already raised during feed. Only then does the application check the shape: the tiny check_shape validator in the solution (types, required keys, array items) returns a list of path-qualified errors — or, in a real system, the same JSON Schema validator as ld21's tool registry. Partial snapshots are deliberately lenient; the final value is deliberately strict, and nothing acts on a value that has not passed both.

8 · Stage six: testing chunk boundaries on purpose

Every real bug in streaming parsers lives at a chunk boundary, so the tests attack boundaries directly. For SSE, a stream containing a BOM, CRLF, a lone CR, a lone LF, accented characters, an arrow, an emoji and an unterminated final event is fed split at every possible byte position, and in 300 random splits into pieces of 1-4 bytes; every split must produce the same two events. For JSON, a property test generates 400 random documents — nested objects and arrays, keys with quotes, backslashes and non-Latin letters, strings with escapes and emoji, integers, floats, literals — serialises each with random choices of ASCII escaping and indentation, feeds them in random 1-5-character pieces, takes a snapshot after every piece, and requires finish() to equal json.loads on the full text. A list of invalid documents (leading zero, half literal, missing colon, trailing comma, bad escape, lone surrogate, trailing garbage, raw newline in a string, missing comma, unterminated object, bad hex, comma in an empty object) must each raise.

Finally, an end-to-end test builds a body of SSE events shaped like Claude's stream — message_start, a series of content_block_delta events whose data is {"type": "content_block_delta", "delta": {"type": "input_json_delta", "partial_json": "…"}}, then message_stop — delivers it in 7-byte network chunks, feeds each partial_json to the incremental parser, records the city field as it grows ("S", "São P", … "São Paulo"), and validates the final arguments against a schema.

9 · The full solution

Python 3.12, standard library only; eight tests run in about a second.

"""A streaming parser for LLM output: an incremental Server-Sent Events parser (HTML Living Standard
rules: CR/LF/CRLF line endings split anywhere, comments, multi-line data, id, retry, BOM, UTF-8
split across chunks), then an incremental JSON parser that emits partial objects as tokens arrive,
handling chunk boundaries inside strings, escapes, surrogate pairs, numbers and literals, with
strict validation at the end. Python 3.12, standard library only.  Run: python stream_parse.py"""
from __future__ import annotations

import codecs
import copy
import json
import random
import re
from dataclasses import dataclass
from typing import Any


# ================================================================ Server-Sent Events
@dataclass(frozen=True)
class SSEEvent:
    type: str            # "message" unless an event: field set it
    data: str
    id: str              # the last event ID at dispatch time ("" if none yet)


class SSEParser:
    """feed(bytes) -> list of events dispatched by that chunk. Bytes can be split anywhere."""

    def __init__(self) -> None:
        self._decoder = codecs.getincrementaldecoder("utf-8")()
        self._buf = ""                  # text not yet terminated by a line ending
        self._pending_cr = False        # chunk ended in CR: an LF at the next chunk's start is the same line ending
        self._started = False           # strip one leading BOM
        self._data: list[str] = []
        self._event = ""
        self.last_id = ""
        self.retry_ms: int | None = None

    def feed(self, chunk: bytes) -> list[SSEEvent]:
        text = self._decoder.decode(chunk)
        if not self._started and text:
            self._started = True
            if text.startswith("\ufeff"):
                text = text[1:]
        if self._pending_cr and text.startswith("\n"):
            text = text[1:]
        self._pending_cr = False
        self._buf += text
        events: list[SSEEvent] = []
        while True:
            i = min((p for p in (self._buf.find("\r"), self._buf.find("\n")) if p != -1), default=-1)
            if i == -1:
                break
            line = self._buf[:i]
            if self._buf[i] == "\r":
                if i + 1 == len(self._buf):     # CR is last: maybe half of a CRLF
                    self._pending_cr = True
                    self._buf = ""
                else:
                    self._buf = self._buf[i + 2:] if self._buf[i + 1] == "\n" else self._buf[i + 1:]
            else:
                self._buf = self._buf[i + 1:]
            ev = self._line(line)
            if ev is not None:
                events.append(ev)
        return events

    def close(self) -> None:
        """End of stream: an event without its terminating blank line is discarded, per the spec."""
        self._buf, self._data, self._event = "", [], ""

    def _line(self, line: str) -> SSEEvent | None:
        if line == "":
            return self._dispatch()
        if line.startswith(":"):
            return None                                     # comment (often a keep-alive)
        field, sep, value = line.partition(":")
        if sep and value.startswith(" "):
            value = value[1:]                               # exactly one leading space removed
        if field == "data":
            self._data.append(value)
        elif field == "event":
            self._event = value
        elif field == "id":
            if "\0" not in value:
                self.last_id = value
        elif field == "retry":
            if value.isascii() and value.isdigit():
                self.retry_ms = int(value)
        return None                                         # unknown fields are ignored

    def _dispatch(self) -> SSEEvent | None:
        data, etype = "\n".join(self._data), self._event or "message"
        had_data = bool(self._data)
        self._data, self._event = [], ""
        if not had_data:
            return None                                     # empty data buffer: no event
        return SSEEvent(etype, data, self.last_id)


# ================================================================ incremental JSON
class JSONStreamError(ValueError):
    pass


_WS = " \t\n\r"
_ESC = {'"': '"', "\\": "\\", "/": "/", "b": "\b", "f": "\f", "n": "\n", "r": "\r", "t": "\t"}
_NUM_CHARS = set("0123456789+-.eE")
_LITERALS = {"true": True, "false": False, "null": None}


_NUMBER = re.compile(r"-?(0|[1-9]\d*)(\.\d+)?([eE][+-]?\d+)?")


def _valid_number(s: str) -> bool:
    return _NUMBER.fullmatch(s) is not None


class IncrementalJSON:
    """feed(text) consumes characters as they arrive and keeps a partial value:
       - containers appear as soon as they open; keys appear once complete;
       - string values appear immediately and grow as characters arrive;
       - numbers and true/false/null appear only once complete (12 could still become 123).
    snapshot() returns a deep copy of the partial value; finish() validates and returns the final one."""

    def __init__(self) -> None:
        self.root: Any = None
        self._has_root = False
        self._done = False              # root value complete
        self._stack: list[dict] = []    # frames: {"c": container, "state": ..., "key": ...}
        self._tok: str | None = None    # "str" | "num" | "lit" while a scalar token is open
        self._buf = ""                  # number/literal text, or string escape in progress
        self._str: list[str] = []       # current string's characters
        self._str_is_key = False
        self._esc: str | None = None    # None, "\\" or "\\uXXXX..." in progress
        self._high: int | None = None   # pending high surrogate
        self.pos = 0                    # characters consumed, for error messages

    # ---- public API
    def feed(self, text: str) -> None:
        for ch in text:
            self._char(ch)
            self.pos += 1

    def snapshot(self) -> Any:
        return copy.deepcopy(self.root)

    def finish(self) -> Any:
        if self._tok in ("num", "lit"):
            self._end_scalar()
        if self._tok == "str" or self._stack or not self._done:
            raise JSONStreamError(f"incomplete JSON at end of stream (position {self.pos})")
        return self.root

    # ---- placing values
    def _place(self, value: Any) -> None:
        """Attach a new value (container or complete scalar) where the grammar expects one."""
        if not self._stack:
            if self._has_root:
                raise JSONStreamError(f"unexpected value after the top-level value at {self.pos}")
            self.root, self._has_root = value, True
            return
        f = self._stack[-1]
        if f["state"] == "value" and isinstance(f["c"], dict):
            f["c"][f["key"]] = value
            f["state"] = "comma_or_end"
        elif f["state"] in ("value_or_end", "value") and isinstance(f["c"], list):
            f["c"].append(value)
            f["state"] = "comma_or_end"
        else:
            raise JSONStreamError(f"unexpected value at {self.pos}")

    def _value_complete(self) -> None:
        if not self._stack:
            self._done = True

    def _expecting_value(self) -> bool:
        if not self._stack:
            return not self._has_root
        f = self._stack[-1]
        return f["state"] == "value" or (f["state"] == "value_or_end" and isinstance(f["c"], list))

    # ---- scalars
    def _end_scalar(self) -> None:
        s, kind = self._buf, self._tok
        self._tok, self._buf = None, ""
        if kind == "num":
            if not _valid_number(s):
                raise JSONStreamError(f"invalid number {s!r} ending at {self.pos}")
            self._place(float(s) if any(c in s for c in ".eE") else int(s))
        else:
            if s not in _LITERALS:
                raise JSONStreamError(f"invalid literal {s!r} ending at {self.pos}")
            self._place(_LITERALS[s])
        self._value_complete()

    def _string_char(self, ch: str) -> None:
        if self._esc is not None:
            self._esc += ch
            if self._esc == "\\u" or (self._esc.startswith("\\u") and len(self._esc) < 6):
                return                                          # still collecting 4 hex digits
            if self._esc.startswith("\\u"):
                hexs = self._esc[2:]
                if any(c not in "0123456789abcdefABCDEF" for c in hexs):
                    raise JSONStreamError(f"bad \\u escape {self._esc!r} at {self.pos}")
                cp = int(hexs, 16)
                self._esc = None
                if 0xD800 <= cp <= 0xDBFF:                      # high surrogate: wait for the low half
                    self._high = cp
                    return
                if 0xDC00 <= cp <= 0xDFFF:
                    if self._high is None:
                        raise JSONStreamError(f"lone low surrogate at {self.pos}")
                    cp = 0x10000 + ((self._high - 0xD800) << 10) + (cp - 0xDC00)
                    self._high = None
                self._emit_str(chr(cp))
                return
            if ch not in _ESC:
                raise JSONStreamError(f"bad escape \\{ch} at {self.pos}")
            self._esc = None
            self._emit_str(_ESC[ch])
            return
        if self._high is not None and ch != "\\":
            raise JSONStreamError(f"high surrogate not followed by a low surrogate at {self.pos}")
        if ch == "\\":
            self._esc = "\\"
        elif ch == '"':
            self._close_string()
        elif ord(ch) < 0x20:
            raise JSONStreamError(f"unescaped control character in string at {self.pos}")
        else:
            self._emit_str(ch)

    def _emit_str(self, s: str) -> None:
        self._str.append(s)
        if not self._str_is_key:                                # grow the visible partial value
            self._set_current_string("".join(self._str))

    def _set_current_string(self, s: str) -> None:
        if not self._stack:
            self.root = s
            return
        f = self._stack[-1]
        if isinstance(f["c"], dict):
            f["c"][f["key"]] = s
        else:
            f["c"][-1] = s

    def _close_string(self) -> None:
        s = "".join(self._str)
        self._tok, self._str = None, []
        if self._high is not None:
            raise JSONStreamError(f"unpaired high surrogate at {self.pos}")
        if self._str_is_key:
            f = self._stack[-1]
            f["key"], f["state"] = s, "colon"
        else:
            self._set_current_string(s)
            if self._stack:
                self._stack[-1]["state"] = "comma_or_end"
            self._value_complete()

    def _open_string_value(self) -> None:
        self._place("")                                         # visible immediately as ""
        if self._stack:
            self._stack[-1]["state"] = "in_string"
        self._tok, self._str, self._str_is_key = "str", [], False

    # ---- the character dispatcher
    def _char(self, ch: str) -> None:
        if self._tok == "str":
            self._string_char(ch)
            return
        if self._tok in ("num", "lit"):
            if (self._tok == "num" and ch in _NUM_CHARS) or (self._tok == "lit" and ch.isalpha()):
                self._buf += ch
                return
            self._end_scalar()                                  # this char terminates it; fall through
        if ch in _WS:
            return
        if self._done:
            raise JSONStreamError(f"unexpected {ch!r} after the top-level value at {self.pos}")
        f = self._stack[-1] if self._stack else None

        if f is not None and isinstance(f["c"], dict) and f["state"] in ("key_or_end", "key"):
            if ch == '"':
                self._tok, self._str, self._str_is_key = "str", [], True
            elif ch == "}" and f["state"] == "key_or_end":
                self._close_container()
            else:
                raise JSONStreamError(f"expected a key at {self.pos}, got {ch!r}")
            return
        if f is not None and f["state"] == "colon":
            if ch != ":":
                raise JSONStreamError(f"expected ':' at {self.pos}, got {ch!r}")
            f["state"] = "value"
            return
        if f is not None and f["state"] == "comma_or_end":
            if ch == ",":
                f["state"] = "key" if isinstance(f["c"], dict) else "value"
            elif ch == ("}" if isinstance(f["c"], dict) else "]"):
                self._close_container()
            else:
                raise JSONStreamError(f"expected ',' or close at {self.pos}, got {ch!r}")
            return
        if f is not None and isinstance(f["c"], list) and f["state"] == "value_or_end" and ch == "]":
            self._close_container()
            return
        if not self._expecting_value():
            raise JSONStreamError(f"unexpected {ch!r} at {self.pos}")
        if ch == "{":
            d: dict = {}
            self._place(d)
            self._stack.append({"c": d, "state": "key_or_end", "key": None})
        elif ch == "[":
            a: list = []
            self._place(a)
            self._stack.append({"c": a, "state": "value_or_end", "key": None})
        elif ch == '"':
            self._open_string_value()
        elif ch == "-" or ch.isdigit():
            self._tok, self._buf = "num", ch
        elif ch in "tfn":
            self._tok, self._buf = "lit", ch
        else:
            raise JSONStreamError(f"unexpected {ch!r} at {self.pos}")

    def _close_container(self) -> None:
        self._stack.pop()
        if self._stack:
            self._stack[-1]["state"] = "comma_or_end"
        self._value_complete()


# ================================================================ end-of-stream validation
def check_shape(value: Any, schema: dict, path: str = "$") -> list[str]:
    """Tiny schema check run once the stream is complete: types, required keys, items."""
    errors: list[str] = []
    types = {"object": dict, "array": list, "string": str, "number": (int, float),
             "integer": int, "boolean": bool}
    t = schema.get("type")
    if t and (not isinstance(value, types[t]) or (t in ("number", "integer") and isinstance(value, bool))):
        return [f"{path}: expected {t}"]
    if t == "object":
        for k in schema.get("required", []):
            if k not in value:
                errors.append(f"{path}: missing {k!r}")
        for k, sub in schema.get("properties", {}).items():
            if k in value:
                errors += check_shape(value[k], sub, f"{path}.{k}")
    if t == "array" and "items" in schema:
        for i, v in enumerate(value):
            errors += check_shape(v, schema["items"], f"{path}[{i}]")
    return errors

def chunks(data: str | bytes, sizes: list[int]):
    i = 0
    for n in sizes:
        yield data[i:i + n]
        i += n
    if i < len(data):
        yield data[i:]


def sse_all(raw: bytes, split) -> list[SSEEvent]:
    p, out = SSEParser(), []
    for c in split(raw):
        out += p.feed(c)
    p.close()
    return out


def test_sse_basic_fields_and_comments() -> None:
    raw = (b": keep-alive\n"
           b"event: content_block_delta\nid: 7\ndata: {\"text\": \"Hel\"}\n\n"
           b"data:no-space\ndata:  two-spaces\n\n"
           b"retry: 3000\nfoo: ignored\ndata\n\n"
           b"id\ndata: x\n\n")
    p = SSEParser()
    evs = p.feed(raw)
    assert evs[0] == SSEEvent("content_block_delta", '{"text": "Hel"}', "7")

    assert evs[2] == SSEEvent("message", "", "7") and p.retry_ms == 3000   # 'data' with no colon = empty value
    assert evs[3] == SSEEvent("message", "x", "")                           # 'id' with no value resets it

def test_sse_line_endings_split_anywhere() -> None:

def test_json_escapes_and_surrogates_split_anywhere() -> None:
    text = json.dumps({"q": 'say "hi"\\ok\n\t', "emoji": "😀 é", "u": "\u00e9\u20ac",
                       "nested": [1, -2.5e-3, {"k": [True, False, None]}], "z": ""}, ensure_ascii=True)

    expected = json.loads(text)

def random_json(rng: random.Random, depth: int = 0) -> Any:
    kind = rng.choice(["obj", "arr", "str", "int", "float", "lit"] if depth < 3 else ["str", "int", "float", "lit"])
    if kind == "obj":
        return {rng.choice(["a", "b\"q", "ключ", "k\\n", "😀"]) + str(i): random_json(rng, depth + 1)
                for i in range(rng.randint(0, 4))}
    if kind == "arr":
        return [random_json(rng, depth + 1) for _ in range(rng.randint(0, 4))]
    if kind == "str":
        return "".join(rng.choice('ab "\\/\n\t\u00e9\u4e2d😀') for _ in range(rng.randint(0, 8)))
    if kind == "int":
        return rng.randint(-10**6, 10**6)
    if kind == "float":
        return rng.choice([0.5, -1.25e-7, 3.0e10, 123.456])
    return rng.choice([True, False, None])

def test_end_to_end_llm_stream() -> None:
    """SSE events carrying JSON deltas whose text is itself streamed JSON (a tool's arguments)."""
    args = {"city": "São Paulo", "days": 3, "units": "metric"}
    payload = json.dumps(args)
    parts = [payload[i:i + 5] for i in range(0, len(payload), 5)]
    body = "event: message_start\ndata: {}\n\n"
    for part in parts:
        delta = {"type": "content_block_delta", "delta": {"type": "input_json_delta", "partial_json": part}}
        body += f"event: content_block_delta\ndata: {json.dumps(delta)}\n\n"
    body += "event: message_stop\ndata: {}\n\n"
    raw = body.encode()
    sse, js, seen_city = SSEParser(), IncrementalJSON(), []
    for i in range(0, len(raw), 7):                                  # 7-byte network chunks
        for ev in sse.feed(raw[i:i + 7]):
            if ev.type == "content_block_delta":
                js.feed(json.loads(ev.data)["delta"]["partial_json"])
                city = (js.snapshot() or {}).get("city")
                if city and (not seen_city or seen_city[-1] != city):
                    seen_city.append(city)
    final = js.finish()
    assert final == args and seen_city[-1] == "São Paulo" and len(seen_city) > 1   # city grew live
    schema = {"type": "object", "required": ["city", "days"],
              "properties": {"city": {"type": "string"}, "days": {"type": "integer"}}}
    assert check_shape(final, schema) == []
    assert check_shape({"city": 5}, schema) == ["$: missing 'days'", "$.city: expected string"]

10 · Edge cases

A chunk that is empty: the decoder returns nothing; nothing happens. A BOM in the middle of the stream: only a leading one is stripped; later ones are data. id containing NUL: ignored, per the standard. retry with non-digits (retry: 3s): ignored. Very long lines: the line buffer grows without bound; cap it (say 1 MB) and raise, so a misbehaving server cannot exhaust memory. Invalid UTF-8: the strict decoder raises; decide whether to fail the stream or use errors="replace". Top-level scalars: "text" or 42 are valid JSON; a model asked for an object should still be validated as one. Duplicate keys: JSON allows them and this parser, like json.loads, keeps the last; a stricter mode could reject them. Deep nesting: the explicit stack has no recursion limit, unlike a recursive parser — but a cap protects memory. Big numbers: integers stay exact in Python; floats lose precision beyond 253 as everywhere.

11 · Extensions the interviewer will ask for

Events instead of snapshots: emit (path, change) events — key started, string appended, value completed — so consumers update incrementally in O(change) rather than deep-copying; the stack already knows the path. Field-complete callbacks: call a handler when a given path completes (start rendering the "summary" section once its string closes). Async iteration: wrap the parsers in an async generator over an HTTP client's byte stream. Reconnection: on a dropped SSE connection, reconnect after the retry time with a Last-Event-ID header carrying the parser's last_id, as browsers' EventSource does. Schema-guided partials: with a known schema, show placeholders for fields not yet started. Performance: process runs of ordinary characters inside strings with one slice instead of per-character calls; that is where a C-speed scan (str.find for the next quote or backslash) gives a large constant-factor win.

12 · Complexity

Both parsers do O(1) amortised work per input character (SSE: each character is scanned once for line endings and copied once into a line; JSON: each character visits _char once), so total time is O(n) for an n-character stream regardless of chunking — versus O(n²/c) for re-parsing the buffer per chunk of size c. Memory: SSE holds the current line and the current event's data; JSON holds the partial value (O(n)) and a stack as deep as the nesting. snapshot() deep-copies the partial value, O(n) per call, which is why events replace snapshots for large documents.

Why SSE dominates model APIs

Server-Sent Events are plain HTTP: a normal request, a response that stays open, text lines in the body. That means they pass through load balancers, proxies, CDNs and corporate firewalls that would block or mangle other protocols, work with ordinary HTTP authentication and retries, and need nothing special on the client beyond reading a response body. Model responses are one-directional — the server talks, the client listens — so the two-way channel WebSockets provide is unnecessary. The format's details then make sense: comments as keep-alives so idle intermediaries do not close the connection during a long pause; ids and Last-Event-ID so a browser can resume; retry so the server can tell clients how fast to reconnect. Model APIs mostly do not support resumption by id, so a dropped stream generally means re-issuing the request — another reason the commit point (ld4) matters.

The repair-and-parse approach, and when it is acceptable

Many client libraries show partial JSON by "repairing" the buffer — appending the closing quotes and brackets the open structure needs — and calling a normal parser. It is attractive because it reuses a fast, correct parser. Its costs: quadratic total work, fragility at escape boundaries (a buffer ending in \ or \u00 cannot be closed with a quote), and ambiguity for numbers and literals (repairing tr needs a guess). For short outputs — a few hundred characters of tool arguments — it is fine and simpler. For long structured outputs, documents with many escapes, or high-throughput servers parsing thousands of streams at once, an incremental state machine is the right tool. Saying both, with the crossover, is what an interviewer wants to hear.

Tokens are not characters

Models produce tokens, and a token can be several characters, part of a multi-byte character, or a mix of structure and content ("name": " may be one or two tokens). The API delivers text deltas, which are already decoded characters, but there is no guarantee a delta ends at a JSON token boundary — or, at the byte level, at a character boundary. This is why the parser must be character-driven at the JSON layer and byte-aware at the transport layer. It also explains a UX quirk: partial strings can appear to "jump" by several characters at once, because one delta carried a multi-character token.

Constrained decoding changes the failure modes, not the parser

With structured outputs or strict tool use, the provider constrains generation so the output matches a schema. That removes most syntax errors and schema violations in complete outputs, but the stream is still delivered in arbitrary fragments, still needs incremental parsing for a responsive UI, and can still be cut off by a token limit or a dropped connection, leaving an incomplete document. The end-of-stream checks therefore remain: completeness from finish(), shape from the schema, and meaning from business rules that no schema can express.

Backpressure and the slow consumer

A parser that is fast enough on average can still fall behind if the consumer is slow — a UI that re-renders a large form on every snapshot, or a server that forwards parsed events to a mobile client on a poor connection. Because the HTTP response is a stream, falling behind does not lose data; it fills buffers, first in the client's socket and then, through TCP flow control, back toward the provider, which may eventually time out the stream. The usual fixes are to decouple parsing from rendering (parse every chunk, render at most every 50-100 ms from the latest state) and, on servers relaying streams, to bound the buffer per client and drop or conflate intermediate updates for slow clients while always delivering the final value. Parsing must never be the thing that is skipped, because the parser's state is what makes the final result correct.

Partial output and safety

Showing partial output means showing content before it has been checked. For most structured outputs that is harmless, but if outputs pass through moderation, PII redaction or a policy check, those checks run on the complete text, and the user has already seen the partial version. Designs that need checks before display either buffer until a check passes (sacrificing latency), check incrementally on sentence or field boundaries, or show partial content in a clearly provisional state. The same applies to tool arguments: render them as they arrive for transparency, but never execute a tool on a partial snapshot.

How streaming parsers fail in production

Garbled non-ASCII text. Symptom: occasional "�" in streamed output, only behind some proxies or on some networks. Cause: per-chunk decoding of UTF-8 split mid-character. Fix: an incremental decoder; test with multi-byte characters at every split.

Events lost or merged. Symptom: rare missing deltas, or two deltas concatenated. Cause: splitting on \n only while a proxy normalised line endings to CRLF, or a CR/LF pair split across reads. Fix: handle all three line endings and the pending CR; test every split.

CPU climbing with response length. Symptom: server CPU for streaming endpoints grows faster than traffic as responses lengthen. Cause: re-parsing the accumulated buffer per chunk. Fix: incremental parsing, or snapshots throttled to every N milliseconds.

Acting on truncated output. Symptom: a tool runs with arguments missing a field, or a form is saved half-filled. Cause: treating "the stream ended" as "the document is complete", or repairing partial JSON before acting. Fix: strict finish(), check the stop reason (a max_tokens stop means truncation), schema validation before any action.

Proxies that buffer. Symptom: streaming works directly but arrives all at once through one environment. Cause: an intermediary (a reverse proxy, a compression layer) buffering the response body. Fix: disable buffering and compression for text/event-stream on that path; the parser cannot fix this, but its time-to-first-event metric reveals it.

Idle connections dropped. Symptom: long generations fail after exactly 60 seconds of silence. Cause: an intermediary's idle timeout during a long pause before output. Fix: servers send comment or ping events as keep-alives; clients must ignore them correctly — which a parser that treats every line as data would not.

What to measure

Time to first byte and to first parsed event; time to first visible field; parse time per chunk and per stream; parser errors by type (invalid UTF-8, invalid JSON at a position, incomplete at end); the share of streams ending with max_tokens; snapshot frequency and size; and dropped-connection rates by network path.

Knobs

Maximum line length and maximum event size (memory safety); snapshot throttle interval for the UI (every chunk is often too frequent — 50-100 ms is plenty for humans); strict versus replacement decoding for invalid bytes; maximum nesting depth; and whether partial values are shown at all for fields that drive actions.

The real references

The SSE rules in this solution come from the HTML Living Standard's server-sent events section, which specifies the stream's ABNF grammar (an end of line is CRLF, CR or LF), that one leading BOM is stripped by UTF-8 decoding, how lines are interpreted (empty line dispatches, colon-prefixed lines are comments, one leading space removed from a value), what each field does (data accumulates with newlines, id sets the last event ID unless it contains NUL, retry accepts only ASCII digits), and that an event without its blank line at end of stream is discarded. The event shapes in the end-to-end test follow Claude's streaming documentation: message_start, content_block_start, content_block_delta with text_delta or input_json_delta (carrying partial_json), content_block_stop, message_delta, message_stop, and ping events. The JSON grammar — number syntax, string escapes, surrogate pairs — is RFC 8259's.

Debug it

A streaming chat client works in development. In production, about one response in two hundred shows a duplicated or missing chunk of text, always at a delta boundary, and users in Brazil report "SÃ£o" instead of "São" occasionally. The client decodes each network read with bytes.decode() and splits it with text.split("\n"). What two bugs are there, and how would you prove each?

Answer

Bug 1: per-read UTF-8 decoding. When a read ends between the two bytes of "ã" (C3 A3), decoding the halves separately fails or, with lenient decoding, produces wrong characters; "SÃ£o" is what you get when UTF-8 bytes are decoded as Latin-1 somewhere in a fallback path. Prove it by feeding a stream containing "São" split at every byte position. Fix: an incremental UTF-8 decoder. Bug 2: line splitting per read. Splitting each read on "\n" treats the end of every read as the end of a line, so a line split across two reads becomes two lines: the second half is parsed as a field with an unknown name (dropped — missing text) or a data line glued wrongly (duplicated or merged text). If production traffic passes through a proxy that uses CRLF, lines also keep a trailing "\r". Prove it by replaying a captured stream split at every position. Fix: a persistent line buffer, all three line endings, and the pending-CR rule.

Design it

A form-filling feature streams a 30-field JSON object from a model. Product wants each field to appear as soon as it is known, the "description" field to render word by word, and the form to auto-save only valid, complete output. Some responses hit the token limit. Sketch the client.

Answer

SSE parser over the byte stream; for each text delta, feed the incremental JSON parser; every 50 ms (not every chunk), take a snapshot or apply path events and render: fields appear when their key is complete, string fields (description) grow per character, numbers and booleans appear once terminated. Mark the whole form "generating". On message_stop, check the stop reason: if max_tokens, show the form as incomplete with the missing fields highlighted and offer to continue or regenerate; never auto-save. Otherwise call finish() (catching incomplete or invalid JSON), validate against the form's schema (required fields, types, enums) and business rules, and only then auto-save. If validation fails, show the errors and optionally ask the model to fix them with the error messages fed back.
