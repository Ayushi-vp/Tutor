"Design an in-memory file system" is one of the most common object-oriented machine-coding rounds, and its first version takes ten minutes: mkdir, ls, add content to a file, read it back. The interview is in what follows. What does ls return when the path is a file? What happens on mkdir("/a/b") when /a does not exist — and with -p? What about //a/./b/../c? Can you move /a into /a/b? What error does reading a directory raise? Now add per-user permissions. Now add quotas, and make the check fast enough to run on every write. Now find every file matching *.py. Now make it thread-safe.

Each follow-up tests a different design skill. The data structure question tests whether you see paths as sequences of components (a trie) rather than strings. Normalisation tests whether you centralise a subtle rule instead of sprinkling string handling everywhere. The error question tests API design: Python already has a precise exception for every file-system failure. mv tests invariants: a careless move creates a cycle and makes part of the tree unreachable. Quotas test incremental computation: storing a derived value and keeping it correct on every mutation. Permissions test whether you know what read, write and execute mean for a directory.

This lesson builds the file system in that order: clarify the operations; define nodes, files and directories as a composite; write the naive flat-dictionary version and see why it fails; then path normalisation, resolution, mkdir and mkdir -p, ls, write, append and read, rm and rm -r, and mv with its guards; then the extensions — usage counters and quotas in O(depth), owner/other permission bits, and find by glob. The full solution is a runnable Python 3.12 file with ten tests, including a comparison against a flat reference model over 6,000 random operations and a multi-threaded append test.

The analogy: a building's directory board

A large office building has a directory board in the lobby listing floors; each floor has its own board listing departments; each department's door lists its rooms. To find "Floor 3, Finance, Room 12" you read three boards in order, each one small and local. Adding a room means updating one department's door, not reprinting the whole lobby board. Moving the whole Finance department to Floor 5 means taking its sign off one floor board and putting it on another — every room inside comes along without being touched. Each board can also have a lock: some floors only let their own staff read the board, some doors only let staff add rooms. And the building manager keeps a running tally of how much space each floor uses, updated whenever a room changes size, so checking "is Floor 3 over its allowance?" never requires measuring every room.

The boards are directories, each a small mapping from names to what lies below; reading boards in order is path resolution; rooms are files; moving a department by moving its sign is mv; the locks are permissions; the running tally is usage with quotas.

The analogy breaks at one rule a building would never need to state: you cannot move Finance into one of Finance's own rooms. In a tree of pointers nothing physically prevents it, and doing it detaches the whole department from the building. The code has to check.

Why this round keeps coming back

Almost every engineer has used a file system for years without thinking about how it is organised, so the round tests whether you can turn familiar behaviour into precise rules. "What does mv do when the destination is a directory?" has an answer everyone knows from the shell and few can state exactly. The problem is also open-ended in a useful way: the core fits in twenty minutes, and the interviewer can keep adding realistic requirements — permissions, quotas, search, links, concurrency, persistence — each of which tests a different skill without changing the foundation. A clean tree with a single path normaliser, a single resolver and a single usage updater absorbs every one of them; a design built on string manipulation absorbs none.

What the round expects

Classes for files and directories with a shared base; a path normaliser; a resolver that walks components; mkdir with a parents flag, ls, write, append, read, rm with recursive, and mv; precise exceptions; and, as time allows, quotas, permissions and find. Strong candidates state the edge-case semantics before coding, keep derived data (usage) consistent on every mutation, and test against a simple model.

1 · Clarify the requirements

Ask: absolute paths only, or a current directory too? Are file contents text or bytes, and how is size measured? What does ls return for a file, and in what order? Does mkdir create parents? What happens when writing to a path whose parent does not exist? Does mv into an existing directory move inside it, like the shell? May mv overwrite a file? Which errors, and as what types? Which extensions matter: permissions, quotas, find, links? Thread safety? Agreed: absolute paths, normalised; text content, size in UTF-8 bytes; ls sorted, a file lists itself; mkdir(parents=…); writes require an existing parent; mv follows the shell (into a directory if one exists, may overwrite a file, never a directory); built-in exceptions; then quotas, owner/other permissions and glob find; one lock for thread safety.

2 · Entities and the interface

Node(name, owner, mode, parent)          # mode: owner rwx and other rwx, e.g. 0o75
  File(Node): data                       # size = UTF-8 bytes
  Dir(Node):  children: dict[str, Node], used: int, quota: int | None

MemFS
  mkdir(path, parents=False)    ls(path)              read(path)
  write(path, data)             append(path, data)    rm(path, recursive=False)
  mv(src, dst)                  set_quota(path, n)    usage(path)
  find(path, glob)              (every call takes user=…, default root)

Files and directories share a base class holding what every node has — name, owner, permission bits and a parent pointer — the composite pattern. The parent pointer makes walking up for usage updates and subtree checks O(depth). Directories store children in a plain dict: insertion and lookup are O(1), and ls sorts on demand.

3 · Stage one: the flat dictionary, and why not

files = {}                                # "/a/b/c.txt" -> content
def ls(path):  return sorted({k[len(path)+1:].split("/")[0] for k in files if k.startswith(path + "/")})
def mv(src, dst):
    for k in [k for k in files if k == src or k.startswith(src + "/")]:
        files[dst + k[len(src):]] = files.pop(k)

It works for the first four calls of the classic problem and then falls apart. ls scans every file in the system to list one directory. Directories do not exist unless they contain a file, so mkdir of an empty directory needs a second structure. Moving a directory rewrites every key under it. Nothing prevents both a file /a and a file /a/b. Prefix tests are subtle: startswith("/a") also matches /ab, which is why the code needs "/a/". A tree keyed by component fixes all of it: listing reads one dict, empty directories are nodes, moves relink one node, and a file cannot have children because it has no children field. The flat model is still useful — as the reference for testing, where its simplicity is the point.

4 · Stage two: normalisation and resolution

Normalise once. split(path) requires a leading slash, splits on /, skips empty parts (from // and trailing slashes) and ., and for .. pops the previous component if there is one. So //x///y/./z/../w becomes [x, y, w] and /../.. becomes [], the root. Every operation calls it first, so the rest of the code only ever sees clean component lists. This is lexical normalisation, like Python's os.path.normpath; with symbolic links (an extension) it can differ from the physical answer, which the edge cases cover.

Resolve by walking. _walk(parts) starts at the root and, for each component, checks that the current node is a directory (else NotADirectoryError naming the prefix), that the user may traverse it (the execute bit), and that the child exists (else FileNotFoundError naming the full prefix). _parent(path) resolves everything but the last component and returns (parent directory, last name), which is what creating, deleting and moving need. Errors carry the exact prefix that failed — /d/f rather than the whole path — which is what makes them useful to callers.

5 · Stage three: mkdir, mkdir -p and ls

mkdir(path, parents) walks the components, creating as needed. For each component: if missing, create a directory — but without parents only the last component may be missing (otherwise FileNotFoundError), and creating requires write and execute permission on the containing directory; if present and a file, NotADirectoryError; if present, a directory and the last component, FileExistsError unless parents is set, in which case it is a successful no-op, as with mkdir -p. ls(path) resolves the path; a file returns [its name]; a directory, after a read-permission check, returns sorted(children).

Traced on the classic session: ls("/") → []; mkdir("/a/b/c", parents=True) creates a, b, c; append("/a/b/c/d", "hello") creates file d with 5 bytes, adding 5 to the used counter of c, b, a and the root; ls("/") → ["a"]; ls("/a/b/c/d") → ["d"]; read → "hello"; a second append makes "hello world" and usage("/a") = 11.

6 · Stage four: write, append, read and rm

write and append share one method. Resolve the parent; if the name is a directory, IsADirectoryError; if the file is new, the user needs write permission on the parent; if it exists, on the file. Compute the new content and the size change delta (in UTF-8 bytes, so non-ASCII text is measured honestly), check quotas with that delta (stage six), and only then create the node if needed, store the data and add delta to every ancestor's usage. Ordering check-before-change means a refused write leaves the file system exactly as it was — the quota test verifies the file still holds its old 8 bytes after a refused append. read resolves, rejects directories, checks read permission and returns the data.

rm(path, recursive) resolves the parent and the node; a non-empty directory without recursive raises "directory not empty"; removing needs write permission on the parent (deleting changes the parent's list of names, not the node). Detaching the node from its parent removes the whole subtree in O(1) — the garbage collector reclaims it — and subtracting the subtree's used (or the file's size) from every ancestor keeps the counters right without visiting anything inside.

7 · Stage five: mv

mv(src, dst) mirrors the shell. Resolve the source node and its parent. If dst resolves to an existing directory, the target is "inside it, under the source's name"; otherwise the target is dst's parent with dst's last name. Then the guards, in order:

  1. No-op: if the target slot already holds this very node, return.
  2. No overwriting a directory: if the target slot holds a directory, IsADirectoryError. (Overwriting a file is allowed, as in the shell.)
  3. No moving into its own subtree: if the source is a directory, walk up from the target parent; meeting the source means the move would make the source its own ancestor — a cycle that detaches the subtree from the root. Raise OSError; POSIX's rename specifies an error for exactly this case.
  4. Permissions: write on both the source and target parents.
  5. Quotas: the moved bytes (minus any file being replaced) are checked against the target's ancestors up to, but not including, the common ancestor of the two parents — above it, the bytes were already counted.

Only then: unlink from the source parent and subtract its size up that chain, subtract a replaced file's size, relink under the new name and parent, and add the size up the new chain. 8 · Stage six: quotas in O(depth)

Every directory stores used, the bytes of all files in its subtree, maintained on every change by _add_usage(dir, delta), which walks to the root adding delta. A quota is an optional limit on a directory. _check_quota(dir, delta) walks the same path before the change and raises if any ancestor with a quota would exceed it — naming the directory, so quota exceeded at /home/alice: 8 + 3 > 10 is immediately actionable. Shrinking (a negative delta) is always allowed. Worked from the test: /home has a 20-byte quota and /home/alice 10. Alice writes 8 bytes: alice and home both at 8. Appending 3 more would make alice 11 > 10: refused, nothing changes. She shrinks the file to 2 bytes; Bob writes 10: home is at 12. Bob writing 9 more would make home 21 > 20: refused at /home, even though Bob's own directory has no quota. Moving a 9-byte file from /tmp into alice's docs would make alice 11: refused. The costs: every write is O(depth) — usually under 20 — instead of a subtree walk, and the counters are only correct if every mutation updates them, which is why there is exactly one function that changes them and the reference-model test checks total usage after every random operation.

9 · Stage seven: permissions and find

Permissions. Each node has an owner and two octal digits of rwx bits — owner and everyone else — so 0o75 means the owner may read, write and traverse, others may read and traverse. The rules are Unix's: reading a file needs r on it; listing a directory needs r; resolving a name inside a directory needs x on it (checked at every step of every path); creating, deleting or renaming an entry needs w on the containing directory; modifying a file needs w on the file. The root user bypasses checks. The test makes /home/alice mode 0o70 owned by alice: alice reads her file; bob cannot even reach it (no x on alice's directory), cannot list it, cannot create in /home; a world-readable file in /pub can be read but not overwritten by bob.

find. find(path, pattern) walks the subtree with an explicit stack and returns every path whose last component matches a glob (fnmatch.fnmatchcase, so *.py or test_*), skipping directories the user cannot read and traverse — as find on Unix reports permission errors and moves on. For bob, find("/", "*") lists /home/alice (visible in /home) but nothing inside it.

10 · Stage eight: testing against a flat model

The flat dictionary rejected in stage one comes back as the oracle: a set of directory paths and a dict of file path to content, where every operation is a few obviously-correct lines. Forty trials of 150 random operations — mkdir -p, write, append, rm (file or recursive), mv of files, read, ls — over paths built from just three names (so collisions, files where directories are expected, and overwrites happen constantly) run against both. Every operation must succeed or fail the same way in both, every read and ls must agree, and total usage must equal the sum of the model's file sizes after every step. A concurrency test then runs eight threads appending to one shared log and writing their own files: the log ends with exactly 4,000 bytes, 81 entries exist, and usage matches the contents.

11 · The full solution

Ten tests, Python 3.12, standard library only, well under a second.

"""An in-memory file system: a tree (trie) of directories keyed by path component, path normalisation,
mkdir (and mkdir -p), ls, write / append / read, mv and rm (-r), standard Python exceptions, then the
extensions: owner/other permission bits, per-directory size quotas maintained incrementally, and find
by glob pattern. Checked against a flat reference model on random operations, with a threaded test.
Python 3.12, standard library only.  Run: python memfs.py"""
from __future__ import annotations

import fnmatch
import random
import threading
from dataclasses import dataclass, field

ROOT_USER = "root"
R, W, X = 4, 2, 1


@dataclass(eq=False)
class Node:
    name: str
    owner: str
    mode: int                                        # two octal digits: owner rwx, other rwx, e.g. 0o75
    parent: "Dir | None"

    def can(self, user: str, bit: int) -> bool:
        if user == ROOT_USER:
            return True
        perms = (self.mode >> 3) & 7 if user == self.owner else self.mode & 7
        return bool(perms & bit)


@dataclass(eq=False)
class File(Node):
    data: str = ""

    @property
    def size(self) -> int:
        return len(self.data.encode())


@dataclass(eq=False)
class Dir(Node):
    children: dict[str, Node] = field(default_factory=dict)
    used: int = 0                                    # bytes of all files in this subtree
    quota: int | None = None


def split(path: str) -> list[str]:
    """Normalise an absolute path into components: collapse '//', resolve '.' and '..' (never above /)."""
    if not path.startswith("/"):
        raise ValueError(f"path must be absolute: {path!r}")
    out: list[str] = []
    for part in path.split("/"):
        if part in ("", "."):
            continue
        if part == "..":
            if out:
                out.pop()
            continue
        out.append(part)
    return out


class MemFS:
    def __init__(self) -> None:
        self.root = Dir("", ROOT_USER, 0o75, None)
        self._lock = threading.RLock()

    # ---------------------------------------------------------------- lookup
    def _walk(self, parts: list[str], user: str) -> Node:
        node: Node = self.root
        for i, name in enumerate(parts):
            if not isinstance(node, Dir):
                raise NotADirectoryError("/" + "/".join(parts[:i]))
            if not node.can(user, X):
                raise PermissionError(f"cannot traverse /{'/'.join(parts[:i])}")
            nxt = node.children.get(name)
            if nxt is None:
                raise FileNotFoundError("/" + "/".join(parts[:i + 1]))
            node = nxt
        return node

    def _parent(self, path: str, user: str) -> tuple[Dir, str]:
        parts = split(path)
        if not parts:
            raise PermissionError("cannot modify /")
        parent = self._walk(parts[:-1], user)
        if not isinstance(parent, Dir):
            raise NotADirectoryError("/" + "/".join(parts[:-1]))
        if not parent.can(user, X):
            raise PermissionError(f"cannot traverse /{'/'.join(parts[:-1])}")
        return parent, parts[-1]

    # ---------------------------------------------------------------- directories
    def mkdir(self, path: str, parents: bool = False, user: str = ROOT_USER, mode: int = 0o75) -> None:
        with self._lock:
            parts = split(path)
            node: Dir = self.root
            for i, name in enumerate(parts):
                last = i == len(parts) - 1
                child = node.children.get(name)
                if child is None:
                    if not last and not parents:
                        raise FileNotFoundError("/" + "/".join(parts[:i + 1]))
                    if not (node.can(user, W) and node.can(user, X)):
                        raise PermissionError(f"cannot create in /{'/'.join(parts[:i])}")
                    child = node.children[name] = Dir(name, user, mode, node)
                elif not isinstance(child, Dir):
                    raise NotADirectoryError("/" + "/".join(parts[:i + 1]))
                elif last and not parents:
                    raise FileExistsError(path)
                elif not child.can(user, X) and not last:
                    raise PermissionError(f"cannot traverse /{'/'.join(parts[:i + 1])}")
                node = child

    def ls(self, path: str = "/", user: str = ROOT_USER) -> list[str]:
        with self._lock:
            node = self._walk(split(path), user)
            if isinstance(node, File):
                return [node.name]                                # like `ls file`
            if not node.can(user, R):
                raise PermissionError(f"cannot list {path}")
            return sorted(node.children)

    # ---------------------------------------------------------------- files
    def write(self, path: str, data: str, user: str = ROOT_USER, mode: int = 0o64) -> None:
        self._put(path, data, append=False, user=user, mode=mode)

    def append(self, path: str, data: str, user: str = ROOT_USER, mode: int = 0o64) -> None:
        self._put(path, data, append=True, user=user, mode=mode)

    def _put(self, path: str, data: str, append: bool, user: str, mode: int) -> None:
        with self._lock:
            parent, name = self._parent(path, user)
            f = parent.children.get(name)
            if isinstance(f, Dir):
                raise IsADirectoryError(path)
            if f is None:
                if not parent.can(user, W):
                    raise PermissionError(f"cannot create {path}")
                new_data, old_size = data, 0
            else:
                if not f.can(user, W):
                    raise PermissionError(f"cannot write {path}")
                new_data, old_size = (f.data + data if append else data), f.size
            delta = len(new_data.encode()) - old_size
            self._check_quota(parent, delta)
            if f is None:
                f = parent.children[name] = File(name, user, mode, parent)
            f.data = new_data
            self._add_usage(parent, delta)

    def read(self, path: str, user: str = ROOT_USER) -> str:
        with self._lock:
            node = self._walk(split(path), user)
            if isinstance(node, Dir):
                raise IsADirectoryError(path)
            if not node.can(user, R):
                raise PermissionError(f"cannot read {path}")
            return node.data

    # ---------------------------------------------------------------- remove and move
    def rm(self, path: str, recursive: bool = False, user: str = ROOT_USER) -> None:
        with self._lock:
            parent, name = self._parent(path, user)
            node = parent.children.get(name)
            if node is None:
                raise FileNotFoundError(path)
            if isinstance(node, Dir) and node.children and not recursive:
                raise OSError(f"directory not empty: {path}")
            if not parent.can(user, W):
                raise PermissionError(f"cannot remove from {path.rsplit('/', 1)[0] or '/'}")
            size = node.used if isinstance(node, Dir) else node.size
            del parent.children[name]
            node.parent = None
            self._add_usage(parent, -size)

    def mv(self, src: str, dst: str, user: str = ROOT_USER) -> None:
        """Rename or move. If dst is an existing directory, move src into it (like `mv a dir/`)."""
        with self._lock:
            sparent, sname = self._parent(src, user)
            node = sparent.children.get(sname)
            if node is None:
                raise FileNotFoundError(src)
            dparts = split(dst)
            try:
                target = self._walk(dparts, user)
            except FileNotFoundError:
                target = None
            if isinstance(target, Dir):
                dparent, dname = target, sname
            else:
                dparent, dname = self._parent(dst, user)
            if dparent.children.get(dname) is node:
                return                                            # moving onto itself
            if isinstance(dparent.children.get(dname), Dir):
                raise IsADirectoryError(f"cannot overwrite directory {dst}")
            if isinstance(node, Dir):                             # no moving a directory into itself
                anc: Dir | None = dparent
                while anc is not None:
                    if anc is node:
                        raise OSError(f"cannot move {src} into its own subtree")
                    anc = anc.parent
            if not (sparent.can(user, W) and dparent.can(user, W)):
                raise PermissionError("need write permission on both directories")
            size = node.used if isinstance(node, Dir) else node.size
            replaced = dparent.children.get(dname)
            replaced_size = replaced.size if isinstance(replaced, File) else 0
            common = self._common_ancestor(sparent, dparent)
            self._check_quota(dparent, size - replaced_size, stop_at=common)
            del sparent.children[sname]
            self._add_usage(sparent, -size)
            if replaced is not None:
                self._add_usage(dparent, -replaced_size)
            node.name, node.parent = dname, dparent
            dparent.children[dname] = node
            self._add_usage(dparent, size)

    # ---------------------------------------------------------------- quotas
    def set_quota(self, path: str, max_bytes: int | None) -> None:
        with self._lock:
            node = self._walk(split(path), ROOT_USER)
            if not isinstance(node, Dir):
                raise NotADirectoryError(path)
            if max_bytes is not None and node.used > max_bytes:
                raise OSError(f"{path} already uses {node.used} bytes")
            node.quota = max_bytes

    def usage(self, path: str = "/") -> int:
        with self._lock:
            node = self._walk(split(path), ROOT_USER)
            return node.used if isinstance(node, Dir) else node.size

    def _check_quota(self, d: Dir | None, delta: int, stop_at: Dir | None = None) -> None:
        while d is not None and d is not stop_at and delta > 0:
            if d.quota is not None and d.used + delta > d.quota:
                raise OSError(f"quota exceeded at {self._path(d)}: {d.used} + {delta} > {d.quota}")
            d = d.parent

    @staticmethod
    def _add_usage(d: Dir | None, delta: int) -> None:
        while d is not None:                                      # O(depth) per write
            d.used += delta
            d = d.parent

    @staticmethod
    def _common_ancestor(a: Dir, b: Dir) -> Dir:
        seen = set()
        n: Dir | None = a
        while n is not None:
            seen.add(id(n))
            n = n.parent
        n = b
        while id(n) not in seen:
            n = n.parent
        return n

    @staticmethod
    def _path(node: Node) -> str:
        parts = []
        while node.parent is not None:
            parts.append(node.name)
            node = node.parent
        return "/" + "/".join(reversed(parts))

    # ---------------------------------------------------------------- find
    def find(self, path: str = "/", pattern: str = "*", user: str = ROOT_USER) -> list[str]:
        """Paths under `path` whose final component matches a glob pattern; unreadable dirs are skipped."""
        with self._lock:
            start = self._walk(split(path), user)
            out: list[str] = []
            stack = [(start, path.rstrip("/") or "/")]
            while stack:
                node, p = stack.pop()
                if node is not start and fnmatch.fnmatchcase(node.name, pattern):
                    out.append(p)
                if isinstance(node, Dir) and node.can(user, R) and node.can(user, X):
                    for name, child in node.children.items():
                        stack.append((child, (p if p != "/" else "") + "/" + name))
            return sorted(out)


# ---------------------------------------------------------------- tests
def raises(exc, fn, *a, **k) -> str:
    try:
        fn(*a, **k)
    except exc as e:
        return str(e)
    raise AssertionError(f"{fn.__name__}{a} did not raise {exc.__name__}")


def test_leetcode_style_session() -> None:
    fs = MemFS()
    assert fs.ls("/") == []
    fs.mkdir("/a/b/c", parents=True)
    fs.append("/a/b/c/d", "hello")
    assert fs.ls("/") == ["a"] and fs.ls("/a/b/c") == ["d"] and fs.ls("/a/b/c/d") == ["d"]
    assert fs.read("/a/b/c/d") == "hello"
    fs.append("/a/b/c/d", " world")
    assert fs.read("/a/b/c/d") == "hello world" and fs.usage("/a") == 11


def test_paths_are_normalised() -> None:
    fs = MemFS()
    fs.mkdir("//x///y/./z/../w", parents=True)
    assert fs.ls("/x/y") == ["w"]
    fs.write("/x/y/w/../f.txt", "1")
    assert fs.read("/x/./y//f.txt") == "1" and fs.ls("/../..") == ["x"]
    raises(ValueError, fs.ls, "relative/path")


def test_errors_use_standard_exceptions() -> None:
    fs = MemFS()
    fs.mkdir("/d")
    fs.write("/d/f", "x")
    raises(FileNotFoundError, fs.mkdir, "/p/q")                   # no -p
    raises(FileExistsError, fs.mkdir, "/d")
    raises(NotADirectoryError, fs.mkdir, "/d/f/g", parents=True)
    raises(NotADirectoryError, fs.write, "/d/f/g", "x")
    raises(IsADirectoryError, fs.read, "/d")
    raises(IsADirectoryError, fs.write, "/d", "x")
    raises(FileNotFoundError, fs.read, "/d/nope")
    assert "not empty" in raises(OSError, fs.rm, "/d")
    fs.mkdir("/d", parents=True)                                  # -p on an existing dir is fine


def test_mv_rename_move_into_and_guards() -> None:
    fs = MemFS()
    fs.mkdir("/src/sub", parents=True)
    fs.write("/src/sub/a.txt", "aaa")
    fs.mkdir("/dst")
    fs.mv("/src/sub/a.txt", "/src/sub/b.txt")                     # rename
    fs.mv("/src/sub", "/dst")                                     # move into existing dir
    assert fs.ls("/dst") == ["sub"] and fs.read("/dst/sub/b.txt") == "aaa" and fs.ls("/src") == []
    assert "own subtree" in raises(OSError, fs.mv, "/dst", "/dst/sub/inner")
    fs.write("/x", "1")
    fs.write("/y", "22")
    fs.mv("/x", "/y")                                             # overwrite a file
    assert fs.read("/y") == "1" and fs.usage("/") == 4            # 3 (b.txt) + 1
    fs.mkdir("/dst/sub/y")
    raises(IsADirectoryError, fs.mv, "/y", "/dst/sub")            # would overwrite the directory /dst/sub/y
    fs.mv("/y", "/dst/sub/b.txt/../z")                            # '..' resolves: lands at /dst/sub/z
    assert fs.ls("/dst/sub") == ["b.txt", "y", "z"]

def test_quotas_are_checked_on_every_ancestor() -> None:
    fs = MemFS()
    fs.mkdir("/home/alice/docs", parents=True)
    fs.mkdir("/home/bob", parents=True)
    fs.set_quota("/home", 20)
    fs.set_quota("/home/alice", 10)

def test_permissions() -> None:
    fs = MemFS()
    fs.mkdir("/home", mode=0o75)
    fs.mkdir("/home/alice", user=ROOT_USER, mode=0o70)
    fs.root.children["home"].children["alice"].owner = "alice"   # chown
    fs.write("/home/alice/secret", "s", user="alice", mode=0o60)
    assert fs.read("/home/alice/secret", user="alice") == "s"
    raises(PermissionError, fs.read, "/home/alice/secret", user="bob")     # cannot traverse alice's dir
    raises(PermissionError, fs.ls, "/home/alice", user="bob")
    raises(PermissionError, fs.write, "/home/new", "x", user="bob")        # /home is not writable by others
    fs.mkdir("/pub", mode=0o77)
    fs.write("/pub/readme", "hi", user="alice", mode=0o64)
    assert fs.read("/pub/readme", user="bob") == "hi"
    raises(PermissionError, fs.write, "/pub/readme", "defaced", user="bob")
    assert fs.find("/", "*", user="bob") == ["/home", "/home/alice", "/pub", "/pub/readme"]

def test_matches_flat_reference_model() -> None:
    rng = random.Random(9)
    names = ["a", "b", "c"]
    for trial in range(40):
        fs, dirs, files = MemFS(), {"/"}, {}

        def rp() -> str:
            return "/" + "/".join(rng.choice(names) for _ in range(rng.randint(1, 3)))

        def parent(p: str) -> str:
            return p.rsplit("/", 1)[0] or "/"
        for step in range(150):
            op, p = rng.choice(["mkdir", "write", "append", "rm", "mv", "read", "ls"]), rp()
            if op == "mkdir":
                ok = all(("/" + "/".join(p.split("/")[1:i + 1])) not in files for i in range(1, len(p.split("/"))))
                try:
                    fs.mkdir(p, parents=True)
                    assert ok
                    parts = p.split("/")[1:]
                    for i in range(1, len(parts) + 1):
                        dirs.add("/" + "/".join(parts[:i]))
                except NotADirectoryError:
                    assert not ok
            elif op in ("write", "append"):
                data = rng.choice(["x", "yy", ""])
                ok = parent(p) in dirs and p not in dirs
                try:
                    getattr(fs, op)(p, data)
                    assert ok, (op, p)
                    files[p] = (files.get(p, "") + data) if op == "append" else data
                except (FileNotFoundError, NotADirectoryError, IsADirectoryError):
                    assert not ok, (op, p)
            elif op == "rm":
                if p in files:
                    fs.rm(p); del files[p]
                elif p in dirs:
                    fs.rm(p, recursive=True)
                    dirs = {d for d in dirs if not (d == p or d.startswith(p + "/"))}
                    files = {f: v for f, v in files.items() if not f.startswith(p + "/")}
            elif op == "mv":
                q = rp()
                if p in files and parent(q) in dirs and q not in dirs and q != p:
                    fs.mv(p, q)
                    files[q] = files.pop(p)
            elif op == "read":
                if p in files:
                    assert fs.read(p) == files[p]
            else:
                if p in dirs:
                    expect = sorted({x[len(p) + 1:].split("/")[0] for x in dirs | set(files)
                                     if x.startswith(p + "/")})
                    assert fs.ls(p) == expect, (p, fs.ls(p), expect)
            assert fs.usage("/") == sum(len(v) for v in files.values())


def test_concurrent_appends() -> None:
    fs = MemFS()
    fs.mkdir("/logs")

    def worker(k: int) -> None:
        for i in range(500):
            fs.append("/logs/shared.log", "x")
            fs.write(f"/logs/w{k}-{i % 10}", str(i))
    ts = [threading.Thread(target=worker, args=(k,)) for k in range(8)]
    for t in ts: t.start()
    for t in ts: t.join()
    assert len(fs.read("/logs/shared.log")) == 4000 and len(fs.ls("/logs")) == 81
    assert fs.usage("/") == 4000 + sum(len(fs.read(f"/logs/{n}")) for n in fs.ls("/logs") if n != "shared.log")

12 · Edge cases

The root: cannot be removed, renamed or written to as a file; _parent("/") raises. Trailing slashes: normalised away, so /a/ is /a; the shell sometimes treats a trailing slash as "must be a directory", a stricter rule you could add. Lexical '..': /a/file/../b normalises to /a/b even though file is not a directory; POSIX resolution would fail at file. State which you implement. Names containing '/' cannot exist, since '/' is the separator; names like .hidden are ordinary. Empty writes create zero-byte files. Moving onto itself is a no-op. Unicode: sizes are UTF-8 bytes, so a one-character "é" counts 2 bytes against a quota. Deep trees: the explicit stack in find avoids recursion limits.

13 · Extensions the interviewer will ask for

Current directory and relative paths: keep a cwd per session and join before normalising. Hard links: separate names from file objects (inodes with link counts), and count bytes once per inode. Symbolic links: a node type holding a target path, followed during resolution with a hop limit. Metadata: created and modified times, stat. Groups: a third rwx digit for a group. Streaming I/O: open handles with offsets and seek, rather than whole-file read and write. Persistence: an operation log plus snapshots, or content-addressed storage. Finer-grained locking: per-directory locks acquired in a consistent order, with a global rename lock for cross-directory moves.

14 · Complexity

With d = path depth: resolution is O(d) dictionary lookups; mkdir, write, append, read and rm are O(d) plus the data copied (append builds a new string, O(size) — a list of chunks would make it amortised O(len(data))); usage updates and quota checks are O(d); mv is O(d) for the subtree and common-ancestor checks; ls is O(k log k) for k children; find is O(subtree size). Space is O(total nodes + total content). Removing a subtree is O(d), because detaching one node drops everything under it.

Inodes: why real file systems separate names from files

In Unix file systems a directory does not contain files; it maps names to inode numbers, and the inode holds the file's metadata and data blocks. This separation is what makes hard links possible (two names, one inode, a link count), makes rename within a file system cheap (change a directory entry, not the data), and explains permissions: deleting a name modifies the directory, so it needs write permission on the directory, not on the file. This solution keeps the name inside the node for simplicity; the first extension most interviewers ask for — hard links — is exactly the change that forces the inode split, and naming it shows you know where the simplification lies.

Lexical versus physical path resolution

Normalising .. by deleting the previous component is lexical: it looks only at the string. Physical resolution walks the tree and, at .., goes to the actual parent of the directory reached so far. Without symbolic links the two agree whenever every component is a directory. With symbolic links they differ: if /a/link points to /x/y, then /a/link/.. is /a lexically but /x physically. Python's os.path.normpath documents this risk, and shells offer both behaviours. In an interview, state that you normalise lexically because the file system has no links, and that adding symlinks would move .. handling into the resolver.

Derived data and the discipline of one writer

The used counters are derived data: they could always be recomputed from the files, and they are stored only for speed. Derived data stays correct only if every mutation path updates it, so the solution funnels every change through one function, and the reference-model test recomputes the truth after every random operation. The same discipline applies to search indexes, materialised views and caches in larger systems. When it fails — a new mutation path added later that forgets the update — the symptom is drift that nobody notices until a quota misfires, which is why the check belongs in the test suite permanently.

Locking a tree

One lock around the whole file system is simple and correct, and with operations that take microseconds it is often enough. Finer locking is tempting because reads dominate and different users touch different subtrees, but mv makes it hard: moving between two directories must lock both, and two concurrent moves in opposite directions can deadlock unless locks are always taken in a global order (for example, by path, ancestors first). Real kernels use per-inode locks for most operations and a file-system-wide rename lock for cross-directory renames, precisely to avoid that deadlock while keeping common operations parallel. Readers-writer locks help when listing and reading dominate.

Errors as part of the interface

Which exception an operation raises is part of its contract, as much as its return value. Callers write except FileNotFoundError to create a missing config, except FileExistsError to treat "already created" as success, except PermissionError to show a specific message. If the in-memory file system raised a generic error, every caller would have to parse messages. Matching Python's hierarchy also means code can be tested against the in-memory version and run against the real one unchanged. The same principle applies to any library: choose error types callers can act on, put the failing path or value in the message, and never let an internal error (a KeyError from a dict lookup) leak out as the public failure.

Copy-on-write trees and snapshots

If nodes are immutable and a change creates new nodes only along the path from the changed node to the root, every version of the file system is a root pointer, and old versions remain intact as long as something references them. Snapshots become free, and two versions can be compared by walking only the paths where node identities differ. Content-addressed variants store nodes by the hash of their contents, so identical files and directories are stored once — the design behind Git's trees and many backup systems. For the in-memory interview version, mentioning this as the route to snapshots and undo is enough; it changes mv and writes from in-place updates to path copying, at O(depth) extra allocation per change.

Where in-memory file systems are used

In-memory file systems are not just interview exercises. Test suites use them to exercise code that reads and writes files without touching disk (Python's pyfakefs and similar libraries patch the standard library to point at one). Operating systems provide RAM-backed file systems such as tmpfs for temporary data. Build tools and sandboxes build virtual file system layers to control what code can see. And in AI systems, agents with "file" tools often operate on a virtual, in-memory or database-backed file system that the host controls — with exactly this lesson's concerns: path normalisation (an agent writing ../../etc/passwd must not escape its sandbox), quotas (an agent must not fill memory), and permissions (which directories it may write).

How these systems fail

Path traversal. Symptom: content written outside the intended directory. Cause: joining user-supplied paths without normalising and checking the result stays under the allowed root. Fix: normalise, then verify the resolved path has the sandbox root as a prefix (by component, not string).

Quota drift. Symptom: quotas refuse writes in a nearly empty directory, or allow writes past the limit. Cause: a mutation path that forgot to update usage. Detection: periodic recomputation compared with the counters. Fix: a single update function and a test that checks the invariant.

Corrupted tree after mv. Symptom: a directory vanishes from listings but its memory is still used. Cause: a move into its own subtree created a cycle unreachable from the root. Fix: the ancestor check before every directory move.

Lock contention. Symptom: throughput flat as threads are added. Cause: one global lock. Fix: readers-writer locking or per-directory locks with ordered acquisition.

Memory blow-up on append-heavy workloads. Symptom: CPU and memory spike on log-like files. Cause: appending by building a new string copies the whole file each time — O(n²) over many appends. Fix: store content as a list of chunks or a bytearray.

Inconsistent error semantics. Symptom: code that works against the real disk fails against the in-memory version in tests, or the reverse. Cause: the fake raises different exception types or treats edge cases (trailing slashes, mv into a directory) differently. Fix: run the same test suite against both implementations.

What to measure

Operation counts and latency by type; lock wait time; total bytes and node count; per-quota usage against limits; refused operations by error type (permission, quota, not found); and, in sandboxes, attempted escapes.

The real references

The error types come straight from Python's built-in exception hierarchy, where FileNotFoundError, FileExistsError, IsADirectoryError, NotADirectoryError and PermissionError are subclasses of OSError raised by the real file system. The normalisation rules match os.path.normpath, whose documentation warns that lexical normalisation may change a path's meaning when symbolic links are involved. The mv guard against moving a directory into its own subtree follows the POSIX specification of rename(), which defines an error for that case. Glob matching uses the standard fnmatch module.

Trace it

Starting from an empty file system: mkdir("/a/b", parents=True); write("/a/b/f", "abc"); mkdir("/c"); mv("/a/b", "/c"); write("/c/b/g", "de"); mv("/c/b/f", "/a/f2"); rm("/c", recursive=True). After each step, give ls("/") and usage of /, /a and /c (where /c exists).

Answer

After mkdir: ls / = [a]; usage / = 0, /a = 0. After write: / = 3, /a = 3. After mkdir /c: ls / = [a, c]; /c = 0. After mv /a/b → /c (existing dir, so into it as /c/b): /a = 0, /c = 3, / = 3 (the common ancestor is the root, so its count does not change). After write /c/b/g: /c = 5, / = 5. After mv /c/b/f → /a/f2: /a = 3, /c = 2, / = 5. After rm -r /c: ls / = [a]; / = 3, /a = 3.

Secure it

An AI agent gets a file tool backed by this file system, rooted at /workspace. It may read and write only under /workspace, at most 50 MB in total, and must not overwrite files in /workspace/inputs. What do you change or configure?

Answer

Resolve every agent-supplied path against /workspace and normalise it, then check the resulting component list starts with the workspace's components — comparing components, not strings, so /workspace-evil is rejected and /workspace/../etc normalises outside and is rejected. Set a 50 MB quota on /workspace. Run the agent's operations as a dedicated user that owns /workspace but not /workspace/inputs, whose files are owned by root with mode 0o64 (others read-only) and whose directory is 0o75 (others cannot create or delete entries). Return errors to the agent as tool errors with the exception message, so it can adjust, and log every refused operation.
