Model cards read like this: "32 layers, hidden size 4,096, 32 attention heads, intermediate size 11,008, vocabulary 32,000, RMSNorm, SwiGLU, RoPE". An engineer who cannot turn that into a picture of the computation is stuck taking every downstream number on trust. How much GPU memory will the weights need? How many floating-point operations per generated token? Which parts would you quantise, shard across GPUs or replace with experts? Why did the team's fine-tune diverge after they changed one normalisation layer? All of these are questions about what is inside a single transformer block and how blocks are stacked.

The previous lesson (lm2) explained self-attention, the operation that lets tokens exchange information. But attention is only about a third of each layer's weights. Around it sit the pieces that make a deep stack trainable and give it most of its capacity: residual connections, normalisation, the feed-forward (MLP) sub-layer, the embedding at the bottom and the LM head at the top. These pieces look like plumbing, and they are the subject of a surprising number of interview questions precisely because they decide parameter counts, memory, compute, stability and where knowledge is stored.

There is also a practical career reason. When something goes wrong with a model in production, whether a port to a new inference engine produces subtly worse text, a fine-tune diverges, or a memory estimate is off by a factor of two, the debugging happens at this level: comparing the residual stream layer by layer against a reference, checking a normalisation's epsilon, recounting the parameters of a modified architecture. Knowing the block well enough to draw it from memory is what turns those incidents from mysteries into checklists.

This lesson follows one token from its ID to a probability distribution over the next token. It introduces the residual stream as the organising idea, builds a block piece by piece (normalisation, attention, MLP), explains why modern models settled on pre-norm, RMSNorm and SwiGLU, counts the parameters of GPT-2 small and Llama 2 7B by hand to the exact published totals, and converts parameters into memory and FLOPs. The lab builds a two-block model from scratch in NumPy and the same parameter calculator.

A stack of identical blocks

A decoder-only language model has three parts. At the bottom, the embedding turns each token ID into a vector of length d_model (lm1). In the middle, L identical blocks (also called layers; 12 in GPT-2 small, 32 in Llama 2 7B, 80 in Llama 2 70B) each refine every position's vector using context. At the top, a final normalisation and the LM head, a linear layer, turn each position's vector into one score (logit) per vocabulary entry; a softmax over the scores gives the probability of each possible next token.

Each block does two things, in order. Attention lets each position read from earlier positions: this is where "it" picks up information from "the animal". The MLP (multi-layer perceptron, also called the feed-forward network) then processes each position's vector on its own: it expands the vector to a wider hidden size, applies a nonlinearity and projects it back. A useful slogan: attention moves information between tokens; the MLP thinks about each token individually. Each of the two is wrapped in a normalisation layer and a residual connection.

The residual stream: a shared whiteboard

The organising idea is the residual stream. Picture each token position as having a whiteboard. It starts with the token's embedding written on it. Each sub-layer in turn reads the whiteboard (through a normalisation that rescales what it sees), computes something, and adds its result to the board; it never erases. After 32 blocks, the board holds the embedding plus 64 contributions, and the LM head reads the final board to make a prediction. In code it is two lines per block:

x = x + attention(norm1(x))     # read the stream, add what other positions contribute
x = x + mlp(norm2(x))           # read the stream, add per-position processing

The analogy holds well: information written early stays readable later, and later layers can refine or cancel it by adding a correction. It breaks in one respect: the "board" has only d_model numbers, so contributions share space, and a lot of interpretability research is about how many features models pack into that space.

Why stack identical blocks at all?

Why not one enormous layer? Because each block can only do a limited amount of work: one round of information exchange between positions, then one round of per-position processing. Many linguistic and reasoning steps need several rounds. To resolve "it" in a long sentence, a model may first need to work out which words form noun phrases (one round), then which noun phrase is the subject (another), then match the pronoun to it (a third). Stacking blocks gives the model as many rounds as it has layers, and because every block has the same shape, depth is a simple dial: GPT-2 came in versions with 12, 24, 36 and 48 blocks of the same design. Each block has its own weights, so different depths learn different jobs, and interpretability studies find early blocks handling local, surface patterns and later blocks more abstract ones.

Numbers to hold on to

Llama 2 7B: d_model = 4,096, 32 blocks, 32 heads, MLP hidden width 11,008, vocabulary 32,000, for 6.74 billion parameters, 13.5 GB in 16-bit precision, about 13.5 billion floating-point operations per token in a forward pass. About two thirds of each block's weights are in the MLP. The rest of the lesson shows where each of those numbers comes from.

1. From IDs to the residual stream

The input is a sequence of n token IDs. The embedding table, a matrix of shape vocabulary × d_model, turns each ID into its row: for Llama 2 7B, a 32,000 × 4,096 matrix, and each token becomes a vector of 4,096 numbers. The result is the n × d_model matrix X, one row per position. Attention by itself cannot tell positions apart (lm2 showed it treats its input as a set), so position information must be added. GPT-2 does it here, by adding a second learned table indexed by position (1,024 rows of 768). Llama instead rotates queries and keys inside every attention layer (rotary embeddings). lm4 is devoted to the options; for this lesson it is enough that each block's attention knows token order.

That matrix X is the initial residual stream. From here on, every position's row will be added to, block by block, and its shape never changes: n × d_model from the first block to the last. This constant shape is what lets you stack as many blocks as you like.

2. Normalisation: keeping the numbers in range

Before each sub-layer reads the stream, it normalises it. The reason is scale. The stream is a sum of many contributions, and its magnitude varies across positions and grows with depth; a matrix multiplication applied to vectors of wildly different sizes produces outputs of wildly different sizes, which makes training unstable. Normalisation rescales each position's vector to a standard size before the sub-layer sees it (dl4 covers normalisation in general).

LayerNorm, used in the original transformer and GPT-2, subtracts the vector's mean, divides by its standard deviation, then multiplies by a learned per-feature scale γ and adds a learned shift β. RMSNorm, used by Llama and most recent models, skips the mean and the shift: it divides by the root mean square and multiplies by γ. Worked by hand for x = [1, −2, 3, 0]: the mean of squares is (1 + 4 + 9 + 0)/4 = 3.5, the RMS is √3.5 = 1.871, so RMSNorm(x) = [0.535, −1.069, 1.604, 0] (with γ = 1). LayerNorm first subtracts the mean 0.5, giving [0.5, −2.5, 2.5, −0.5], whose standard deviation is 1.803, so LayerNorm(x) = [0.277, −1.387, 1.387, −0.277]. RMSNorm is cheaper (one reduction instead of two, no shift) and was found to work as well, which at billions of tokens per day is reason enough.

3. The attention sub-layer

The first sub-layer is causal multi-head self-attention from lm2: project the normalised stream to queries, keys and values, compute softmax(QKᵀ/√d_k) with the causal mask per head, take the weighted sum of values, concatenate heads and project with W_O. Its output, n × d_model, is added to the stream. This is the only place in the block where position i's vector is influenced by position j's. Its weights are four d_model × d_model matrices: 4 × 4,096² = 67.1 million for Llama 2 7B. (Models that share keys and values across heads, covered in lm5, have smaller W_K and W_V.)

4. The MLP sub-layer

The second sub-layer is applied to each position independently, with the same weights at every position. The classic version is two linear layers with a nonlinearity between: expand from d_model to a hidden width d_ff (usually 4·d_model), apply an activation such as ReLU or GELU, project back to d_model:

MLP(x) = GELU(x W₁ + b₁) W₂ + b₂          W₁: d × 4d,  W₂: 4d × d   → 8·d² weights

Why expand and contract? The expansion gives the layer many hidden units, each of which can respond to a particular pattern in its input; the nonlinearity lets it represent functions that a single matrix cannot; the contraction writes the combined result back in the stream's size. Interpretability work (Geva et al.) found that a useful way to read it is as a large key-value memory: each column of W₁ is a key that fires on some input pattern, and the matching row of W₂ is a value written into the stream when it fires, often one that promotes the tokens that tend to follow that pattern.

Modern LLMs use a gated variant, SwiGLU (Shazeer, 2020). It computes two projections of the input, applies the SiLU activation (x·sigmoid(x), a smooth ReLU) to one, multiplies them element by element so one acts as a learned gate on the other, and projects back:

SwiGLU(x) = ( SiLU(x W₁) ⊙ (x W₃) ) W₂     W₁, W₃: d × d_ff,  W₂: d_ff × d   → 3·d·d_ff weights

With three matrices instead of two, keeping the same parameter count as a 4·d MLP requires d_ff = (2/3)·4·d = 8d/3. For d = 4,096 that is 10,923, which Llama rounds up to a multiple of 256: 11,008. That odd-looking number in every Llama 2 7B config comes straight from this rule. Shazeer found the gated variants reached lower perplexity than ReLU and GELU MLPs at the same parameters and compute; nobody has a complete theory of why, and the paper itself says so.

5. Residual connections and pre-norm

The two sub-layers are joined by residual connections: each adds its output to its input rather than replacing it. Residuals were introduced for very deep image networks (dl3) and matter for the same reason here. The derivative of x + f(x) with respect to x is 1 + f′(x), so during backpropagation every layer receives the gradient from the loss through a path that multiplies by exactly 1, no matter how many layers sit above. Without them, a 32- or 80-block stack would suffer vanishing or exploding gradients.

Where the normalisation goes relative to the residual matters. The original transformer used post-norm: x ← LayerNorm(x + f(x)). The residual path then passes through a normalisation at every layer, so the identity path is broken, and Xiong et al. (2020) showed that at initialisation the gradients near the output are large, which is why post-norm transformers need a learning-rate warm-up (a gradual ramp of the learning rate over the first thousands of steps) or they diverge. GPT-2 switched to pre-norm, x ← x + f(LayerNorm(x)), which normalises only what each sub-layer reads; the stream itself is a pure sum. Pre-norm needs one extra normalisation at the very top, before the LM head, because the raw stream is never normalised otherwise; GPT-2 added exactly that. Xiong et al. showed pre-norm transformers can train without warm-up, and almost every large model since is pre-norm.

6. The top: final norm, LM head, loss

After L blocks, the stream is normalised one last time and multiplied by the LM head, a d_model × vocabulary matrix, giving n × vocabulary logits: a score for every possible next token at every position. Some models tie the LM head to the embedding table (use its transpose), so the same vector represents a token going in and coming out; GPT-2 does, Llama does not.

In training, the causal mask means position t's logits depend only on tokens 1 … t, so they are a legitimate prediction of token t + 1. The loss is the cross-entropy at every position, −log p(correct next token), averaged over the n − 1 positions that have a next token. One forward pass therefore yields n − 1 training signals in parallel. At generation, only the last position's logits are needed; they are turned into a choice of next token by the decoding rules of lm8, the token is appended, and the process repeats.

7. A SwiGLU unit by hand

To see the gate at work, take one hidden unit with a 2-dimensional input x = [1, 2]. Suppose its column of W₁ is [0.5, 0.5] and its column of W₃ is [1, −1]. The gate pre-activation is x·[0.5, 0.5] = 1.5, and SiLU(1.5) = 1.5 × sigmoid(1.5) = 1.5 × 0.818 = 1.227. The other projection is x·[1, −1] = −1. The unit's value is their product, 1.227 × (−1) = −1.227, and it is written back to the stream through this unit's row of W₂. Now flip the input to x = [−1, −2]: the gate pre-activation is −1.5 and SiLU(−1.5) = −1.5 × 0.182 = −0.273, nearly closed, so even though the other projection is now +1 the unit outputs only −0.273. The gate decides whether this unit speaks; the other projection decides what it says. With 11,008 such units per layer, the MLP can switch on combinations of features that suit each input.

8. One token's trip, step by step

Put together, here is what happens to the token " sat" at position 3 of "the cat sat" in a Llama-style model. Its ID selects its row of the embedding table: a 4,096-number vector, the stream's starting value. Block 1: RMSNorm rescales a copy; attention projects it to a query, compares with the keys of " the", " cat" and itself (rotated for position), and adds a weighted mix of their values to the stream; RMSNorm rescales a copy again; the SwiGLU MLP expands it to 11,008 hidden units, gates them, projects back and adds the result. Blocks 2 to 32 repeat this with their own weights, each adding contributions. The final RMSNorm rescales the stream, and the LM head turns it into 32,000 logits; the softmax gives, say, a high probability to " on" and " down". During training the loss compares this distribution with the true next token; during generation one token is chosen and fed back in.

11. From parameters to memory and FLOPs

Two conversions every interviewer expects (gpu3 derives them in detail). Memory: weights take parameters × bytes per parameter. In bf16 (2 bytes) Llama 2 7B is 6.74 × 10⁹ × 2 = 13.5 GB; in 8-bit, 6.7 GB; in 4-bit, about 3.4 GB plus a little for scaling factors (lm12). Compute: in a forward pass every weight takes part in one multiply-add per token, which is two floating-point operations (FLOPs), so a forward pass costs about 2N FLOPs per token: 13.5 GFLOP for Llama 2 7B. Attention adds a term that is not in the parameter count: computing scores and the weighted sum costs about 4·n·d FLOPs per layer per token for a context of n tokens, 2.1 GFLOP per token across 32 layers at n = 4,096 (about 15% extra) and more than the weights' term beyond about 24K tokens. Training costs roughly three times the forward pass (the backward pass computes gradients with respect to both activations and weights), so about 6N FLOPs per token, the rule lm7 uses for scaling-law budgets.

12. Encoder-only, decoder-only, encoder–decoder

The same block appears in three arrangements. Encoder-only models such as BERT use attention without the causal mask, so every token sees the whole input; they are trained to fill in masked-out tokens and are used to produce representations for classification and retrieval (lm10 uses such embeddings). Encoder–decoder models such as the original transformer and T5 have an encoder stack for the input and a decoder stack that generates the output with causal self-attention plus cross-attention to the encoder. Decoder-only models, GPT and Llama, use one causal stack for everything: the prompt is just the start of the sequence. Decoder-only won for general LLMs largely because one simple objective (predict the next token of any text) scales to any data, and because the same model can then handle any task phrased as text.

The residual stream as a communication channel

Mechanistic interpretability treats the residual stream as the model's shared memory bus. Because every sub-layer reads from it with a linear map (after normalisation) and writes to it with a linear map, two sub-layers communicate whenever one writes in a direction the other reads. Different features occupy different directions, and since there are far more useful features than d_model dimensions, models pack many nearly-orthogonal features into the same space ("superposition"). This view explains why attention heads in later layers can depend on heads in earlier layers (the induction-head circuit from lm2 is exactly a previous-token head writing a feature that a later head reads), and why you can sometimes steer a model by adding a vector to the stream.

Why the residual stream grows, and what pre-norm does about it

Each sub-layer reads a normalised copy and adds an output of roughly constant scale, so the stream's norm tends to grow with depth, as the lab's tiny model shows (from 3.4 after block 1 to 4.4 after block 2 with random weights). Late sub-layers therefore change the stream by a smaller fraction, and studies find middle and late layers of large models are more redundant than early ones: some can be removed with modest damage. GPT-2 counters this at initialisation by scaling the output projections of residual layers by 1/√N, where N is the number of residual layers, so the sum of N contributions starts with a variance that does not grow with depth. Other schemes add learned per-layer scales or extra normalisations on sub-layer outputs.

Gated MLPs as multiplicative interactions

A standard MLP computes act(xW₁)W₂: each hidden unit's output is a fixed nonlinear function of a single linear feature. A gated MLP computes act(xW₁) ⊙ (xW₃): each hidden unit is the product of two features of the input, so it can express "A and B" style interactions (fire strongly only if both features are present) directly. That is a plausible reason for its consistent small advantage. The cost is a third weight matrix, absorbed by shrinking the hidden width to 8d/3, and slightly more memory traffic per token, which matters at inference when the MLP weights dominate the bytes read (gpu10).

Why no biases and why RMSNorm

Removing biases saves parameters and memory traffic, and makes every linear layer a pure matrix multiplication, which simplifies sharding across GPUs (tensor parallelism splits weight matrices across devices, dl9) and some quantisation schemes. RMSNorm's justification is empirical and practical: Zhang and Sennrich found that re-centring (subtracting the mean) contributed little, and dropping it removes one reduction over the vector per normalisation. At inference these small savings matter because normalisations are memory-bound element-wise operations that are fused into neighbouring kernels when possible (gpu6).

Parallel blocks and other variants

Some models compute attention and the MLP from the same normalised input and add both to the stream at once: x ← x + Attn(norm(x)) + MLP(norm(x)). This "parallel" formulation (used in GPT-J and PaLM) lets the two sub-layers' matrix multiplications be fused and run together, which PaLM's authors reported as roughly 15% faster training at large scale with small quality cost at small scale. Other common variations: QK-norm inside attention for stability (lm2), sliding-window attention in some layers, and mixture-of-experts MLPs (lm17). All keep the residual-stream skeleton.

Reading the stream mid-way: the logit lens

Because the LM head is a linear map applied to the (normalised) stream, you can apply it to the stream after any block, not just the last, and ask what the model "would predict" at that depth. This technique, known as the logit lens, shows predictions forming gradually: early layers often predict generic or copied tokens, middle layers converge on the right answer for easy cases, and late layers sharpen the distribution. It works because pre-norm models keep the stream in a roughly consistent basis from bottom to top; refined versions train a small linear translator per layer (the "tuned lens") to correct for drift. It is a cheap, practical tool when investigating where in the stack a fact is retrieved or a mistake is introduced, and it rests entirely on the residual-stream structure explained in this lesson.

Activation memory and the shape of training cost

During training each block must keep its intermediate activations for the backward pass: the normalised inputs, the queries, keys and values, the attention outputs, the MLP's wide hidden activations (n × d_ff per sequence, the largest), and the softmax statistics. Per token per layer this is a few tens of times d_model numbers, so for long sequences and large batches activation memory can exceed weight memory. That is why activation checkpointing (recomputing activations in the backward pass instead of storing them, gpu9) is standard, and why the MLP's width, which sets its hidden activation size, matters for training memory as well as parameters.

Depth versus width

For a fixed parameter budget you can have more, narrower blocks or fewer, wider ones. Width makes each matrix multiplication bigger, which uses GPUs more efficiently and parallelises well across devices; depth composes more sequential steps of computation, which helps tasks that need multi-step reasoning, but adds latency because blocks run one after another. Large models settle on aspect ratios d_model / L of roughly 50 to 200 (Llama 2 7B: 4,096 / 32 = 128). Kaplan et al.'s scaling study found loss depends mostly on total non-embedding parameters and only weakly on shape within a broad range, so shape is usually chosen for hardware efficiency.

The public case: GPT-2's block and the move to pre-norm

The GPT-2 paper (Radford et al., 2019) describes its architecture in one paragraph of section 2.3, and almost every change it lists is now standard. Layer normalisation "was moved to the input of each sub-block, similar to a pre-activation residual network"; "an additional layer normalization was added after the final self-attention block"; and "a modified initialization which accounts for the accumulation on the residual path with model depth is used", scaling residual-layer weights at initialisation by 1/√N. The same paragraph raises the vocabulary to 50,257 and the context from 512 to 1,024 tokens. The paper trained four sizes, with 12, 24, 36 and 48 layers at widths 768 to 1,600; the largest, 1.5 billion parameters, still underfit its training data.

Xiong et al. (2020) later explained why the pre-norm move mattered: with post-norm, the expected gradients of the parameters near the output are large at initialisation, so a large learning rate makes training unstable unless it is warmed up; with pre-norm the gradients are well-behaved, and their experiments trained pre-norm transformers without warm-up in less time. LLaMA (Touvron et al., 2023) then fixed the recipe most open models follow: pre-normalisation with RMSNorm, SwiGLU MLPs at width (2/3)·4d, rotary position embeddings, no biases. The lab's parameter counter reproduces the 124,439,808 parameters of GPT-2 small and the 6,738,415,616 of Llama 2 7B from these descriptions.

Failure modes in practice

Loss spikes and divergence. Large-model training runs show sudden loss spikes, often traced to growing activations in the residual stream or attention logits. Symptoms: gradient-norm spikes before the loss jumps. Remedies: lower learning rate, gradient clipping, QK-norm, restarting from a checkpoint and skipping the offending batches.

Mismatched architecture details at load time. Loading weights into an implementation with a different normalisation epsilon, a different SwiGLU ordering (which of W₁ and W₃ is gated) or a different rotary convention gives a model that runs but produces degraded text. Always validate a ported model by comparing logits on a fixed input with the reference implementation to a tight tolerance.

Memory estimates that forget something. Weights are only the start: inference also needs the KV cache (lm5) and activations, training needs gradients, optimiser states and activations (gpu9). A 7B model whose weights are 13.5 GB needs on the order of 16 bytes per parameter for mixed-precision Adam training, over 100 GB, before activations.

Silent quality loss from the wrong MLP width. Architecture variants built by hand sometimes use 4·d for a SwiGLU MLP instead of 8d/3, giving a model 50% larger in its MLPs than intended; it trains, but compute and memory budgets are off and comparisons with published baselines are no longer fair. Recount parameters from the code, not from the plan, before launching a run.

Precision in norms and softmax. Normalisations and softmaxes computed in 16-bit lose precision; implementations upcast to float32 inside these operations. A custom kernel that does not is a common source of slowly degrading quality.

What to monitor

In training: loss, gradient norm, the norm of the residual stream per layer and the largest activation values, which warn of instabilities early. In serving: whether the fused kernels (attention, normalisation plus matrix multiplication) are actually in use, and the weight bytes read per generated token, which sets the floor on decode latency (gpu10).

import numpy as np

# ---- 1. parameter counts from a config, layer by layer
def count(name, d, L, vocab, d_ff, n_heads, n_kv=None, gated=True, bias=False, tied=False, pos=0, norm_params=1):
    n_kv = n_kv or n_heads; hd = d // n_heads
    attn = d * d * 2 + d * (n_kv * hd) * 2 + (4 * d if bias else 0)            # W_Q, W_O full; W_K, W_V may be smaller (lm5)
    mlp = (3 if gated else 2) * d * d_ff + ((d_ff + d) if bias else 0)
    norms = 2 * norm_params * d                                                   # two norms per block (LayerNorm has scale+shift)
    emb = vocab * d * (1 if tied else 2) + pos * d
    total = L * (attn + mlp + norms) + emb + norm_params * d
    print(f"{name:13s} attn/layer {attn/1e6:7.2f}M  mlp/layer {mlp/1e6:7.2f}M  layers {L*(attn+mlp+norms)/1e9:6.3f}B"
          f"  embeddings {emb/1e9:6.3f}B  total {total:,}  (MLP share of layers {mlp/(attn+mlp):.0%})")
    return total

def rmsnorm(x, g): return g * x / np.sqrt((x ** 2).mean(-1, keepdims=True) + 1e-6)
def softmax(z): z = z - z.max(-1, keepdims=True); e = np.exp(z); return e / e.sum(-1, keepdims=True)
silu = lambda z: z / (1 + np.exp(-z))
P = {"emb": rng.normal(0, 0.02, (V, d)), "out": rng.normal(0, 0.02, (d, V)), "gf": np.ones(d)}
for l in range(L):
    for k, shape in [("q", (d, d)), ("k", (d, d)), ("v", (d, d)), ("o", (d, d)), ("w1", (d, dff)), ("w3", (d, dff)), ("w2", (dff, d))]:
        P[f"{k}{l}"] = rng.normal(0, d ** -0.5 if k != "w2" else dff ** -0.5, shape)
    P[f"g1{l}"], P[f"g2{l}"] = np.ones(d), np.ones(d)
def forward(ids, trace=False):
    x = P["emb"][ids]                                                     # (n, d): the residual stream
    for l in range(L):
        a = rmsnorm(x, P[f"g1{l}"])
        q, k, v = (a @ P[f"{w}{l}"] for w in "qkv")
        sp = lambda t: t.reshape(len(ids), h, d // h).transpose(1, 0, 2)
        s = sp(q) @ sp(k).transpose(0, 2, 1) / np.sqrt(d // h)
        s = np.where(np.triu(np.ones((len(ids),) * 2, bool), 1), -np.inf, s)
        att = (softmax(s) @ sp(v)).transpose(1, 0, 2).reshape(len(ids), d) @ P[f"o{l}"]
        x = x + att                                                       # write attention's result into the stream
        m = rmsnorm(x, P[f"g2{l}"])
        mlp = (silu(m @ P[f"w1{l}"]) * (m @ P[f"w3{l}"])) @ P[f"w2{l}"]   # SwiGLU, per position
        x = x + mlp
        if trace: print(f"  block {l}: |attn out| {np.linalg.norm(att, axis=1).mean():.3f}  |mlp out| {np.linalg.norm(mlp, axis=1).mean():.3f}  |stream| {np.linalg.norm(x, axis=1).mean():.3f}")
    return rmsnorm(x, P["gf"]) @ P["out"]                                 # logits (n, V)
ids = rng.integers(0, V, n)
print(f"\ntiny model: {sum(p.size for p in P.values()):,} parameters"); logits = forward(ids, trace=True)
p = softmax(logits[-1])
print("logits shape", logits.shape, " next-token distribution sums to", round(p.sum(), 6), " top token", p.argmax())
ids2 = ids.copy(); ids2[-1] = (ids2[-1] + 1) % V
print("changing the last token leaves earlier logits unchanged:", np.allclose(forward(ids2)[:-1], logits[:-1]))
nll = -np.log(softmax(logits[:-1])[np.arange(n - 1), ids[1:]]).mean()
print(f"untrained loss {nll:.3f} vs uniform ln(V) = {np.log(V):.3f}")

What to look for.

  1. Section 1 prints exactly 124,439,808 for GPT-2 small, 6,738,415,616 for Llama 2 7B and 8,030,261,248 for Llama 3 8B, with the MLP share of each block (67%, 67%, 81%), 13.5 GB and 16.1 GB of bf16 weights, and about 13.5 GFLOP per token for the 7B forward pass.
  2. Section 2 reproduces the hand calculation: RMS 1.8708, RMSNorm [0.5345, −1.069, 1.6036, 0]; LayerNorm [0.2774, −1.3868, 1.3868, −0.2774].
  3. Section 3 traces the tiny model: each sub-layer's output norm and the stream's norm, which grows block by block because sub-layers add. The next-token distribution sums to 1, changing the last token leaves earlier logits unchanged (the causal mask works through the whole stack), and the untrained loss (3.93) is close to ln 50 = 3.91, the loss of a uniform guess.

Work it out — size a model from its config

A config says: d_model 5,120, 40 layers, 40 heads, MLP width 13,824 (SwiGLU), vocabulary 32,000, untied embeddings, no biases. Estimate the parameters, the bf16 weight memory and the forward FLOPs per token at short context.

Answer

Attention per layer: 4 × 5,120² = 104.9M. MLP: 3 × 5,120 × 13,824 = 212.3M. Norms: 10,240. Per layer ≈ 317.2M; × 40 = 12.69B. Embeddings: 2 × 32,000 × 5,120 = 0.33B. Total ≈ 13.0B; this is the Llama 2 13B shape. Check: 13,824 ≈ 8 × 5,120 / 3 = 13,653 rounded up to a multiple of 256.

Memory: 13.0B × 2 bytes ≈ 26 GB of weights in bf16, so it does not fit a 24 GB GPU unquantised, and an 80 GB GPU has room for weights plus KV cache.

FLOPs: about 2 × 13.0B ≈ 26 GFLOP per token in a forward pass at short context, plus about 4 × n × 5,120 × 40 for attention at context n (about 3.4 GFLOP at n = 4,096).

Diagnose — the ported model that rambles

You port a Llama-style checkpoint into your own inference code. It runs without errors and produces fluent-ish but noticeably worse text than the reference. Where do you look?

Answer

Compare logits with the reference on one fixed input, layer by layer: feed the same tokens to both, and compare the residual stream after the embedding, after each block, and the final logits, to find the first point of divergence. Usual culprits: RMSNorm epsilon or computing the norm in 16-bit instead of float32; swapped W₁/W₃ in SwiGLU (which matrix is gated); a different rotary-embedding convention (interleaved versus split halves, lm4); a wrong causal mask; or a chat template or tokeniser mismatch (lm1) before the model is even reached. A model that is wrong but still fluent usually has a small numerical or convention mismatch rather than a crash-level bug, which is why layer-by-layer comparison beats reading the code.
