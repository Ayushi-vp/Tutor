Take two sentences: "the dog bit the man" and "the man bit the dog". Same five words, very different news. Now recall how self-attention works (lm2): each token's new vector is a weighted average of other tokens' values, with weights from query–key similarity. Nothing in that computation looks at where a token is. If you shuffle the words, every token gets exactly the same attention weights over the same set of other tokens, and the outputs are simply shuffled along with them. To a transformer with no positional information, both sentences are the same bag of words.

So position has to be put in deliberately, and how it is put in turns out to matter far more than it first appears. It decides whether a model can run at all on text longer than it was trained on. It decides how expensive it is to grow a model's context window from 4,000 tokens to 128,000, which is one of the main things LLM vendors have competed on since 2023. And it explains a family of strange behaviours: models that read long documents fluently but miss facts in the middle, models whose quality falls off a cliff at exactly their training length, and models whose output degrades subtly after someone changes a "rope_theta" setting in a config file.

It also matters in day-to-day engineering. When you choose a model for a long-document feature, the advertised context window tells you what the model accepts, not how well it uses what it accepts; understanding how the window was obtained (trained natively, or extended with interpolation from something shorter) tells you what to test before you trust it.

This lesson starts from why attention is order-blind, then walks through the four schemes you will be asked about. Sinusoidal and learned embeddings label each position with a vector. RoPE, the scheme used by Llama and most open models, rotates queries and keys so attention depends on relative distance; you will rotate one by hand. ALiBi subtracts a penalty proportional to distance. The last part covers context extension: why RoPE models fail past their training length, and how position interpolation, NTK-aware scaling, YaRN and base changes stretch them, with Meta's position-interpolation paper as the real-world case.

The problem in one sentence

Attention scores come from dot products of content vectors, so they are the same whatever order the tokens arrive in. Positional information is any trick that makes a token's position affect the computation. There are two broad families. Absolute schemes give each position its own signature, "this is token number 17", and let the model work out relationships. Relative schemes make attention depend directly on the distance between two tokens, "this key is 3 tokens before this query", which is closer to how language works: the link between a verb and its subject does not care whether the sentence begins at token 5 or token 5,000.

An analogy: clocks with many hands

Picture labelling each position in a sequence with the reading of a clock that has many hands, each spinning at a different speed. A seconds hand changes noticeably from one position to the next, so it distinguishes neighbours; an hour hand barely moves between neighbours but separates positions that are hundreds apart. The original sinusoidal encoding writes down the angles of all the hands as a position label. RoPE goes one step further: it physically turns each query and key by its clock's angles, so that when a query compares itself with a key, what matters is the difference between their clock readings, the distance between them. The analogy breaks in an instructive place: a clock's hands come back round, so two positions exactly one revolution apart look identical on that hand. Using many hands at different speeds is what keeps positions distinguishable, and what happens when you go beyond the slowest hand's trained range is the whole problem of context extension.

Two places to put position

There are two natural places to inject position, and the four schemes split between them. The first is the input: add a position vector to each token's embedding before the first block, so the residual stream itself carries "I am token 17" and every layer can read it. The original transformer and GPT-2 do this. The second is inside attention, the only place where tokens interact: leave the residual stream alone and make the attention score between two tokens depend on their positions. RoPE (by rotating queries and keys) and ALiBi (by adding a penalty to the scores) do this. Putting position inside attention has a structural advantage: the score between a query and a key can be made to depend directly on their distance, in every layer, without the position signal being diluted as the stream accumulates other information.

What "extrapolation" means and why it matters

A model is trained on sequences up to some maximum length, its training context: 1,024 tokens for GPT-2, 2,048 for the first LLaMA, 4,096 for Llama 2. Running it on longer inputs is called extrapolation. With some schemes the model cannot even run (there is no learned vector for position 1,025); with others it runs but quality collapses; with others it degrades gently. Because training on long sequences is expensive (attention cost grows with the square of length), the industry's path to long-context models has been to pretrain mostly at moderate length and then extend, which is why the second half of this lesson is about extension methods.

Hold on to one picture: RoPE is a rotation of 2-D pieces of each query and key, with angle proportional to position. Everything about its behaviour, good and bad, follows from that.

1. Attention is order-blind: a quick proof

Write a token's attention output as o_i = Σ_j softmax_j(q_i · k_j) v_j, where q_i, k_j and v_j are computed from the tokens' content. If you swap tokens 2 and 5, their queries, keys and values swap too; token 2's output becomes what token 5's was, and vice versa, and nothing else changes. Formally, attention without a mask is permutation equivariant: permute the input, and the output is permuted the same way. The lab for lm2 checked this numerically. In a decoder the causal mask adds a faint signal, since position t can see exactly t tokens, but it still cannot tell which of the earlier tokens came first. So a position scheme must make the score q_i · k_j, or the vectors feeding it, depend on i and j.

2. Sinusoidal encoding

The original transformer added a fixed vector PE(pos) to each token's embedding at the bottom of the model. Dimension pairs (2i, 2i + 1) of that vector hold a sine and cosine of the position at frequency 1 / 10,000^(2i/d):

PE(pos, 2i)     = sin( pos / 10000^(2i/d) )
PE(pos, 2i + 1) = cos( pos / 10000^(2i/d) )

For d = 16, position 1 starts [sin 1, cos 1, sin 0.316, cos 0.316, sin 0.1, cos 0.1, …] = [0.841, 0.540, 0.311, 0.950, 0.100, 0.995, …]. The first pair turns by 1 radian per position (a full turn every 6.3 positions), and each later pair more slowly, down to one turn every ~60,000 positions for the last pair at the original d = 512. Two properties made it attractive. It needs no parameters and can be computed for any position. And for any fixed offset k, PE(pos + k) is a rotation of PE(pos), so the dot product of two position vectors depends only on their distance: in the lab, PE(10)·PE(13) and PE(40)·PE(43) are both 5.543. The authors hoped this would let the model learn to attend by relative position and extrapolate to longer sequences. In practice, because the position vector is added to the content vector and then passed through learned projections, the clean relative property is mixed with content terms, and Press et al. found sinusoidal models extrapolate poorly.

3. Learned absolute embeddings

GPT-2 and BERT replaced the fixed sinusoids with a second embedding table, one trainable row per position (1,024 rows for GPT-2, 512 for BERT), added to the token embeddings. This is simple and works well inside the trained range: the model can learn whatever position signals help. Its limits are equally simple. There is no row for position 1,025, so the model cannot process longer input without surgery, and positions near the end of the range are seen less often in training (only long documents reach them), so their rows are less well trained. Both schemes in this section and the last are absolute: they label positions, and relative relationships must be learned from the labels.

4. Rotation in two dimensions, from scratch

RoPE is built from one piece of school geometry. A 2-D vector (x, y) rotated anticlockwise by angle a becomes

( x cos a − y sin a ,  x sin a + y cos a )

Rotation never changes a vector's length. And the dot product of two 2-D vectors equals |u||v|cos(angle between them). Rotate u by a and v by b, and the angle between them changes by a − b; their lengths do not change. So the dot product of the rotated vectors depends on the original vectors and on a − b, never on a and b separately. That single fact is the whole trick.

5. RoPE, step by step

Rotary position embedding (Su et al., 2021) takes each query and key vector of head dimension d and splits it into d/2 pairs of adjacent components. Pair i gets its own frequency θᵢ = base^(−2i/d), with base = 10,000 in the original: pair 0 has θ = 1 radian per position, and the frequencies fall geometrically to about 1/10,000 for the last pair. For a token at position m, pair i of its query and of its key is rotated by angle m·θᵢ. That is all: no vectors are added, no parameters are learned, and it happens inside every attention layer, after the query and key projections and before the dot product. Values are not rotated.

Why it works: the score between a query at position m and a key at position n is the sum over pairs of (rotated query pair)·(rotated key pair). By section 4, each term depends on the angle difference mθᵢ − nθᵢ = (m − n)θᵢ. So the whole score depends on the content of q and k and on the relative position m − n only. RoPE gets relative attention while each key can still be computed once, from its own absolute position, which makes it compatible with caching keys during generation (lm5).

6. Rotating a query by hand

Take head dimension 4, so two pairs, with base 10,000: θ₀ = 10,000⁰ = 1 and θ₁ = 10,000^(−2/4) = 0.01 radians per position. A query q = [1, 0, 0.5, 0.5] at position m = 2:

  • Pair 0, (1, 0), rotates by 2 × 1 = 2 radians: (1·cos 2 − 0·sin 2, 1·sin 2 + 0·cos 2) = (cos 2, sin 2) = (−0.416, 0.909).
  • Pair 1, (0.5, 0.5), rotates by 2 × 0.01 = 0.02 radians: cos 0.02 = 0.9998, sin 0.02 = 0.0200, so (0.5 × 0.9998 − 0.5 × 0.0200, 0.5 × 0.0200 + 0.5 × 0.9998) = (0.490, 0.510).

The rotated query is [−0.416, 0.909, 0.490, 0.510]. The fast pair has swung more than 100 degrees; the slow pair has barely moved. Now the relative property with numbers. Let the first pair of both query and key be (1, 0). With the query at position 3 and the key at position 1, the pairs are rotated by 3 and 1 radians, the angle between them is 2, and their dot product is cos 2 = −0.416. Move both to positions 10 and 8: rotated by 10 and 8 radians, the angle between them is still 2, the dot product is still −0.416. The lab repeats this with random 64-dimensional vectors: the scores at positions (3, 1), (10, 8) and (1,000, 998) are all −8.1158, and at (5, 1) a different −9.1879.

7. What the frequencies give the model

Each pair has a wavelength, 2π/θᵢ, the number of positions after which its rotation returns to the start. With base 10,000 and head dimension 128 (typical of 7B-70B models), the lab computes wavelengths from 6.3 tokens for pair 0 to about 54,000 tokens for the last pair. Fast pairs make the score sensitive to small offsets, which helps with local syntax; slow pairs change little over short distances and act almost like position-free channels for nearby tokens while still separating far-apart ones. Su et al. also showed that, averaged over content, RoPE gives scores a mild long-term decay: the contributions of many pairs at different angles partly cancel as the distance grows, a gentle bias towards nearby tokens. The base controls the spread: Llama 3 raised it from 10,000 to 500,000, which stretches the longest wavelength to about 2.56 million tokens, part of how it supports 128K-token contexts.

8. ALiBi: a penalty for distance

Press, Smith and Lewis (2021) took a different route: no position vectors and no rotations, just a bias on the attention scores. Before the softmax, the score of query i attending to key j (j ≤ i) gets −m × (i − j) added, where m is a fixed slope for each head. For 8 heads the slopes are the geometric sequence 1/2, 1/4, 1/8, … 1/256; steep heads look mostly at recent tokens, shallow heads can see far back. Nothing is learned and nothing is added to the embeddings.

Worked example: a query at position 4 has raw scores [1.0, 0.5, 2.0, 0.0, 1.0] against keys at positions 0 to 4. In the head with slope 1/2 the biases are [−2.0, −1.5, −1.0, −0.5, 0], so the scores become [−1.0, −1.0, 1.0, −0.5, 1.0]. Without ALiBi the softmax weights are [0.176, 0.107, 0.478, 0.065, 0.176]; with it, [0.054, 0.054, 0.401, 0.089, 0.401]. The distant key 0 lost two thirds of its weight, the current token gained, and key 2, which had a strong content match, kept a large share. Content still matters; distance now costs.

ALiBi's selling point was extrapolation. In Press et al.'s experiments, a 1.3-billion-parameter model trained on 1,024-token sequences reached the same perplexity at 2,048 tokens as a sinusoidal model trained on 2,048-token sequences, while training 11% faster and using 11% less memory, because training on shorter sequences is cheaper. The cost is the built-in recency bias. Every head penalises distance linearly forever, so a token 20,000 positions back is heavily discounted in all but the shallowest heads. Perplexity, which mostly measures local prediction, hides this; tasks that require retrieving a distant fact expose it.

9. Why RoPE models break past their training length

RoPE's scores depend on relative distance, so it seems it should extrapolate. It does not, for two reasons. First, a model trained on 2,048-token sequences has never seen a distance above 2,047; the attention patterns it learned are only defined on that range. Second, look at the slowest pairs. With head dimension 128 and base 10,000, the last pair rotates by about 0.000115 radians per position, so over 2,048 positions it only ever reached about 0.236 radians. At position 4,095 it reaches 0.473, at 8,191 0.946: angles that pair never produced in training. Chen et al. show that attention scores computed with such unseen angles can be extremely large and effectively random, which "completely ruins" attention; perplexity explodes just past the training length.

10. Position interpolation

Chen et al.'s fix (2023) is to stop extrapolating and interpolate instead. To extend a 2,048-token model to 8,192 tokens, divide every position by 4 before computing the rotation angles. Position 8,191 is treated as 2,047.75, so every angle, including the slow pairs' maximum of 0.236 radians, stays inside the range the model was trained on. What is new is only that positions are now spaced a quarter as far apart, a much smaller change, which a short fine-tune on long documents teaches. They prove that the interpolated attention scores have an upper bound at least about 600 times smaller than the extrapolated ones in the LLaMA 7B setting, and extend LLaMA models from 7B to 65B parameters to context windows up to 32,768 tokens with fine-tuning within 1,000 steps.

11. Refinements: NTK-aware scaling, YaRN, base changes

Plain interpolation compresses every pair equally, including the fast pairs that had already cycled through all angles many times in training and did not need help. Compressing them blurs fine distinctions between neighbouring tokens, which slightly hurts short-range quality. NTK-aware scaling (named after a theory of how networks learn high and low frequencies) instead raises the base, which stretches low frequencies a lot and high frequencies hardly at all. YaRN (Peng et al., 2023) makes this explicit: pairs whose wavelength is much shorter than the training length are left alone, pairs whose wavelength is longer than it are interpolated fully, those in between are blended, and the attention logits are rescaled by a temperature factor because longer contexts spread softmax weight more thinly. The YaRN authors report reaching long contexts with about 10 times fewer training tokens and 2.5 times fewer steps than earlier methods. Finally, model builders can simply train with a larger base from the start or during a long-context stage: Llama 3 uses base 500,000 and extends its context from 8K to 128K tokens in six gradual stages of continued pretraining.

12. Choosing a scheme today

For a new decoder-only model the default is RoPE, with a base chosen for the target context (10,000 for a few thousand tokens; hundreds of thousands to millions for 100K+), plus a planned long-context training stage. ALiBi remains attractive when training budget is tight and inputs at inference will be modestly longer than in training, because it degrades gracefully with no extension step. Learned absolute embeddings survive mainly in encoders with fixed maximum length, such as BERT-style embedding models (lm10), where inputs are short and never extended. Sinusoidal encoding is now mostly of historical and teaching interest. Whatever the choice, it is fixed at pretraining: switching a trained model from one scheme to another means retraining, while extension methods only adjust the scheme the model already has.

13. Testing whether long context works

None of these methods is proven by perplexity alone, because perplexity rewards predicting the next token from nearby context and can stay low while distant tokens are ignored. Standard checks are passkey retrieval (a random number hidden in long filler text, which the model must repeat), needle in a haystack (a fact inserted at varying depths of a long document, then asked about), multi-needle and aggregation variants, and real tasks such as question answering over long reports. Results are usually shown as a grid of context length against insertion depth. A common finding is that models use the beginning and end of their context better than the middle ("lost in the middle"), which is one reason retrieval systems (lm9) still put the most relevant passages near the question.

RoPE in complex numbers

Treat each pair (x, y) as the complex number x + iy. Rotation by angle a is multiplication by e^(ia). RoPE multiplies query pair q by e^(imθ) and key pair k by e^(inθ); the real part of q·e^(imθ) times the conjugate of k·e^(inθ) is Re(q·k̄·e^(i(m−n)θ)), which visibly depends only on m − n. Implementations either view the head dimension as complex numbers or, more commonly, compute x·cos + rotate_half(x)·sin with precomputed cos and sin tables. There are two conventions for which components form a pair: adjacent components (0,1), (2,3) … as in the RoFormer paper, or the first half paired with the second half, (0, d/2), (1, d/2 + 1) …, as in the GPT-NeoX and Hugging Face Llama code. They are equivalent up to a fixed permutation of the projection weights, but mixing conventions between weights and inference code silently degrades a model, a classic porting bug.

Partial rotary and where position lives

Some models apply RoPE to only a fraction of each head's dimensions (GPT-NeoX rotates 25%), leaving the rest position-free. The rationale is that not every feature should be position-sensitive: content matching ("find the token that names a person") benefits from dimensions where nearby and distant tokens are treated alike. Interpretability studies of RoPE models find that the low-frequency pairs often carry content-matching signal (they barely rotate over typical distances), while high-frequency pairs implement positional heads such as "attend to the previous token". This division of labour is also why extension methods can leave high frequencies alone.

Why extrapolation fails, more precisely

A model trained to length L learns, for each head, a scoring function of content and relative distance on the domain 0 ≤ m − n < L. Extrapolation asks for values outside that domain, and a learned function has no obligation to behave sensibly there. With RoPE there is a second, sharper problem: the score is a sum of terms q_i k_i cos((m − n)θᵢ + φ), and for slow pairs the argument leaves the trained interval, so the sum can reach magnitudes never seen in training. Chen et al. bound the interpolated case using the smoothness of these trigonometric sums on the trained interval, which is why they can guarantee interpolation is far better behaved. ALiBi sidesteps the issue by making the distance term monotone and simple, at the cost of flexibility.

Attention temperature and entropy at long range

As context grows, the softmax spreads over more keys, so attention becomes more diffuse even if scores are unchanged: with n keys of similar score, each gets about 1/n of the weight. YaRN's temperature factor and related "log-n scaling" multiply the logits by a factor that grows slowly with length to keep attention entropy similar to training. This is the same √d_k logic from lm2 applied along the sequence axis instead of the feature axis: keep the softmax in the regime the model learned.

Other schemes you may meet

T5's relative bias learns a scalar bias per head for each bucket of relative distance (exact buckets for small distances, logarithmic for large ones), added to scores like ALiBi but learned; Press et al. found it extrapolates well but costs more compute. NoPE, no positional encoding at all, works surprisingly well in causal decoders, which can infer position from the mask, but is rarely used at scale. Sliding-window attention limits each layer's reach to a window, so positions beyond the window are reached only through several layers; combined with RoPE it bounds the distances any layer sees, which simplifies long-context behaviour.

Position and the KV cache

During generation, each new token's key is rotated by its own absolute position once, when it is computed, and stored in the KV cache (lm5); because the score between rotated vectors depends only on relative position, later queries can use the cached keys directly. This is a quiet but important property: a relative scheme that required re-rotating all keys whenever a new query arrived would make caching useless. It also constrains extension tricks. "Dynamic" scaling methods that change the rotation factor as the sequence grows would, strictly, require recomputing earlier keys with the new factor, so many serving engines use a fixed scale chosen for the maximum length. ALiBi's bias, added at score time from the distance alone, has no such interaction.

The training-data side of long context

A position scheme only makes long context possible; the model must still learn to use it, and that requires training sequences where distant information matters. Naturally long documents (books, code repositories, long reports) are a small fraction of web data, so long-context training stages upsample them and concatenate related documents. Llama 3's report describes increasing context in six stages from 8K to 128K tokens while checking that short-context performance recovers and that "needle in a haystack" retrieval works at each length. Without such data, extension methods produce models that accept long inputs but behave as if most of them were not there.

The public case: extending LLaMA with position interpolation (Chen et al., Meta, 2023)

The original LLaMA models accepted at most 2,048 tokens, which was quickly too short for long conversations and document summarisation. Retraining from scratch at a longer length would have cost as much as the original pretraining. Chen, Wong, Chen and Tian at Meta first tried the obvious alternative, fine-tuning at the longer length and letting RoPE extrapolate, and found it adapted very slowly: after more than 10,000 batches of fine-tuning, the effective context window grew only from 2,048 to 2,560 tokens. They traced the problem to the unseen-angle effect described above. Their figure 2 fits a RoPE-style score function (head dimension 128, the LLaMA 7B setting) to random points on the trained range: inside [0, 2,048] it stays within about ±1, but just outside it the same function exceeds 8,000, and they note this happens for almost every random fit, not a cherry-picked one. Directly extrapolating, perplexity "may shoot up" above 1,000, comparable to an untrained model.

Their position interpolation scales positions down by the extension factor. The paper reports extending LLaMA 7B, 13B, 33B and 65B to context windows up to 32,768 tokens with fine-tuning within 1,000 steps on the Pile dataset, good results on passkey retrieval, long-document language modelling and summarisation, and quality within the original 2,048-token window preserved relatively well. Their theoretical bound shows the interpolated scores are at least about 600 times smaller in the worst case than the extrapolated ones for the LLaMA 7B configuration. The idea spread within weeks: it became a configuration option ("linear RoPE scaling") in common libraries, and its refinements (NTK-aware scaling, YaRN) were developed in the open community in the following months.

Failure modes in practice

Quality cliff at the training length. A model that is excellent at 7,000 tokens and incoherent at 9,000 is usually running past its trained context with no extension configured. Check the model's maximum position setting and RoPE scaling configuration; serving engines may silently allow longer inputs.

Wrong rope_theta or scaling after a port. Llama 2 uses base 10,000 and Llama 3 500,000; a config that loads Llama 3 weights with base 10,000 produces a model that runs and writes plausible but degraded text. The same holds for pairing conventions (interleaved versus half-split). Compare logits with the reference implementation on a fixed input at several positions, including late ones.

Long context that is not really used. A model accepts 128K tokens but answers as if it had read only the beginning and end. Measure with needle-in-a-haystack grids on your own document types before relying on long context, and consider retrieval to put the relevant passage near the question.

Short-context regressions after extension. Interpolation and base changes alter every position's angles, so extended models can lose a little quality on short tasks. Re-run the standard short-context evaluation suite after any extension.

What to measure

Perplexity as a function of position on long held-out documents (it should keep falling or stay flat, not rise past a certain length), retrieval accuracy by context length and depth, and task metrics on real long inputs. On the systems side, long context multiplies KV-cache memory per sequence and prefill time, so check memory headroom and time to first token at the lengths you plan to serve (lm5, lm13).

Goal: compute sinusoidal encodings, rotate a query with RoPE and verify the relative-position property, compare RoPE wavelengths for two bases, apply ALiBi to a row of scores, and see why interpolation keeps angles in range. NumPy only, instant.

import numpy as np
np.set_printoptions(precision=3, suppress=True)
softmax = lambda z: np.exp(z - z.max()) / np.exp(z - z.max()).sum()

# ---- 1. sinusoidal table (Vaswani et al.): even dims sin, odd dims cos
def sinusoidal(n_pos, d, base=10000.0):
    pos = np.arange(n_pos)[:, None]; i = np.arange(0, d, 2)[None, :]
    ang = pos / base ** (i / d)
    pe = np.zeros((n_pos, d)); pe[:, 0::2] = np.sin(ang); pe[:, 1::2] = np.cos(ang)
    return pe
pe = sinusoidal(64, 16)
print("sinusoidal PE(pos=1)[:6] =", pe[1, :6])
print("dot(PE[10], PE[13]) =", round(pe[10] @ pe[13], 4), " dot(PE[40], PE[43]) =", round(pe[40] @ pe[43], 4), "(same offset -> same dot)")

# ---- 2. RoPE: rotate each (even, odd) pair of q and k by angle position * theta_i
def rope(x, pos, base=10000.0):
    d = x.shape[-1]; theta = base ** (-np.arange(0, d, 2) / d)
    a = pos * theta; c, s = np.cos(a), np.sin(a)
    x1, x2 = x[0::2], x[1::2]
    out = np.empty_like(x); out[0::2] = x1 * c - x2 * s; out[1::2] = x1 * s + x2 * c
    return out
q = np.array([1.0, 0.0, 0.5, 0.5])                                   # head dim 4: thetas 1 and 0.01 rad per position
print("\nRoPE thetas for d=4:", 10000.0 ** (-np.arange(0, 4, 2) / 4))
print("q =", q, " rotated to position 2:", rope(q, 2))
rng = np.random.default_rng(0); q, k = rng.normal(size=64), rng.normal(size=64)
for m, n in [(3, 1), (10, 8), (1000, 998), (5, 1)]:
    print(f"score(q at {m:4d}, k at {n:4d}) = {rope(q, m) @ rope(k, n):8.4f}")
print("norm preserved:", np.isclose(np.linalg.norm(rope(q, 777)), np.linalg.norm(q)))

# ---- 3. wavelengths of the pairs: how many tokens before each pair's angle wraps around
for base in (10000.0, 500000.0):
    wl = 2 * np.pi * base ** (np.arange(0, 128, 2) / 128)
    print(f"base {base:>9,.0f}, head dim 128: shortest wavelength {wl[0]:.1f} tokens, longest {wl[-1]:,.0f} tokens")

# ---- 4. ALiBi: add -slope * distance to each score
n_heads = 8
slopes = 2.0 ** (-8 * np.arange(1, n_heads + 1) / n_heads)
print("\nALiBi slopes for 8 heads:", slopes)
raw = np.array([1.0, 0.5, 2.0, 0.0, 1.0])                             # query at position 4, keys 0..4
bias = -0.5 * (4 - np.arange(5))
print("raw", raw, "+ bias", bias, "=", raw + bias)
print("weights without ALiBi", softmax(raw), " with (slope 1/2)", softmax(raw + bias))

# ---- 5. order matters once positions are in: same tokens, swapped order
X = rng.normal(size=(3, 8))
def attn_last(X):                                                    # output of the last position's attention, RoPE on q and k
    n = len(X); Q = np.stack([rope(X[i], i) for i in range(n)]); K = Q.copy()
    return softmax(Q[-1] @ K.T / np.sqrt(8)) @ X
print("\nlast-token output, order A B C:", attn_last(X[[0, 1, 2]])[:4], "\nlast-token output, order B A C:", attn_last(X[[1, 0, 2]])[:4])

# ---- 6. extending context: extrapolate vs interpolate (Chen et al.) for the slowest pair of a 2,048-trained model
theta_min = 10000.0 ** (-126 / 128)
for pos in (2047, 4095, 8191):
    print(f"position {pos:5d}: slowest-pair angle {pos * theta_min:.3f} rad (trained max {2047 * theta_min:.3f});"

What to look for.

Design — extend a model from 8K to 32K tokens

Your product uses an open RoPE model trained with an 8,192-token context. Customers want to paste 30-page contracts (about 25,000 tokens). You have a modest fine-tuning budget. What do you do, and how do you know it worked?

Answer

Do not just raise the max length. Positions beyond 8,191 produce unseen RoPE angles in the slow pairs, and quality collapses past the training length.

Extend with interpolation. A 4× extension: either linear position interpolation (divide positions by 4) or, better for short-context quality, NTK-aware/YaRN scaling, which stretches low frequencies and leaves high ones nearly untouched. Then fine-tune on long documents, ideally contracts and similar long texts, for on the order of a thousand steps; Chen et al. extended LLaMA 8× within 1,000 steps.

Verify. (1) Perplexity by position on held-out long contracts should not rise past 8K. (2) Needle-in-a-haystack and passkey grids at 8K, 16K, 24K and 32K, at several depths. (3) Your actual task: questions whose answers sit early, middle and late in a contract. (4) The standard short-context evaluations, to catch regressions.

Systems check. 32K tokens means four times the KV cache per request (lm5) and a long prefill, so re-check memory headroom, batch size and time to first token. And compare against the alternative: retrieving the relevant clauses (lm9) may answer most questions with a short context at a fraction of the cost.

Compute — RoPE by hand

A head of dimension 4 uses base 10,000. Rotate the key k = [0, 1, 1, 0] to position 3, and say which pair is more useful for telling position 3 from position 4.

Answer

θ₀ = 1 and θ₁ = 0.01. Pair 0, (0, 1), rotates by 3 radians: (0·cos 3 − 1·sin 3, 0·sin 3 + 1·cos 3) = (−sin 3, cos 3) = (−0.141, −0.990). Pair 1, (1, 0), rotates by 0.03 radians: (cos 0.03, sin 0.03) = (0.9996, 0.0300). So the rotated key is [−0.141, −0.990, 1.000, 0.030]. Moving from position 3 to 4 turns pair 0 by a whole radian (57 degrees) but pair 1 by only 0.01 radians, so the fast pair 0 is the one that distinguishes neighbouring positions; the slow pair matters for distances in the hundreds.
