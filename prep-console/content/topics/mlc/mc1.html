A team building a house-price estimator has 200,000 past sales, each described by twenty numbers: floor area, number of bedrooms, distance to the station, age of the roof and so on. They want a formula that turns those twenty numbers into a price. The simplest formula anyone would try is a weighted sum: so many pounds per square metre, minus so much per kilometre from the station, plus a constant. Finding the best weights for that weighted sum is linear regression, and it is the model the team will ship first, because it trains in a second, every weight means something a product manager can read, and when it is wrong you can see why.

Now picture the interview version. "Implement linear regression without scikit-learn." It sounds trivial, and that is exactly why it is asked first: there is nowhere to hide. Within ten minutes the interviewer learns whether you can turn a loss function on the whiteboard into array code with the shapes right, whether you know that the formula in the textbook (multiply by an inverse) is the wrong way to compute the answer, whether your gradient descent diverges because you never scaled the features, whether you accidentally shrink the intercept when you add regularisation, and whether you test your code against something you can trust or just eyeball the output and hope.

Each of those mistakes has a real cost outside the interview. An explicit inverse on nearly duplicate columns (floor area in square metres and in square feet, say) produces weights of plus and minus a billion that cancel on the training data and explode on the next house. A learning rate that was fine on standardised data turns into NaN on the raw data. A regularised intercept quietly biases every prediction toward zero. These are the bugs this lesson trains you to avoid.

The lesson goes from nothing to an expert-level answer. It starts with the model and the loss in plain words, derives the gradient and the closed-form normal equations, and then does everything once by hand on three data points: the exact best line, one full gradient-descent step with real numbers, and one ridge solution. Then it writes the naive Python-loop version, the vectorised NumPy version, and a test suite that checks the hand-worked numbers, recovers known weights, makes two solvers agree, checks the gradient against finite differences and cross-checks against PyTorch. It finishes with the numerical traps (conditioning, collinearity, scaling, dtype), complexity, the senior follow-ups (sufficient statistics for ten billion rows, the SVD and the whole ridge path, QR versus Cholesky) and what goes wrong in production.

Start with a picture. You have a scatter of points on a sheet of paper: house size along the bottom, price up the side. Linear regression lays a straight ruler across the scatter and asks: of all the ways I could lay this ruler, which one makes the total squared vertical gap between the ruler and the points as small as possible? The vertical gap for one point is its residual, the prediction minus the true value. Squaring the residuals does two things: it makes misses above and below the line count the same, and it punishes big misses much more than small ones (a miss of 10 costs 100, a miss of 1 costs 1).

With more than one feature the ruler becomes a flat sheet (a plane, or a hyperplane in many dimensions), but the idea is identical. The model is a weighted sum, ŷ = w₁x₁ + w₂x₂ + … + w_d x_d + b, where the xs are the features of one example, the ws are the weights we are looking for, and b is the intercept, the prediction when every feature is zero. Stack all n examples as rows of a matrix X of shape (n, d), called the design matrix, and all predictions become one matrix-vector product: ŷ = Xw + b.

The quantity we minimise is the mean squared error (MSE): the average of the squared residuals. As a function of the weights, MSE is a bowl. Every weight vector is a point on the floor of a landscape, and the height of the bowl above that point is the error those weights would make. The bowl has exactly one lowest point (or, in a special case covered later, a flat valley floor of equally good points), and there are two ways to find it.

The first is to solve for it directly. At the bottom of a smooth bowl the slope is zero in every direction. Writing "slope equals zero" as equations gives a small system of linear equations, one equation per weight, called the normal equations. Solve that system and you have the answer in one shot: this is the closed form.

The second is to walk downhill. Start anywhere, measure the slope (the gradient), take a small step against it, and repeat. That is gradient descent, which you met in the ML track (ml4). It is slower for this problem but it is the method that generalises to every model in the rest of this section, from logistic regression to transformers, and it is the only option when the data does not fit in memory.

Where the ruler picture breaks: in many dimensions you can no longer see the line, and some features may be near copies of each other, which makes the "lowest point" a long, nearly flat valley rather than a single dip. Much of the numerical care in this lesson is about that valley.

Finally, ridge regression (L2 regularisation, from ml3) adds a second term to the loss, α‖w‖², the squared length of the weight vector times a strength α. It tilts the bowl toward small weights, which costs a little training error and buys stability: the solution always exists, it is unique, and the weights no longer explode on nearly duplicate features. An ML coding round usually asks for all three pieces: the closed form, gradient descent, and an optional ridge penalty.

1. The problem as it is usually asked

"Implement linear regression with fit(X, y) and predict(X), without scikit-learn. Support the closed-form solution and gradient descent, and an optional L2 penalty." Before writing, ask the questions that change the code. Is X dense and in memory, or does it stream? (Streaming rules out anything that needs all of X at once.) Should the intercept be fitted? (Almost always yes.) How do we decide gradient descent has converged? (A fixed number of steps is a weak answer; a tolerance on the gradient is a strong one.) What sizes are we talking about? (With d = 20 features the closed form is instant; with d = 10⁶ sparse features it is impossible.) Saying these out loud costs thirty seconds and shows you know where implementations differ.

2. The maths in plain words

The model multiplies each feature by a weight, adds them up, and adds a constant. The loss averages the squared misses. To make the loss smaller, we need to know, for each weight, whether nudging it up makes the loss go up or down and by how much. That number is the partial derivative of the loss with respect to that weight, and the list of all of them is the gradient.

For one weight w_j the reasoning is short. Each example's squared residual rᵢ² changes by 2rᵢ per unit change in rᵢ (the derivative of a square). And rᵢ changes by x_ij per unit change in w_j, because w_j is multiplied by that feature. Multiplying the two (the chain rule) and averaging over examples: the derivative is (2/n) Σᵢ rᵢ x_ij. In words: each feature's gradient is the average of residual times that feature, doubled. If examples with a big value of feature j tend to be over-predicted (positive residual), the gradient for w_j is positive and descending it lowers w_j. The intercept behaves like a feature that is always 1, so its derivative is (2/n) Σᵢ rᵢ: if the predictions are too high on average, lower the constant.

3. The equations

Writing those sums as matrix products gives the whole thing in three lines. With residual vector r = Xw + b − y of shape (n,):

L(w, b) = (1/n) · ‖Xw + b − y‖²            mean squared error
∂L/∂w   = (2/n) · Xᵀ r                      shape (d,): Xᵀ is (d, n), r is (n,)
∂L/∂b   = (2/n) · Σ r                       a scalar

Say the shapes as you write them. Xᵀ is (d, n), r is (n,), so Xᵀr is (d,), exactly the shape of w. A gradient must always have its parameter's shape; checking that catches most transposition bugs before you run anything.

For the closed form, deal with the intercept first. If you centre the data, subtracting each column's mean from X and the mean of y from y, the best intercept on the centred data is exactly zero (the intercept's gradient says the residuals must average zero, and with centred data that holds at b = 0). So solve for w on centred data, then recover b = ȳ − x̄ · w. Setting the weight gradient to zero on centred data gives:

Xᵀ(Xw − y) = 0    ⟹    XᵀX · w = Xᵀy          the normal equations (d equations, d unknowns)
ridge:  L + α‖w‖²   ⟹   (XᵀX + nαI) · w = Xᵀy

The ridge version adds 2αw to the gradient; moving it across and multiplying through by n/2 is where the nα on the diagonal comes from. Some libraries define the loss as a sum rather than a mean and write αI instead; the two are the same model with α rescaled by n, a detail worth stating whenever you compare against another implementation.

Why is it called "normal"? Xᵀ(y − Xw) = 0 says the residual vector is perpendicular (normal) to every column of X. The best prediction Xw is the point in the space spanned by the columns that sits closest to y, and the shortest path from a point to a flat space meets it at a right angle. The figure shows this for two columns.

4. A worked example by hand

Take three points: x = [1, 2, 3] and y = [2, 4, 5]. One feature, so w is a single number.

The closed form. The means are x̄ = 2 and ȳ = 11/3 ≈ 3.667. Centred, x_c = [−1, 0, 1] and y_c = [−1.667, 0.333, 1.333]. With one feature, XᵀX is just Σ x_c² = 1 + 0 + 1 = 2, and Xᵀy is Σ x_c y_c = 1.667 + 0 + 1.333 = 3. So w = 3 / 2 = 1.5, and b = ȳ − x̄·w = 3.667 − 3 = 0.667. The predictions are [2.167, 3.667, 5.167], the residuals [+0.167, −0.333, +0.167] (they sum to zero, as promised), and the MSE is (0.0278 + 0.1111 + 0.0278)/3 = 0.0556.

One gradient-descent step, from w = 0, b = 0 with learning rate 0.1, on the raw (uncentred) data so you can see the coupling. Every prediction is 0, so the residuals are r = [−2, −4, −5] and the starting loss is (4 + 16 + 25)/3 = 15.

  • Weight gradient: (2/3)·(1·−2 + 2·−4 + 3·−5) = (2/3)·(−25) = −16.667.
  • Intercept gradient: (2/3)·(−2 − 4 − 5) = (2/3)·(−11) = −7.333.
  • Step: w = 0 − 0.1·(−16.667) = 1.667, b = 0 − 0.1·(−7.333) = 0.733.
  • New predictions [2.400, 4.067, 5.733], residuals [0.400, 0.067, 0.733], loss (0.160 + 0.0044 + 0.538)/3 = 0.234.

The loss fell from 15 to 0.234 in one step, and w has overshot the optimum (1.667 against 1.5) while b is close (0.733 against 0.667). That overshoot is the coupling between w and b on uncentred data: because every x is positive, raising w also raises every prediction, so w did part of the intercept's job on the first step and will hand it back slowly. On centred data the two gradients are independent and that slow hand-back disappears.

Ridge with α = 0.5 on the centred data: w = Σx_c y_c / (Σx_c² + nα) = 3 / (2 + 1.5) = 0.857. The slope has been pulled from 1.5 toward zero; the intercept is still recovered as ȳ − x̄·w = 3.667 − 1.714 = 1.952, unpenalised. All of these numbers are asserted by the first block of the solution:

import time
import numpy as np

# The hand-worked example: three points, one feature.
x_hand = np.array([1.0, 2.0, 3.0])
y_hand = np.array([2.0, 4.0, 5.0])

def mse(w, b, x, y):
    return np.mean((w * x + b - y) ** 2)

# Closed form for one feature: slope = Sxy / Sxx on centred data, then b = ybar - w * xbar.
xc, yc = x_hand - x_hand.mean(), y_hand - y_hand.mean()
w_star = (xc @ yc) / (xc @ xc)
b_star = y_hand.mean() - w_star * x_hand.mean()
assert np.isclose(w_star, 1.5) and np.isclose(b_star, 2 / 3)

# One gradient step from w = b = 0 with lr = 0.1, exactly as done by hand.
r = 0.0 * x_hand + 0.0 - y_hand                 # residuals [-2, -4, -5]
gw, gb = 2 * np.mean(x_hand * r), 2 * np.mean(r)
assert np.isclose(gw, -50 / 3) and np.isclose(gb, -22 / 3)
w1, b1 = 0 - 0.1 * gw, 0 - 0.1 * gb
assert np.isclose(w1, 5 / 3) and np.isclose(b1, 11 / 15)
assert np.isclose(mse(0, 0, x_hand, y_hand), 15.0)
assert np.isclose(mse(w1, b1, x_hand, y_hand), 0.234074, atol=1e-6)

# Ridge on the centred data: w = Sxy / (Sxx + n * alpha).
assert np.isclose((xc @ yc) / (xc @ xc + 3 * 0.5), 6 / 7)

5. The naive loop implementation

The first draft most people write follows the sums literally: loop over steps, loop over examples, loop over features. It is worth writing once because it makes every symbol in the gradient concrete, and in an interview it is a fine thing to sketch on the way to the real answer, as long as you say that you are about to replace it.

def gd_naive(X, y, lr=0.1, steps=500):
    """Batch gradient descent written with explicit Python loops (the 'first draft')."""
    n, d = len(X), len(X[0])
    w, b = [0.0] * d, 0.0
    for _ in range(steps):
        gw, gb = [0.0] * d, 0.0
        for i in range(n):                         # every example ...
            pred = b
            for j in range(d):                     # ... every feature
                pred += w[j] * X[i][j]
            r = pred - y[i]
            for j in range(d):
                gw[j] += 2 * r * X[i][j] / n
            gb += 2 * r / n
        for j in range(d):
            w[j] -= lr * gw[j]
        b -= lr * gb
    return np.array(w), b

Count the work. Each step touches every feature of every example twice (once for the prediction, once for the gradient), so it is O(nd) multiply-adds, executed one at a time by the Python interpreter. Each of those costs tens of nanoseconds of interpreter overhead, around a hundred times more than the multiply itself. On 20,000 rows and 20 features one step took about 98 ms on this lesson's laptop.

6. The vectorised version

The same step in NumPy is two matrix products: r = Xc @ w − yc and grad = 2 * Xc.T @ r / n. NumPy hands each product to BLAS (Basic Linear Algebra Subprograms), compiled code that uses the CPU's vector instructions and caches well. The same 20,000 × 20 step took about 1.3 ms, roughly 75 times faster, and the gap grows with size. The full class below supports the closed form, ridge and gradient descent, centres the data so the intercept is never penalised, and stops gradient descent when the gradient's length falls below a tolerance rather than after a fixed count.

class LinearRegression:
    """Minimises (1/n)·||Xw + b - y||² + alpha·||w||²  (the intercept b is not penalised)."""

    def __init__(self, alpha=0.0, method="closed", lr=0.1, max_iter=10_000, tol=1e-8):
        self.alpha, self.method = alpha, method
        self.lr, self.max_iter, self.tol = lr, max_iter, tol

    def fit(self, X, y):
        X, y = np.asarray(X, float), np.asarray(y, float)
        n, d = X.shape
        self.x_mean, self.y_mean = X.mean(0), y.mean()
        Xc, yc = X - self.x_mean, y - self.y_mean          # centring removes the intercept
        if self.method == "closed":
            if self.alpha == 0:
                # least squares via SVD, not an inverse: stable, and fine with collinear columns
                self.w = np.linalg.lstsq(Xc, yc, rcond=None)[0]
            else:
                A = Xc.T @ Xc + n * self.alpha * np.eye(d)   # (d, d), symmetric positive definite
                self.w = np.linalg.solve(A, Xc.T @ yc)
        else:
            self.w = np.zeros(d)
            for self.n_iter in range(1, self.max_iter + 1):
                r = Xc @ self.w - yc                              # (n,) residuals
                grad = 2 * Xc.T @ r / n + 2 * self.alpha * self.w  # (d,) same shape as w
                self.w -= self.lr * grad
                if np.linalg.norm(grad) < self.tol:
                    break
        self.b = self.y_mean - self.x_mean @ self.w
        return self

    def predict(self, X):
        return np.asarray(X, float) @ self.w + self.b

Three decisions in that code deserve a sentence each when you present it. lstsq for the unpenalised case: it solves least squares through the singular value decomposition, so it copes with collinear columns and returns the minimum-norm answer (section 8). solve for ridge: XᵀX + nαI is symmetric and strictly positive definite, so a direct factorisation is safe and fast; there is never a reason to call inv. Stopping on the gradient norm: the gradient is exactly zero at the optimum, so its size measures how far you still are; a fixed epoch count stops too early on hard problems and wastes time on easy ones.

7. Testing it: the hand example, a reference, and a gradient check

The tests are the part of the answer interviewers remember, because they show you know how to be sure. There are four kinds, and the block below does all of them. First, the class must reproduce the hand-worked numbers exactly (w = 1.5, b = 2/3, ridge w = 6/7). Second, on synthetic data generated from known weights [2, −1, 0.5] and intercept 3 plus tiny noise, it must recover them, and the closed form, vectorised gradient descent and the naive loop must agree to six decimals. Third, the analytic gradient must match a finite-difference estimate: nudge one weight up and down by ε = 10⁻⁶, and (L(w + ε) − L(w − ε)) / 2ε approximates that partial derivative with error proportional to ε². The relative difference here is below 10⁻⁷. Fourth, if PyTorch is installed, its torch.linalg.lstsq must give the same weights to ten decimals.

# 1. The class reproduces the hand-worked answer.
m = LinearRegression().fit(x_hand[:, None], y_hand)
assert np.isclose(m.w[0], 1.5) and np.isclose(m.b, 2 / 3)
assert np.isclose(LinearRegression(alpha=0.5).fit(x_hand[:, None], y_hand).w[0], 6 / 7)

# 2. Synthetic data with known weights; closed form, GD and the naive loop all agree.
rng = np.random.default_rng(0)
X = rng.normal(size=(200, 3))
true_w, true_b = np.array([2.0, -1.0, 0.5]), 3.0
y = X @ true_w + true_b + 0.01 * rng.normal(size=200)
closed = LinearRegression().fit(X, y)
gd = LinearRegression(method="gd").fit(X, y)
assert np.allclose(closed.w, true_w, atol=0.01) and abs(closed.b - true_b) < 0.01
assert np.allclose(closed.w, gd.w, atol=1e-6) and abs(closed.b - gd.b) < 1e-6
w_loop, b_loop = gd_naive(X.tolist(), y.tolist(), steps=300)
assert np.allclose(w_loop, closed.w, atol=1e-6) and abs(b_loop - closed.b) < 1e-6

# 3. Ridge: both solvers agree, and the weights shrink.
r_closed = LinearRegression(alpha=1.0).fit(X, y)
r_gd = LinearRegression(alpha=1.0, method="gd").fit(X, y)
assert np.allclose(r_closed.w, r_gd.w, atol=1e-6)
assert np.linalg.norm(r_closed.w) < np.linalg.norm(closed.w)

# 4. A duplicated column makes XᵀX singular; lstsq still predicts correctly (minimum-norm w).
X_dup = np.hstack([X, X[:, :1]])
dup = LinearRegression().fit(X_dup, y)
assert np.allclose(dup.predict(X_dup), closed.predict(X), atol=1e-8)
assert np.isclose(dup.w[0], dup.w[3])          # the weight is split evenly between the twins

# 5. Gradient check: the analytic gradient matches central finite differences.
def loss(w, Xc, yc, alpha):
    return np.mean((Xc @ w - yc) ** 2) + alpha * w @ w
Xc, yc = X - X.mean(0), y - y.mean()
w0, eps = rng.normal(size=3), 1e-6
analytic = 2 * Xc.T @ (Xc @ w0 - yc) / len(yc) + 2 * 0.3 * w0
numeric = np.array([(loss(w0 + eps * e, Xc, yc, 0.3) - loss(w0 - eps * e, Xc, yc, 0.3)) / (2 * eps)
                    for e in np.eye(3)])
assert np.max(np.abs(analytic - numeric)) / np.max(np.abs(analytic)) < 1e-7

# 6. Conditioning: normal equations square the condition number; lstsq does not.
t = np.linspace(0, 1, 50)
V = np.vander(t, 8, increasing=True)            # polynomial features 1, t, ..., t^7
w_true = np.ones(8)
yv = V @ w_true
cond_V, cond_VtV = np.linalg.cond(V), np.linalg.cond(V.T @ V)
assert cond_VtV > 0.5 * cond_V ** 2
err_normal = np.max(np.abs(np.linalg.solve(V.T @ V, V.T @ yv) - w_true))
err_lstsq = np.max(np.abs(np.linalg.lstsq(V, yv, rcond=None)[0] - w_true))
assert err_lstsq < err_normal

# 7. Cross-check against torch's least-squares solver, if torch is installed.
try:
    import torch
    wt = torch.linalg.lstsq(torch.tensor(X - X.mean(0)), torch.tensor(y - y.mean())[:, None]).solution
    assert np.allclose(wt.numpy().ravel(), closed.w, atol=1e-10)
except ImportError:
    pass

# 8. Naive loop vs vectorised: same answer, very different speed.
t0 = time.perf_counter(); gd_naive(X.tolist(), y.tolist(), steps=50); t_loop = time.perf_counter() - t0
t0 = time.perf_counter()
w = np.zeros(3)
for _ in range(50):
    w -= 0.1 * 2 * Xc.T @ (Xc @ w - yc) / len(yc)
t_vec = time.perf_counter() - t0
if __name__ == "__main__":
    print(f"cond(V)={cond_V:.3g} cond(VtV)={cond_VtV:.3g} err normal={err_normal:.2e} lstsq={err_lstsq:.2e}")
    print(f"loop {t_loop*1e3:.1f} ms  vectorised {t_vec*1e3:.2f} ms  speed-up {t_loop/t_vec:.0f}x")
    print("gd iterations:", gd.n_iter, "dup w:", dup.w.round(4))

Why central differences rather than one-sided (L(w + ε) − L(w))/ε? The one-sided version has error proportional to ε, the central one to ε², so with ε = 10⁻⁶ the central estimate is accurate to about 10⁻¹² in theory, limited in practice by floating-point cancellation to about 10⁻¹⁰ relative. Choosing ε is itself a trade-off: too large and the curvature term dominates, too small and subtracting two nearly equal losses loses all the digits. Around 10⁻⁶ in float64 is the usual sweet spot; in float32 it would need to be near 10⁻³.

8. Numerical stability traps

Trap 1: inverting, or even forming, XᵀX. The condition number of a matrix, the ratio of its largest to smallest singular value, measures how much it amplifies errors: solving a system with condition number 10ᵏ can lose about k of your 16 float64 digits. Forming XᵀX squares the condition number. In the test, polynomial features 1, t, …, t⁷ on 50 points in [0, 1] give a matrix with condition number 1.1 × 10⁵; XᵀX has 1.2 × 10¹⁰. Solving the normal equations recovered the true weights to about 6 × 10⁻⁷; lstsq, which works on X directly, got 2 × 10⁻¹². Five extra digits lost, just by forming the product. An explicit inv is worse again: it computes d right-hand sides when you need one, and multiplying by a slightly wrong inverse adds its own error.

Trap 2: collinear columns. If two columns are identical (or one is a linear combination of others), XᵀX is singular: its smallest eigenvalue is zero, and the bowl has a flat valley floor along the direction "add to one twin, subtract from the other". Every point on that floor makes the same predictions. inv fails or returns huge cancelling weights; lstsq picks the minimum-norm point, which splits the weight evenly. The test duplicates the first column: lstsq gives weights of about 1.0 on each twin (summing to the original 2.0) and predictions identical to the original fit to 10⁻⁸. Ridge also fixes it, by making the floor slope toward zero.

Trap 3: unscaled features and the learning rate. Gradient descent on this loss converges only if the learning rate is below 2/λ_max, where λ_max is the largest eigenvalue of the Hessian H = (2/n)XᵀX, the matrix of second derivatives that describes the bowl's curvature. Error along each eigen-direction shrinks by a factor |1 − lr·λ| each step; if that factor exceeds 1 in any direction, the error grows geometrically until it overflows to NaN. Meanwhile the flattest direction shrinks by only 1 − lr·λ_min, so the number of steps grows with λ_max/λ_min. In the three-point example with uncentred x, H = (2/3)·[[14, 6], [6, 3]] for (w, b) has eigenvalues about 11.1 and 0.24: the safe learning rate is below 0.18, and the flat direction shrinks by only 2.4% a step at lr = 0.1. Centring decouples w from b; standardising (dividing each column by its standard deviation) puts every eigenvalue near 2, so one learning rate suits every direction.

Trap 4: dividing by a zero standard deviation. A constant column has standard deviation 0, and standardising it produces NaN everywhere. Either drop constant columns or divide by max(std, ε).

Trap 5: dtype. In float32 (7 significant digits), a condition number of 10⁷ leaves nothing; the normal equations on the polynomial example would be pure noise. Keep classical regression in float64, and if you must accumulate XᵀX over billions of rows, accumulate in float64 even if the data is stored as float32.

9. Complexity

The closed form costs O(nd²) to form XᵀX (each of the d² entries is a sum over n rows) plus O(d³) to factorise it. lstsq's SVD is also O(nd²) for tall matrices, with a larger constant. Memory is O(d²) beyond the data. For n = 10⁶ and d = 100 that is about 10¹⁰ flops, a few seconds; for d = 10,000 the d³ term alone is 10¹² flops and the d × d matrix is 800 MB in float64, so the closed form stops being attractive.

Gradient descent costs O(nd) per step and O(d) extra memory, times the number of steps, which grows with the condition number of the (standardised) problem. Sparse data makes each step cost O(number of non-zeros), which is why large sparse problems (text features, one-hot categories) are solved iteratively. Mini-batch stochastic gradient descent costs O(bd) per step for a batch of b rows and never needs the whole dataset in memory.

10. Talking through the design

A good presentation order: state the model and loss with shapes; derive the gradient in one line; centre to handle the intercept; give the closed form and say why you call lstsq/solve instead of inv; give gradient descent with a gradient-norm stopping rule; add ridge as one extra term in each solver; then tests. If the interviewer asks "which would you use?", answer with sizes: closed form for d up to a few thousand dense features, iterative methods beyond that or when the data streams. If they ask "how do you know it's right?", point at the three independent checks: known weights, solver agreement, finite differences. Both answers are short, concrete and show judgement rather than recitation.

The probabilistic reading

Suppose the data really is y = Xw + ε, where the noise ε is drawn from a normal (Gaussian) distribution with mean 0 and constant variance σ². The probability of observing your y under weights w is a product of Gaussian densities, and its logarithm is −(1/2σ²)·‖y − Xw‖² plus a constant. Maximising the likelihood is therefore exactly minimising squared error. That tells you when MSE is the right loss (symmetric, light-tailed, constant-variance noise) and when it is not (heavy tails: use Huber or absolute loss; variance growing with the target: weight the rows or model the logarithm). Ridge has the matching reading: put a Gaussian prior with variance τ² on each weight and the most probable weights given the data (the MAP estimate) minimise squared error plus (σ²/τ²)‖w‖², so α is a noise-to-prior variance ratio. Lasso is the same with a Laplace prior, whose sharp peak at zero is why it produces exact zeros.

The SVD view, and the whole ridge path at once

Write the centred X = USVᵀ: V holds orthogonal directions in feature space, S the singular values s_k (how strongly the data varies along each), and U the corresponding directions in example space. Then the least-squares solution is w = V·diag(1/s_k)·Uᵀy and the ridge solution is w(α) = V·diag(s_k/(s_k² + nα))·Uᵀy. Two senior points come out of that formula. First, ridge shrinks each direction by the factor s_k²/(s_k² + nα): strongly supported directions (large s_k) are barely touched, weakly supported ones (small s_k, exactly the ones where 1/s_k would explode) are suppressed. Second, after one SVD every value of α costs only a rescale, so tuning α by cross-validation over fifty values costs one decomposition, not fifty solves.

QR, Cholesky and SVD: which and why

Cholesky factorises the symmetric positive definite XᵀX = LLᵀ and solves two triangular systems; it is the fastest (about nd² + d³/3 flops) but inherits the squared condition number. QR factorises X = QR with orthonormal Q and triangular R, then solves Rw = Qᵀy; it never forms XᵀX, so it keeps the original condition number, for roughly twice the cost. The SVD costs more again but reveals the rank and handles rank deficiency gracefully, which is why NumPy's lstsq uses it. A strong answer: Cholesky for ridge (where nα fixes the conditioning) and well-conditioned problems, QR as the default for plain least squares, SVD when columns may be collinear or you want the ridge path.

Sufficient statistics: regression on ten billion rows

Everything the closed form needs is XᵀX (d × d), Xᵀy (d), the column sums (for the means) and n. Each is a sum over rows, so they are sufficient statistics: each worker computes them on its shard, a reduce step adds them up, and the tiny final system is solved on one machine. For d = 1,000 the statistics are 8 MB however many rows there are. The traps are numerical: accumulate in float64, and centre using a first-pass mean (or Welford-style streaming updates) because Σx² − n·x̄² computed from raw sums cancels catastrophically when the mean is large compared with the spread.

When d is huge: iterative solvers that need only products

If d is a million sparse features, XᵀX cannot be formed. Conjugate gradient solves (XᵀX + nαI)w = Xᵀy using only the products Xv and Xᵀu, each O(non-zeros), and converges in roughly the square root of the condition number's number of steps, far fewer than gradient descent. L-BFGS does the same job for general smooth losses. Stochastic gradient descent goes further and touches only a mini-batch per step, at the cost of noisy convergence and a learning-rate schedule.

More features than rows

When d > n there are infinitely many weight vectors that fit the training data exactly. The choice among them is a regularisation decision whether you make it consciously or not: lstsq returns the minimum-norm one (which is also what gradient descent started from zero converges to, a fact that underlies much of the modern "benign overfitting" literature), ridge returns a smoothly shrunk one, and lasso a sparse one. Saying "the solution isn't unique, so here is which one I pick and why" is the senior answer.

How fast gradient descent converges, exactly

Because the loss is quadratic, gradient descent can be analysed exactly rather than by rule of thumb. Write the error e = w − w*. One step maps it to (I − lr·H)e, so along each eigen-direction of the Hessian with eigenvalue λ, the error is multiplied by 1 − lr·λ every step. The best single learning rate balances the fastest and slowest directions: lr = 2/(λ_max + λ_min), which gives a contraction factor of (κ − 1)/(κ + 1) per step, where κ = λ_max/λ_min is the condition number. For the uncentred three-point example, κ ≈ 46, so even the best learning rate shrinks the error by only 4% a step and needs about 210 steps to cut the error by a factor of 10⁴; after centring κ is 1.5 and two or three steps suffice. Momentum and conjugate gradient improve the dependence from κ to about √κ, which is why they matter on badly conditioned problems, and why preconditioning (standardising is the simplest preconditioner) is the first thing to try.

Robust regression when MSE is the wrong loss

One mislabelled house price of £50 million contributes a squared residual so large that the fit tilts to reduce it, worsening every other prediction. The Huber loss is squared for residuals smaller than a threshold δ and linear beyond it, so its gradient is capped at δ in magnitude: an outlier can pull, but only as hard as a point at distance δ. It has no closed form, but iteratively reweighted least squares solves it by repeatedly running weighted least squares with weights min(1, δ/|rᵢ|), a nice reuse of the solver you just wrote. In an interview, mentioning that MSE is a modelling choice and naming the alternative with its mechanism is a strong signal.

Multiple outputs and weighted rows

Pass Y of shape (n, k) and solve/lstsq return W of shape (d, k) with no code change: the factorisation is shared across all k right-hand sides, so fitting 1,000 targets costs little more than one. Weighted least squares, where row i carries weight vᵢ (inverse noise variance, or an importance weight), changes one line: XᵀVX·w = XᵀVy, or equivalently scale each row of X and y by √vᵢ and run the unweighted solver.

Where linear regression lives in real systems

Linear models are still everywhere in production: demand and price forecasting baselines, the calibration layer on top of a complex model, linear probes that test what a frozen neural network's embeddings encode, the final layer of almost every network, and the "is the fancy model actually better?" baseline that every experiment should report. The failure modes below are the ones that show up in those settings.

Failure modes and their symptoms

Exploding, sign-flipping weights. Symptom: a weight of +3.2 million on "area in m²" and −0.3 million on "area in ft²", fine training error, and wild predictions on new data. Cause: near-collinear features and an unregularised solve. Detection: the condition number of the standardised X, or weights that change sign between daily retrains. Fix: drop the duplicate, or add a small ridge penalty, which costs almost nothing in accuracy and removes the instability.

NaN after a schema change. Symptom: a training job that ran for months starts producing NaN. Cause: a new column with a different scale (cents instead of pounds) pushed λ_max above 2/lr, or a constant column was standardised by a zero standard deviation. Detection: assert finite losses, log the per-feature mean and standard deviation, alert when they shift.

Training/serving skew in preprocessing. The model is only correct with the same centring and scaling it was trained with. If training computed means on the training set and serving recomputes them on each request batch, predictions shift silently. Store the means and scales with the weights, as the class above does with x_mean, and version them together.

Extrapolation. A linear model happily predicts a negative price for a tiny flat or a billion-pound price for a stadium. Clip predictions to the training target range, or model log(price), which also fixes noise that grows with the price.

What to monitor and tune

Log the training and validation MSE, the gradient norm at stopping (it should be near the tolerance, not the iteration cap), the condition number of the standardised design matrix, the largest absolute weight, and residual summaries by segment (a model that is right on average can be biased by £40,000 in one city). Tune α by cross-validation on a log grid (10⁻⁴ to 10²); with the SVD this costs one decomposition. Refit when the feature means drift, not only on a calendar.

The reference for this problem

The official NumPy documentation for numpy.linalg.lstsq is the reference implementation this lesson leans on, and it is worth reading because it answers three interview follow-ups in its own words. It "computes the vector x that approximately solves the equation a @ x = b", minimising the Euclidean norm ‖b − ax‖, and "if there are multiple minimizing solutions, the one with the smallest 2-norm ‖x‖ is returned": the minimum-norm behaviour the collinearity test relies on. Its rcond parameter sets the rank cut-off: singular values smaller than rcond times the largest are treated as zero, and since NumPy 2.0 the default is machine precision times max(M, N) (previously −1, which meant machine precision alone, with a warning that it would change). And the returned residuals are an empty array when the matrix is rank-deficient or not taller than it is wide, a detail that has broken more than one script that assumed a number would come back. scikit-learn's linear-model guide, the second reference, states the same O(n·d²) cost for its SVD-based ordinary least squares that section 9 derives.

Work it out

Extend the solution to lasso (L1 penalty), which has no closed form. Implement coordinate descent for (1/2n)·‖y − Xw‖² + α‖w‖₁ and show that it sets the weights of irrelevant features to exactly zero.

Answer

Fix every weight except w_j. The one-dimensional problem has a closed-form answer: compute the correlation ρ_j of feature j with the partial residual (the residual with j's own contribution added back), then apply soft thresholding S(ρ, α) = sign(ρ)·max(|ρ| − α, 0). Any feature whose correlation with the residual is below α lands on exactly zero, which is where the sparsity comes from. Keep the residual up to date incrementally so each coordinate update costs O(n), not O(nd).

def soft_threshold(z, t):
    return np.sign(z) * np.maximum(np.abs(z) - t, 0.0)

def lasso_cd(X, y, alpha, n_sweeps=200):
    X = X - X.mean(0); y = y - y.mean()
    n, d = X.shape
    w = np.zeros(d)
    col_sq = (X ** 2).sum(0) / n
    r = y.copy()                                 # residual y - Xw, kept current
    for _ in range(n_sweeps):
        for j in range(d):
            r += X[:, j] * w[j]                  # add j's contribution back
            rho = X[:, j] @ r / n
            w[j] = soft_threshold(rho, alpha) / col_sq[j]
            r -= X[:, j] * w[j]
    return w

rng = np.random.default_rng(1)
X = rng.normal(size=(300, 10))
w_true = np.zeros(10); w_true[:3] = [3.0, -2.0, 1.5]
y = X @ w_true + 0.1 * rng.normal(size=300)
w = lasso_cd(X, y, alpha=0.1)
assert np.all(w[3:] == 0.0)                     # exactly zero, not merely small
assert np.all(np.abs(w[:3] - w_true[:3]) < 0.2) # shrunk toward zero by about alpha

Two things to say out loud: the surviving weights are biased toward zero by roughly α (the price of sparsity; refit plain least squares on the selected features if you need unbiased estimates), and in practice you solve for a decreasing sequence of α values using each solution as the warm start for the next, which is how glmnet computes a whole regularisation path quickly.
