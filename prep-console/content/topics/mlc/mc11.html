Every deep-learning framework computes gradients for you. Call loss.backward() and every weight in a billion-parameter model receives exactly the right number. So why do interviewers still ask candidates to write the backward pass of a two-layer network by hand? Because the moment you step outside the framework's built-in operations, you are on your own. A custom attention kernel, a fused normalisation layer, a new loss for a ranking problem, a memory-saving trick that recomputes activations: each needs a backward pass someone wrote by hand and someone else must trust. Teams that write such kernels verify them in exactly the way this lesson does, against a finite-difference check and against the framework's autograd on small shapes.

The question also tests whether "backprop" is a magic word or something you understand. A two-layer network, a linear layer, a ReLU, another linear layer and a softmax loss, is the smallest model that contains every idea: matrix shapes that must line up, gradients that flow backward through matrix products by transposition, a non-linearity that gates gradients, a loss whose gradient is "predicted minus target", and parameters shared across a batch so their gradients sum. Get one rule slightly wrong (a missing transpose on a square matrix, a forgotten division by the batch size, the regulariser's factor of two) and the network may still train, just badly, which is why a gradient check is not optional.

There is a satisfying payoff too. On the classic three-armed spiral dataset from Stanford's CS231n course, a linear softmax classifier cannot do better than about half the points, because no straight lines separate interleaved spirals. Add one hidden layer of 100 ReLU units, train it with the backward pass you derived, and accuracy jumps to 99% in this lesson's run. Watching that happen with code you understand line by line is the best way to stop thinking of neural networks as black boxes, and the same derivation habits carry straight over to attention (mc16), normalisation layers (mc15) and the autograd engine of mc13.

The lesson starts with the computation in plain words, writes the forward and backward equations with shapes, and then pushes one example through by hand with real numbers: the loss, every gradient, the dead unit whose weights get zero gradient, and one update step that lowers the loss from 4.018 to 1.405. It then writes a per-example loop version, the vectorised version, a gradient check that knows about ReLU kinks, a PyTorch autograd cross-check, the spiral experiment against a linear baseline, and finally a modular layer design in the drill. Along the way it covers initialisation, dead units, the memory cost of backprop, and how to debug a network that will not learn.

A two-layer network is two linear models stacked with a bend in between. The first layer takes each input (here, a point's two coordinates) and computes several weighted sums of it, one per hidden unit; these sums are the pre-activations. Each passes through a ReLU, which keeps positive values and replaces negatives with zero, producing the activations. The second layer computes one weighted sum of the activations per class, the logits, and softmax with cross-entropy (mc10) scores them. Each hidden unit acts like a feature detector that fires on one side of a line in input space; the second layer combines the detectors, and because the ReLU bends each one, the combination can carve out curved regions that no single line could.

Training needs, for every weight, the answer to: if I nudged this weight, how much would the loss change? The chain rule answers it by passing blame backwards. The loss knows how it depends on the logits (predicted probabilities minus targets). The logits depend on the second layer's weights and on the activations, so the blame splits: part goes to the second-layer weights, part flows back to the activations. The ReLU passes that blame through only for units that were on. The pre-activations depend on the first-layer weights and the input, so the blame splits again. This backwards sweep, reusing each step's result for the next, is backpropagation: one forward pass to compute the loss, one backward pass to compute every gradient, at roughly twice the forward pass's cost.

Why can the backward pass be so cheap? Because the blame for an early weight passes through every later operation, and backprop computes the blame at each intermediate point once and shares it. Computing each weight's gradient separately, by nudging it and re-running the network, would cost one forward pass per weight, millions of passes for a modest model. Backprop costs about two, whatever the number of weights. That asymmetry is the single reason deep learning is computationally possible.

Two habits make the backward pass easy to write correctly. First, write the forward pass as a list of simple lines, one operation each, keeping every intermediate value; the backward pass is then the same list in reverse, one line per forward line. Second, check shapes constantly: the gradient of anything has the same shape as the thing itself, which almost always tells you whether a matrix needs transposing and on which side it goes.

And one habit makes it trustworthy: the gradient check. Nudge one weight up and down by a tiny amount, measure the loss each time, and the difference divided by the nudge is a numerical estimate of that weight's gradient. If your backward pass agrees with it to six or seven significant digits for every weight, the backward pass is right. Where the picture breaks: the ReLU has a corner at zero, and a nudge that crosses the corner gives a misleading estimate, so the check must avoid inputs sitting right on a corner.

1. The problem as it is usually asked

"Implement a two-layer neural network classifier in NumPy: forward pass, softmax cross-entropy loss with L2 regularisation, and the backward pass by hand. Verify the gradients numerically and train it on a toy dataset." Clarify: hidden size and activation (ReLU unless told otherwise); whether biases are regularised (usually not); mean or sum over the batch (mean); which optimiser (plain gradient descent is fine). Then outline: initialise with He scaling, write the forward pass as one operation per line, write the backward pass in reverse, gradient-check on a few points in float64, then train and compare with a linear baseline.

2. The maths in plain words

For a batch of N examples stacked as rows of X: multiply by the first weight matrix and add the bias to get one pre-activation per hidden unit per example; apply ReLU; multiply by the second weight matrix and add its bias to get one logit per class per example; take the mean softmax cross-entropy over the batch and add half the regularisation strength times the sum of squared weights.

Backwards. The loss's gradient with respect to the logits is the softmax probabilities minus the one-hot targets, divided by N because the loss is a mean (mc10). The second layer's weights were multiplied by the activations, so each weight's gradient is the sum over examples of "activation times logit gradient": a matrix product of the activations' transpose with the logit gradients. The bias was added to every example, so its gradient is the logit gradients summed over the batch. The activations were multiplied by the second-layer weights, so their gradient is the logit gradients times those weights transposed. ReLU passes that through where the pre-activation was positive and blocks it elsewhere. The first layer repeats the linear-layer pattern with the input in place of the activations. Finally, the regulariser adds its own term, λ times each weight matrix, to that matrix's gradient.

3. The equations, with shapes

forward                                   shapes
z₁ = X W₁ + b₁                            (N, d)(d, h) + (h,)   → (N, h)
a₁ = max(z₁, 0)                           (N, h)
z₂ = a₁ W₂ + b₂                           (N, h)(h, C) + (C,)   → (N, C)
L  = −(1/N) Σₙ log softmax(z₂)ₙ,yₙ + ½λ(‖W₁‖² + ‖W₂‖²)

backward (each line undoes one forward line, in reverse order)
dz₂ = (softmax(z₂) − onehot(y)) / N       (N, C)
dW₂ = a₁ᵀ dz₂ + λW₂                       (h, N)(N, C) → (h, C)  same as W₂
db₂ = Σₙ dz₂                              (C,)
da₁ = dz₂ W₂ᵀ                             (N, C)(C, h) → (N, h)  same as a₁
dz₁ = da₁ ⊙ 1[z₁ > 0]                     (N, h)
dW₁ = Xᵀ dz₁ + λW₁                        (d, N)(N, h) → (d, h)  same as W₁
db₁ = Σₙ dz₁                              (h,)

Read the shape column as the derivation's safety net. dW₂ must be (h, C) because W₂ is; the only way to combine a₁ (N, h) and dz₂ (N, C) into (h, C) is a₁ᵀ dz₂, which also performs the required sum over the N examples. da₁ must be (N, h); the only product of dz₂ (N, C) and W₂ (h, C) with that shape is dz₂ W₂ᵀ. Once you have done this a few times, you can write any linear layer's backward pass from shapes alone.

4. A worked example by hand

One example x = [1, 2], two hidden units, two classes, target class 1, zero biases, no regularisation:

W₁ = [[1,  −1],      W₂ = [[1, −1],
      [0.5, −1]]           [2,  1]]
  • Layer 1. z₁ = [1·1 + 2·0.5, 1·(−1) + 2·(−1)] = [2, −3].
  • ReLU. a₁ = [2, 0]. The second unit is off.
  • Layer 2. z₂ = [2·1 + 0·2, 2·(−1) + 0·1] = [2, −2].
  • Softmax. The difference between logits is 4, so p = [1/(1 + e⁻⁴), 1/(1 + e⁴)] = [0.98201, 0.01799].
  • Loss. The target is class 1, which got 1.8%: loss = −log 0.01799 = log(1 + e⁴) = 4.01815. A confidently wrong prediction.
  • dz₂ = p − onehot(1) = [0.98201, −0.98201] (N = 1, so no division).
  • dW₂ = outer(a₁, dz₂) = [[1.964, −1.964], [0, 0]]; the second row is zero because a₁[1] = 0. db₂ = [0.982, −0.982].
  • da₁ = W₂ · dz₂ = [1·0.982 + (−1)(−0.982), 2·0.982 + 1·(−0.982)] = [1.964, 0.982].
  • dz₁ = da₁ ⊙ [z₁ > 0] = [1.964, 0]. The second unit's gradient, 0.982, is blocked by the ReLU.
  • dW₁ = outer(x, dz₁) = [[1.964, 0], [3.928, 0]]; db₁ = [1.964, 0].

One step with learning rate 0.1: W₁[0,0] goes from 1 to 0.804, W₁[1,0] from 0.5 to 0.107, W₂[0] from [1, −1] to [0.804, −0.804], and the biases move by −0.196 and ±0.098. Recomputing: the first unit's pre-activation drops to 0.822, the logits become [0.562, −0.562], and the loss falls from 4.018 to 1.405. Everything moved in the direction that shrinks the gap between the wrong class's logit and the right one's. The second hidden unit's weights did not change at all: on this example, it simply did not participate.

import math
import time
import numpy as np

# The hand-worked example: one input, two hidden ReLU units, two classes, target class 1.
x = np.array([1.0, 2.0])
W1 = np.array([[1.0, -1.0], [0.5, -1.0]]); b1 = np.zeros(2)
W2 = np.array([[1.0, -1.0], [2.0, 1.0]]); b2 = np.zeros(2)
y = 1

z1 = x @ W1 + b1                        # [1 + 1, -1 - 2] = [2, -3]
a1 = np.maximum(z1, 0)                  # [2, 0]: the second unit is off
z2 = a1 @ W2 + b2                       # [2, -2]
assert z1.tolist() == [2.0, -3.0] and a1.tolist() == [2.0, 0.0] and z2.tolist() == [2.0, -2.0]
p = np.exp(z2 - z2.max()); p /= p.sum()
assert np.allclose(p, [1 / (1 + math.exp(-4)), 1 / (1 + math.exp(4))])     # [0.98201, 0.01799]
loss = -np.log(p[y])
assert np.isclose(loss, math.log(1 + math.exp(4)))                          # 4.01815

dz2 = p - np.eye(2)[y]                  # [0.982, -0.982]
dW2 = np.outer(a1, dz2); db2 = dz2
da1 = W2 @ dz2                          # = dz2 @ W2.T  -> [1.964, 0.982]
dz1 = da1 * (z1 > 0)                    # [1.964, 0]: no gradient through the dead unit
dW1 = np.outer(x, dz1); db1 = dz1
q = p[0]
assert np.allclose(dW2, [[2 * q, -2 * q], [0, 0]])
assert np.allclose(da1, [2 * q, q]) and np.allclose(dz1, [2 * q, 0])
assert np.allclose(dW1, [[2 * q, 0], [4 * q, 0]])

# One gradient step with learning rate 0.1 lowers the loss.
W1n, b1n, W2n, b2n = W1 - 0.1 * dW1, b1 - 0.1 * db1, W2 - 0.1 * dW2, b2 - 0.1 * db2
z2n = np.maximum(x @ W1n + b1n, 0) @ W2n + b2n
loss_new = np.logaddexp(z2n[0], z2n[1]) - z2n[y]
assert loss_new < loss and np.isclose(loss_new, 1.4054, atol=1e-4)

5. The naive implementation: one example, one neuron at a time

The most literal version loops over examples, and within each over input features, hidden units and classes, accumulating every gradient entry with explicit additions:

def mlp_naive(X, y, W1, b1, W2, b2):
    """Forward and backward one example at a time, one neuron at a time."""
    N, d = len(X), len(X[0]); h, C = len(b1), len(b2)
    g = {"W1": [[0.0] * h for _ in range(d)], "b1": [0.0] * h,
         "W2": [[0.0] * C for _ in range(h)], "b2": [0.0] * C}
    total = 0.0
    for n in range(N):
        z1 = [b1[j] + sum(X[n][i] * W1[i][j] for i in range(d)) for j in range(h)]
        a1 = [max(v, 0.0) for v in z1]
        z2 = [b2[k] + sum(a1[j] * W2[j][k] for j in range(h)) for k in range(C)]
        m = max(z2); e = [math.exp(v - m) for v in z2]; s = sum(e)
        total += -(z2[y[n]] - m - math.log(s))
        dz2 = [e[k] / s - (k == y[n]) for k in range(C)]
        for j in range(h):
            for k in range(C):
                g["W2"][j][k] += a1[j] * dz2[k] / N
        for k in range(C):
            g["b2"][k] += dz2[k] / N
        dz1 = [sum(W2[j][k] * dz2[k] for k in range(C)) * (z1[j] > 0) for j in range(h)]
        for i in range(d):
            for j in range(h):
                g["W1"][i][j] += X[n][i] * dz1[j] / N
        for j in range(h):
            g["b1"][j] += dz1[j] / N
    return total / N, {k: np.array(v) for k, v in g.items()}

It is useful in two ways. It makes every sum in the matrix equations visible (the / N in each accumulation is the mean; the double loop over j and k is the outer product that a₁ᵀ dz₂ computes for all examples at once). And it is an independent implementation to test against: on 40 spiral points, its loss and all four gradients agree with the vectorised version to floating-point precision. Its cost is the problem: the backward pass on 300 examples with 100 hidden units took 167 ms, against 0.83 ms for the matrix version, about 200 times slower, and the gap widens with width.

6. The vectorised version

class MLP:
    """x -> Linear(d, h) -> ReLU -> Linear(h, C) -> softmax cross-entropy."""

    def __init__(self, d, h, C, seed=0):
        rng = np.random.default_rng(seed)
        self.p = {
            "W1": rng.normal(0, np.sqrt(2 / d), (d, h)), "b1": np.zeros(h),   # He init for ReLU
            "W2": rng.normal(0, np.sqrt(1 / h), (h, C)), "b2": np.zeros(C),
        }

    def loss(self, X, y, reg=0.0):
        p, N = self.p, len(X)
        # forward: one simple operation per line
        z1 = X @ p["W1"] + p["b1"]                  # (N, h)
        a1 = np.maximum(z1, 0)                       # (N, h)
        z2 = a1 @ p["W2"] + p["b2"]                  # (N, C)
        z2 = z2 - z2.max(1, keepdims=True)
        logp = z2 - np.log(np.exp(z2).sum(1, keepdims=True))
        loss = -logp[np.arange(N), y].mean() + 0.5 * reg * ((p["W1"] ** 2).sum() + (p["W2"] ** 2).sum())
        # backward: the same lines in reverse
        dz2 = np.exp(logp); dz2[np.arange(N), y] -= 1; dz2 /= N     # softmax - onehot, averaged
        g = {"W2": a1.T @ dz2 + reg * p["W2"], "b2": dz2.sum(0)}
        da1 = dz2 @ p["W2"].T                        # (N, h)
        dz1 = da1 * (z1 > 0)                         # ReLU passes gradient only where it was active
        g["W1"] = X.T @ dz1 + reg * p["W1"]
        g["b1"] = dz1.sum(0)
        return loss, g

    def predict(self, X):
        return (np.maximum(X @ self.p["W1"] + self.p["b1"], 0) @ self.p["W2"] + self.p["b2"]).argmax(1)

def grad_check(model, X, y, reg=0.0, eps=1e-5):
    """Worst per-tensor relative error: ||numeric - analytic|| / (||numeric|| + ||analytic||)."""
    _, g = model.loss(X, y, reg)
    worst = 0.0
    for k, P in model.p.items():
        num = np.zeros_like(P)
        for i in np.ndindex(P.shape):
            old = P[i]
            P[i] = old + eps; lp, _ = model.loss(X, y, reg)
            P[i] = old - eps; lm, _ = model.loss(X, y, reg)
            P[i] = old                                   # always restore the parameter
            num[i] = (lp - lm) / (2 * eps)
        worst = max(worst, np.linalg.norm(num - g[k]) / max(1e-12, np.linalg.norm(num) + np.linalg.norm(g[k])))
    return worst

Initialisation. W₁ is drawn with standard deviation √(2/d), He initialisation, so that ReLU activations keep roughly the input's variance; W₂ uses √(1/h); biases start at zero. Random weights break the symmetry between hidden units.

Forward. One operation per line, keeping z₁ (for the ReLU mask), a₁ (for dW₂) and the log-probabilities (for dz₂). The softmax is the stable log-softmax of mc10.

Backward. Each line mirrors a forward line in reverse, exactly as in the equations. dz2 is built by exponentiating the log-probabilities, subtracting 1 at the targets and dividing by N. The ReLU backward is da1 * (z1 > 0). The regulariser's gradient reg * W is added to each weight gradient, and its loss term carries the ½ so the two agree.

Gradient check. grad_check loops over every entry of every parameter, evaluates the loss at θ + ε and θ − ε (restoring the original value each time, without which every later entry is checked at the wrong point), and reports the worst relative error ‖num − ana‖/(‖num‖ + ‖ana‖) per tensor.

7. The gradient check, and why kinks matter

The finite difference (L(θ + ε) − L(θ − ε))/2ε estimates the slope of the loss along one parameter. For a smooth function its error shrinks like ε², so with ε = 10⁻⁵ in float64 the estimate agrees with a correct analytic gradient to about seven digits; CS231n's notes put it as "1e-7 and less you should be happy", and warn that single precision can give errors as high as 10⁻² even for a correct gradient.

ReLU is not smooth at zero. If some pre-activation is within ε of zero, nudging a weight can switch that unit on or off, and the finite difference then measures an average of two different slopes. The spiral dataset makes this concrete: every arm starts at the origin, where the input is (0, 0), so every pre-activation equals the bias, which is initialised to exactly zero. Every hidden unit sits precisely on its kink for those points. A gradient check including them reports errors that look like bugs. The solution checks on every thirtieth point starting from the fifth, which avoids the origin, and gets a worst relative error below 10⁻⁷. The general advice is the same: check on a handful of examples, away from kinks, in float64.

8. Testing it, and the spiral

The test block checks: the class reproduces every hand-worked gradient; the per-example loops agree with the matrix version on 40 points; the gradient check passes below 10⁻⁷; PyTorch's autograd, given the same weights and data, produces the same four gradients to 10⁻¹²; and then the experiment. CS231n's spiral has 100 points per class in three interleaved arms. A linear softmax classifier trained with the same gradient descent reached 54% training accuracy here (CS231n reports 49% for its version); the two-layer network with 100 hidden units, trained for 4,000 full-batch steps with learning rate 1 and λ = 10⁻³, reached 99% (CS231n: 98%), with the loss falling from 1.27 to 0.24. Finally it times the backward pass both ways.

def spiral(n=100, C=3, seed=0):
    rng = np.random.default_rng(seed)
    X, y = [], []
    for c in range(C):
        r = np.linspace(0.0, 1, n)
        t = np.linspace(c * 4, (c + 1) * 4, n) + rng.normal(0, 0.2, n)
        X.append(np.c_[r * np.sin(t), r * np.cos(t)]); y += [c] * n
    return np.vstack(X), np.array(y)

# 1. The class reproduces the hand-worked gradients.
m = MLP(2, 2, 2); m.p = {"W1": W1.copy(), "b1": b1.copy(), "W2": W2.copy(), "b2": b2.copy()}
l, g = m.loss(x[None], np.array([y]))
assert np.isclose(l, loss) and np.allclose(g["W1"], dW1) and np.allclose(g["W2"], dW2)
assert np.allclose(g["b1"], db1) and np.allclose(g["b2"], db2)

# 2. The naive per-example loops agree with the vectorised backward pass.
X, Y = spiral()
mm = MLP(2, 8, 3, seed=2)
ln, gn = mlp_naive(X[:40].tolist(), Y[:40].tolist(), *(mm.p[k].tolist() for k in ("W1", "b1", "W2", "b2")))
lv, gv = mm.loss(X[:40], Y[:40])
assert np.isclose(ln, lv) and all(np.allclose(gn[k], gv[k]) for k in gv)

# 3. Gradient check on points away from the origin: every spiral arm starts at (0, 0), where all
#    pre-activations equal b1 = 0, exactly on the ReLU kink, where finite differences lie.
assert grad_check(MLP(2, 6, 3, seed=1), X[5::30], Y[5::30], reg=1e-3) < 1e-7

# 4. Cross-check the gradients against PyTorch autograd, if available.
try:
    import torch
    tp = {k: torch.tensor(v, requires_grad=True) for k, v in mm.p.items()}
    zt = torch.relu(torch.tensor(X[:40]) @ tp["W1"] + tp["b1"]) @ tp["W2"] + tp["b2"]
    torch.nn.functional.cross_entropy(zt, torch.tensor(Y[:40])).backward()
    assert all(np.allclose(tp[k].grad.numpy(), gv[k], atol=1e-12) for k in gv)
except ImportError:
    pass

# 5. Train on the spiral: the network separates what a linear softmax cannot.
model = MLP(2, 100, 3)
losses = []
for step in range(4000):
    loss_t, g = model.loss(X, Y, reg=1e-3)
    losses.append(loss_t)
    for k in model.p:
        model.p[k] -= 1.0 * g[k]                      # plain full-batch gradient descent
acc_mlp = (model.predict(X) == Y).mean()
assert losses[-1] < 0.3 * losses[0] and acc_mlp > 0.95

W = np.zeros((2, 3)); bb = np.zeros(3)                # linear softmax baseline
for step in range(2000):
    z = X @ W + bb; z -= z.max(1, keepdims=True); pr = np.exp(z); pr /= pr.sum(1, keepdims=True)
    pr[np.arange(len(Y)), Y] -= 1; pr /= len(Y)
    W -= 1.0 * (X.T @ pr); bb -= 1.0 * pr.sum(0)
acc_lin = ((X @ W + bb).argmax(1) == Y).mean()
assert acc_lin < 0.65

One sanity check is worth adding to any new classifier: the loss at initialisation. If the output layer's weights are small, every class gets probability about 1/C and the loss should be about log C, 1.0986 for three classes; CS231n's case study shows exactly that value at iteration 0 because it initialises with tiny weights. This lesson's He-scaled output layer starts at 1.27, a little higher, because its logits are not near zero. An initial loss far above log C (say 5 on a three-class problem) usually means the output layer's initialisation or the loss computation is wrong.

Overfit a tiny batch before anything else

The gradient check proves the backward pass matches the forward pass; it does not prove the training loop works. The next test, recommended in Karpathy's "recipe" post and used by practitioners everywhere, is to train on a tiny batch, say eight examples, with no regularisation, and confirm the loss goes to nearly zero within a few hundred steps. A two-layer network with 100 hidden units has far more capacity than eight points need, so failing to memorise them means something outside the gradient is broken: the update is applied to a copy of the weights, the learning rate is zero or has the wrong sign, the labels are shuffled relative to the inputs, or the data loader returns the same batch with different labels each time. It takes seconds and catches bugs that otherwise cost hours of staring at slowly falling loss curves. Only after this passes is it worth tuning the learning rate, the hidden size or the regularisation on the full dataset.

From full batches to mini-batches

The solution trains on all 300 points at every step, which is fine for a toy problem. Real training samples a random mini-batch of, say, 64 or 256 examples per step, computes the loss and gradients on it with exactly the same code (N is now the mini-batch size), and updates. The mini-batch gradient is a noisy but unbiased estimate of the full gradient, each step is far cheaper, and the noise itself tends to help generalisation. Two details change. The loss curve becomes noisy, so plot a moving average or the full-dataset loss every few hundred steps. And the learning rate that worked for full batches is usually too large for small mini-batches, because the gradient's noise grows as the batch shrinks; a common starting point is to scale the learning rate roughly in proportion to the batch size and then tune. Nothing in the backward pass itself depends on the batch size, which is the point of writing it with matrices: the same lines handle one example or ten thousand.

9. Numerical and practical traps

Trap 1: forgetting to restore the parameter in the gradient check. Every later entry is then checked at a shifted point, and errors appear in random places. Always set it back.

Trap 2: kinks. Described above. Symptoms: a few entries of one weight matrix with large errors, the rest fine.

Trap 3: single precision. In float32, ε = 10⁻⁵ is near the precision of the loss itself, and the difference L(θ + ε) − L(θ − ε) is mostly rounding noise. Check in float64, always.

Trap 4: the mean's 1/N. Dividing the loss by N but not dz₂ (or vice versa) makes every gradient off by a factor of N. The check catches it immediately; training without the check just looks like a learning rate that is N times too large or too small.

Trap 5: the regulariser's factor. A loss term of λ‖W‖² with a gradient of λW is off by a factor of 2. Either use ½λ‖W‖² with λW, or λ‖W‖² with 2λW.

Trap 6: square matrices hide transposes. With d = h = C, a wrong transpose still has the right shape and runs. Use non-square sizes in tests (here d = 2, h = 6 or 8, C = 3) so shape errors surface.

Trap 7: dead units. A large negative bias or a too-large learning rate can push a unit's pre-activation negative for every example; it then outputs zero and gets zero gradient for ever. Count units that are zero on the whole batch during training.

10. Edge cases worth naming

A batch of one example is fine and is exactly the hand example. A hidden size of one reduces the network to a single bent line and fails on the spiral, a useful experiment. An input feature that is constant contributes only through the bias, and its weights receive gradients proportional to that constant. Labels outside [0, C) index out of range in dz2[np.arange(N), y] -= 1; validate them. And a learning rate of 1, which works for this small, well-scaled problem, would diverge on unscaled inputs: standardise features before blaming the network.

11. Complexity

The forward pass costs O(N·d·h + N·h·C) multiply-adds, dominated by the two matrix products; the backward pass costs about twice that, because each linear layer needs two products (one for its weight gradient, one for its input gradient); the first layer's input gradient is not needed and can be skipped. Memory is O(N·(h + C)) for the stored intermediates, plus the parameters O(d·h + h·C). The gradient check costs two full forward passes per parameter entry, O(P·N·(d·h + h·C)) for P parameters, which is why it runs on tiny networks and a few data points.

12. Talking through the design

In the interview: write the forward pass with shapes; derive dz₂ = (p − y)/N from mc10; give the linear-layer rule and the ReLU mask; write the backward pass line by line in reverse; add regularisation consistently; then gradient-check, explaining ε, central differences, relative error, float64 and kinks; then train on something non-linear and compare with a linear baseline. Mention He initialisation and symmetry breaking unprompted; they are the most common follow-ups.

Why backprop costs about two forward passes

Reverse-mode differentiation computes the gradient of one scalar (the loss) with respect to all parameters in one backward sweep, because each node's gradient is computed once and reused by every path through it. For a linear layer the backward pass needs two matrix products (for dW and dx) against one in the forward pass, so a full training step costs about three forward passes' worth of arithmetic, the origin of the common "6 × parameters × tokens" estimate for transformer training FLOPs (2 for the forward multiply-add, 4 for the backward). Forward-mode differentiation would instead need one pass per parameter, which is why it is only used when there are few inputs and many outputs.

Activation memory and checkpointing

The backward rules need forward values: a₁ for dW₂, the ReLU mask for dz₁, X for dW₁. So memory for training grows with batch size × widths × depth, and for large models this activation memory, not the parameters, is what fills the GPU. Activation checkpointing keeps only the inputs of selected blocks and recomputes everything else during the backward pass, costing roughly one extra forward pass for a large saving. Knowing exactly which values each backward rule needs (the ReLU needs only a 1-bit mask, not z₁ itself) is also how fused kernels minimise memory traffic.

Initialisation, from symmetry to variance

Zero initialisation makes every hidden unit identical for ever. Random initialisation fixes that, and its scale matters for depth. For a layer with fan-in n and weights of variance σ², each pre-activation's variance is about n·σ² times the input variance; a ReLU then keeps half of it. He initialisation, σ² = 2/n, makes the product 1, so signals neither shrink nor grow across layers, and the same argument run backwards keeps gradients stable. Xavier/Glorot initialisation, σ² = 1/n (or 2/(n_in + n_out)), suits tanh. With two layers either works; with fifty, the wrong choice makes training stall or explode (dl3).

L2 penalty versus decoupled weight decay

Adding ½λ‖W‖² to the loss puts λW into the gradient, and with plain gradient descent that is identical to shrinking every weight by a factor (1 − ηλ) each step, which is why the two names are often used interchangeably. With adaptive optimisers such as Adam the equivalence breaks, because Adam rescales the whole gradient, including the λW term, per parameter. AdamW instead applies the shrinkage directly to the weights, separately from the gradient, which behaves better in practice; mc12 implements both and shows the difference.

Modular layers: the design every framework uses

The drill refactors the network into Linear and ReLU objects, each with forward (which caches what its backward needs) and backward (which stores parameter gradients and returns the gradient for the layer below), plus a Sequential container that calls them in order and in reverse. That is precisely the design of early frameworks such as Torch's nn modules, and still the mental model behind PyTorch's autograd.Function, where you write a custom forward and backward and save tensors for the backward with ctx.save_for_backward. mc13 goes one step further and records the graph automatically.

Gradient checking at scale

Checking every parameter of a real model is impossible: each entry costs two forward passes. Practitioners check custom operations in isolation on tiny random inputs in float64 (PyTorch provides torch.autograd.gradcheck for exactly this), check a random subset of entries for larger pieces, or compare a directional derivative: pick a random direction v, compare (L(θ + εv) − L(θ − εv))/2ε with ∇L · v. One random direction tests all parameters at once with two forward passes, and a few directions catch almost any bug.

Other activations and their backward rules

Only the mask line changes when the activation changes. Leaky ReLU, max(αz, z) with α around 0.01, has derivative 1 for positive inputs and α for negative ones, so a unit that is off still receives a small gradient and cannot die permanently. GELU, used in most transformers, is z·Φ(z) with Φ the standard normal CDF; its derivative Φ(z) + z·φ(z) is smooth everywhere, so it has no kink and gradient checks behave as for a smooth function. Tanh's derivative is 1 − tanh²(z), conveniently computed from the forward output. In each case the backward rule needs the forward input or output, which determines what must be cached for the backward pass.

What the hidden layer learns on the spiral

Each hidden unit is max(0, w·x + b), a ramp that is zero on one side of a line in the plane and rises linearly on the other. The output layer adds up these ramps with different weights per class, so each class's logit is a piecewise-linear surface with creases along the hidden units' lines. With 100 units there are enough creases to follow the spiral arms. This "sum of ramps" view explains both why one hidden layer is a universal approximator (enough ramps can approximate any continuous function on a bounded region) and why depth helps (composing layers multiplies the number of linear pieces exponentially, where widening adds them linearly).

Where hand-written backward passes live

Inside custom CUDA and Triton kernels for attention, normalisation, activation functions and losses (FlashAttention's backward pass is hand-derived and recomputes the attention matrix on the fly); in research code for new layers; in numerical libraries that need gradients of solvers; and in interviews. In every case the workflow is the same as this lesson: derive, implement, gradient-check against a reference in float64 on tiny shapes, then compare with the framework's autograd on realistic shapes in the training precision.

Failure modes and symptoms

Silent gradient bugs. The model trains, but worse than expected, or a component learns nothing. A scaled or partially wrong gradient often still decreases the loss. Only a gradient check or an autograd comparison reveals it; make one part of the test suite for every custom operation.

Dead ReLUs. Symptom: a growing fraction of hidden units output zero for every input, and capacity quietly shrinks. Causes: a learning rate spike, large negative biases, poor initialisation. Monitor the fraction of units active on each batch; consider leaky ReLU or GELU variants that keep a small gradient for negative inputs.

Gradients applied to the wrong object. In hand-written NumPy training loops, rebinding a name instead of updating in place, for example writing W1 = W1 - lr * dW1 inside a function that received the weights, leaves the model's stored weights unchanged, so the loss never moves. Update arrays in place or return the new values explicitly, and assert that the weights changed after the first step.

Loss stuck at log C. The output is not learning: zero or tiny learning rate, labels misaligned with inputs, all units dead, or gradients not being applied (updating a copy of the parameters rather than the parameters themselves is a common NumPy bug). Overfit a batch of eight examples first; a working network drives their loss to near zero.

Exploding loss. A learning rate too high for the input scale, or inputs not standardised. Gradient-norm logging shows the spike one step before the loss does.

Mismatch between precisions. A kernel passes its float64 gradient check but disagrees with autograd in bfloat16 by more than expected; usually an accumulation done in low precision. Accumulate sums of products in float32 inside kernels.

A custom kernel that is right on average. A hand-written backward pass that is correct for most shapes but wrong at a boundary (the last partial tile of a blocked kernel, sequence lengths not divisible by the block size, masked positions) passes a gradient check on round shapes and fails in production. Check odd shapes: lengths like 1, 7 and 129, not just 64 and 128.

What to monitor

Per-layer gradient norms and weight norms, the ratio of update size to weight size (around 10⁻³ per step is a common healthy range for SGD-style training), the fraction of active ReLU units, the initial loss against log C, and training and validation loss. For custom operations, keep the gradient-check test in CI.

A cost estimate

For the spiral network, one training step is 300 × (2 × 100 + 100 × 3) ≈ 150,000 multiply-adds forward and about twice that backward: microseconds of arithmetic, dominated by NumPy call overhead. For a transformer with 7 billion parameters on 4 million tokens per step, the same "about three forward passes" rule gives 6 × 7 × 10⁹ × 4 × 10⁶ ≈ 1.7 × 10¹⁷ floating-point operations per step. The ratio of backward to forward cost is the same; only the scale changes.

Work it out

Refactor into modular layers: Linear and ReLU classes with forward(x) and backward(dout), and a Sequential container. Build a three-layer network from them and gradient-check it.

Answer

Each layer caches exactly what its backward rule needs during forward, stores its parameter gradients during backward, and returns the gradient for the layer below. The container runs forward in order and backward in reverse: the whole of backprop in four lines. The check compares every parameter's analytic gradient with central differences of the full loss.

class Linear:
    def __init__(self, d_in, d_out, rng):
        self.params = {"W": rng.normal(0, np.sqrt(2 / d_in), (d_in, d_out)), "b": np.zeros(d_out)}
    def forward(self, x):
        self.x = x                                  # needed for dW
        return x @ self.params["W"] + self.params["b"]
    def backward(self, dout):
        self.grads = {"W": self.x.T @ dout, "b": dout.sum(0)}
        return dout @ self.params["W"].T

class ReLU:
    params = {}
    def forward(self, x):
        self.mask = x > 0
        return x * self.mask
    def backward(self, dout):
        self.grads = {}
        return dout * self.mask

class Sequential:
    def __init__(self, *layers): self.layers = layers
    def forward(self, x):
        for l in self.layers: x = l.forward(x)
        return x
    def backward(self, dout):
        for l in reversed(self.layers): dout = l.backward(dout)
        return dout

def ce_loss(net, X, y):
    z = net.forward(X); z = z - z.max(1, keepdims=True)
    logp = z - np.log(np.exp(z).sum(1, keepdims=True))
    d = np.exp(logp); d[np.arange(len(y)), y] -= 1
    net.backward(d / len(y))
    return -logp[np.arange(len(y)), y].mean()

rng = np.random.default_rng(4)
net = Sequential(Linear(2, 16, rng), ReLU(), Linear(16, 16, rng), ReLU(), Linear(16, 3, rng))
Xs, ys = X[5::20], Y[5::20]                       # away from the ReLU kinks at the origin
def full_loss():
    z = net.forward(Xs); z = z - z.max(1, keepdims=True)
    return -(z[np.arange(len(ys)), ys] - np.log(np.exp(z).sum(1))).mean()
ce_loss(net, Xs, ys)                                # fills every layer's grads
eps, worst = 1e-5, 0.0
analytic = [{k: v.copy() for k, v in l.grads.items()} for l in net.layers]
for li, layer in enumerate(net.layers):
    for k, P in layer.params.items():
        num = np.zeros_like(P)
        for i in np.ndindex(P.shape):
            old = P[i]
            P[i] = old + eps; lp = full_loss()
            P[i] = old - eps; lm = full_loss()
            P[i] = old
            num[i] = (lp - lm) / (2 * eps)
        a = analytic[li][k]
        worst = max(worst, np.linalg.norm(num - a) / (np.linalg.norm(num) + np.linalg.norm(a)))
assert worst < 1e-6

Adding a new layer type now means writing one small class with two methods, and the gradient check covers it automatically. This is the design of early deep-learning frameworks, and mc13 replaces the hand-written backward methods with an automatic graph.
