Train a twenty-layer network with plain linear layers and ReLUs and you will often watch nothing happen: the loss sits flat, or it explodes to NaN in a few steps. Each layer multiplies the scale of its input by some factor, and twenty factors slightly above or below one compound into activations that are enormous or vanishingly small, along with their gradients. In 2015 Ioffe and Szegedy proposed a fix that looked almost too simple: after each layer, rescale every feature to zero mean and unit variance across the current mini-batch, then let the network learn its own scale and shift. Batch Normalization let them match the accuracy of a state-of-the-art ImageNet model with 14 times fewer training steps. Its descendants, LayerNorm and RMSNorm, sit in every transformer block of every large language model.

The companion technique in this lesson, dropout, attacks a different problem, overfitting, by randomly silencing activations during training so the network cannot rely on any single one. Both are "layers that behave differently in training and in inference", and that dual behaviour is the source of a whole family of production bugs: a model evaluated in training mode, whose predictions change with batch composition; running statistics corrupted by a strange batch; dropout left on at inference, making every prediction random.

In an ML coding round these layers test precise thinking about axes, statistics and gradients. Which axis does each normaliser average over, and why does that make LayerNorm right for transformers and BatchNorm right for convolutional networks? What exactly is stored in the running statistics (the unbiased variance, as PyTorch documents, not the biased one used in the forward pass)? Why does BatchNorm's backward pass have two extra terms, and what do they mean geometrically? And how do you compute a variance without catastrophic cancellation? In this lesson's float32 test, the textbook formula mean(x²) − mean(x)² returned a variance of 8 for data whose true variance is 1.

The lesson takes one batch of four numbers through BatchNorm, LayerNorm, RMSNorm and dropout by hand, including the running-statistics update and the backward pass, then writes a loop version, the vectorised layers, a gradient check, an exact comparison with PyTorch's BatchNorm1d (output, running statistics and gradient), LayerNorm and RMSNorm, and the traps: batch size one, the one-pass variance, eval mode. Every number in the hand example is asserted by the solution, so you can check your own arithmetic against running code. The drill derives LayerNorm's backward and shows it is BatchNorm's with the axis changed.

These layers are also where training and serving code most often diverge, so understanding them is as much an operations skill as a modelling one: a large share of 'the model works in the notebook but not in production' incidents for vision models trace back to normalisation statistics or a missing switch to eval mode.

Imagine a classroom where every teacher marks on a different scale: one gives scores out of 10, another out of 1,000, a third mostly negative numbers. Before combining them you would standardise each set of scores: subtract its average, divide by its spread. That is normalisation. In a network, each layer's outputs are the "scores", and standardising them keeps the next layer's inputs in a predictable range no matter how the earlier layers' weights drift during training.

The three normalisers differ only in which numbers they standardise together. Lay a layer's outputs for a mini-batch out as a table: one row per example, one column per feature. BatchNorm standardises each column: for feature j, it takes the mean and variance of that feature across all the examples in the batch. LayerNorm standardises each row: for example i, it takes the mean and variance across that example's own features. RMSNorm also works row by row but skips the mean: it divides each example's features by their root mean square, the square root of the average squared value. All three then multiply by a learned scale γ and (except RMSNorm) add a learned shift β, per feature, so the network can choose whatever scale actually helps.

That choice of axis has big consequences. Because BatchNorm's statistics come from the batch, an example's output depends on which other examples are in its batch. That is fine in training (it even acts as a mild regulariser) but not at inference, where a single image should get the same prediction whatever else is being processed. So BatchNorm keeps running statistics, moving averages of the batch means and variances seen in training, and uses those in eval mode. LayerNorm and RMSNorm never look across examples, so they need no running statistics and behave identically in both modes, which is one reason transformers, which process sequences of varying length and serve one request at a time, use them.

A concrete feel for the numbers helps. If a feature's values in a batch are 1, 2, 3 and 6, BatchNorm turns them into about −1.07, −0.53, 0 and 1.60: centred on zero and spread by one. If instead those four numbers were one example's four features, LayerNorm would produce the same four outputs for that example alone. And if the learned γ and β were 1.87 and 3, the layer would map them straight back to 1, 2, 3 and 6: normalisation never removes the network's ability to represent the original scale, it only makes the default well behaved.

Dropout is simpler and unrelated in purpose. During training, each activation is set to zero with probability p (say 0.1) independently at every step, so the network learns not to depend on any single unit, a bit like training many thinned networks and averaging them. Modern implementations use inverted dropout: survivors are divided by 1 − p, which keeps each activation's expected value unchanged, so at inference dropout is simply switched off.

Where the classroom picture breaks: standardising scores only rescales them, but a normalisation layer also changes the gradients flowing backward, because the mean and spread themselves depend on the inputs. That is why BatchNorm's backward pass is more interesting than its forward pass, and it is where most hand-written implementations go wrong.

1. The problem as it is usually asked

"Implement BatchNorm1d with running statistics and a training-mode backward pass, LayerNorm, RMSNorm and inverted dropout, in NumPy." Clarify: which variance in the forward pass (biased) and in the running average (unbiased, as PyTorch does); the momentum convention (PyTorch's: new = (1 − m)·old + m·batch); ε (10⁻⁵ by default); whether γ and β are learned; and what happens with a batch of one. Then outline: forward with stored intermediates, backward with the two correction terms, eval mode, tests against finite differences and PyTorch.

2. The maths in plain words

BatchNorm, training. For each feature, compute the batch mean and the batch variance (dividing by N). Subtract the mean, divide by the square root of the variance plus a small ε, then multiply by γ and add β. Update the running mean and variance as weighted averages of their old values and this batch's values; for the variance, store the unbiased estimate (dividing by N − 1), because the running value is meant to estimate the population variance.

BatchNorm, eval. Use the running mean and variance in place of the batch's. Now each example's output depends only on itself.

LayerNorm. The same arithmetic, with the mean and variance taken over each example's features instead of over the batch, and no running statistics.

RMSNorm. Divide each example's features by the square root of their mean square (plus ε), then multiply by γ. No mean subtraction, no β. The output is invariant to rescaling the input (multiply x by 3.7 and the output is unchanged), which is the property its authors argue matters, while LayerNorm is also invariant to shifting.

The backward pass in words. If you nudge one input, three things change: its own normalised value (directly), the batch mean (which shifts every normalised value), and the batch variance (which rescales every normalised value). The first effect gives dx̂/σ. The mean effect subtracts the average of dx̂: adding a constant to every input changes nothing, so the gradient can have no "constant" component. The variance effect subtracts x̂ times the average of dx̂·x̂: scaling every deviation changes nothing, so the gradient can have no component along x̂.

3. The equations

BatchNorm (per feature j, over the batch of N)       LayerNorm (per example, over D features)
μ = (1/N) Σᵢ xᵢ                                      μ = (1/D) Σⱼ xⱼ
σ² = (1/N) Σᵢ (xᵢ − μ)²        (biased)              σ² = (1/D) Σⱼ (xⱼ − μ)²
x̂ = (x − μ)/√(σ² + ε)                                x̂ = (x − μ)/√(σ² + ε)
y = γ·x̂ + β                                          y = γ·x̂ + β

running_mean ← (1 − m)·running_mean + m·μ            RMSNorm:  y = γ·x / √(mean(x²) + ε)
running_var  ← (1 − m)·running_var  + m·σ²·N/(N − 1)  (unbiased)
eval: x̂ = (x − running_mean)/√(running_var + ε)

backward (training mode), with dx̂ = dy·γ and σ̃ = √(σ² + ε):
dx = (dx̂ − mean(dx̂) − x̂ · mean(dx̂ · x̂)) / σ̃          means over the same axis as the statistics
dγ = Σ dy · x̂          dβ = Σ dy                      sums over the batch

inverted dropout: mask ~ Bernoulli(1 − p);  y = x · mask / (1 − p) in training;  y = x at inference

The backward formula is the compact form; the original paper derives it through the intermediate gradients for σ² and μ, and a careful expansion gives exactly this. Two consequences are worth stating: the components of dx sum to zero, and dx is orthogonal to x̂ (exactly, if ε is zero). Gradient descent therefore never changes the mean or the scale of a normalised layer's input through this path; those are controlled entirely by β and γ.

4. A worked example by hand

One feature, a batch of four values x = [1, 2, 3, 6], γ = 1, β = 0, ε = 10⁻⁵.

  • Mean and variance. μ = 12/4 = 3. Deviations −2, −1, 0, 3; squared 4, 1, 0, 9; biased variance 14/4 = 3.5; σ̃ = √3.50001 = 1.8708.
  • Normalised values. x̂ = [−2, −1, 0, 3]/1.8708 = [−1.069, −0.535, 0, 1.604]. They have mean 0 and mean square 1.
  • Running statistics, starting from mean 0 and variance 1 with momentum 0.1: running mean = 0.9·0 + 0.1·3 = 0.3; the unbiased variance is 14/3 = 4.667, so running variance = 0.9·1 + 0.1·4.667 = 1.367. After one batch the running statistics are still far from this batch's values, by design; they converge over many batches.
  • Backward with upstream gradient dy = [1, 0, 0, 0] (only the first output matters). dx̂ = dy. mean(dx̂) = 0.25. mean(dx̂·x̂) = −1.069/4 = −0.267. So dx = ([1, 0, 0, 0] − 0.25 − x̂·(−0.267))/1.8708 = [0.248, −0.210, −0.134, 0.095]. Nudging the first input up raises its own output, but it also raises the mean (pulling every output down) and changes the spread; the other inputs' gradients are not zero, because they influence the first output through the statistics. The four values sum to zero and are orthogonal to x̂ (up to the tiny ε effect).
  • LayerNorm of the same four numbers as one example's features gives the same x̂, because the arithmetic is identical with the axis swapped.
  • RMSNorm: mean square = (1 + 4 + 9 + 36)/4 = 12.5, RMS = 3.536, output [0.283, 0.566, 0.849, 1.697]. No centring, so all four stay positive, and their mean square is 1.
  • Inverted dropout with p = 0.5 and the mask [1, 0, 1, 1]: [1, 0, 3, 6]/0.5 = [2, 0, 6, 12]. On average over masks each value keeps its original expectation.
import math
import time
import numpy as np

# The hand-worked example: one feature, a batch of four values.
xb = np.array([1.0, 2.0, 3.0, 6.0])
mu = xb.mean(); var = ((xb - mu) ** 2).mean()              # biased variance, as in training
assert mu == 3.0 and var == 3.5
std = math.sqrt(var + 1e-5)
xhat = (xb - mu) / std
assert np.allclose(xhat, [-1.069, -0.535, 0.0, 1.604], atol=1e-3)
# Running statistics after one step from (0, 1), momentum 0.1, unbiased variance 14/3.
run_mean = 0.9 * 0.0 + 0.1 * mu
run_var = 0.9 * 1.0 + 0.1 * var * 4 / 3
assert math.isclose(run_mean, 0.3) and math.isclose(run_var, 0.9 + 0.1 * 14 / 3)   # 1.3667
# Backward with upstream gradient dy = [1, 0, 0, 0] and gamma = 1.
dy = np.array([1.0, 0.0, 0.0, 0.0])
dx = (dy - dy.mean() - xhat * (dy * xhat).mean()) / std
assert np.allclose(dx, [0.2482, -0.2100, -0.1336, 0.0954], atol=1e-4)
assert abs(dx.sum()) < 1e-12 and abs(dx @ xhat) < 1e-5      # orthogonal to 1 and (up to eps) to xhat
# LayerNorm on the same four numbers as one row gives the same xhat; RMSNorm divides by sqrt(12.5).
rms = math.sqrt((xb ** 2).mean())
assert math.isclose(rms, math.sqrt(12.5))
assert np.allclose(xb / rms, [0.283, 0.566, 0.849, 1.697], atol=1e-3)
# Inverted dropout with p = 0.5 and the mask [1, 0, 1, 1].
assert (xb * np.array([1, 0, 1, 1]) / 0.5).tolist() == [2.0, 0.0, 6.0, 12.0]

Dropout's expectation, by hand

For any one activation x, dropout's output is x/(1 − p) with probability 1 − p and 0 otherwise, so its expected value is (1 − p)·x/(1 − p) = x: the rescaling is exactly what makes the expectation match inference. Its variance, however, is x²·p/(1 − p), equal to x² for p = 0.5: training activations are much noisier than inference ones, which is the regularisation. One subtle consequence is that the next layer's input variance differs between training and inference, which is why combining dropout with BatchNorm placed after it can shift statistics; putting dropout after the normalisation, or using small rates, avoids most of it. The backward pass of dropout is the same mask and scale applied to the upstream gradient, so units that were dropped receive no gradient on that step.

5. The naive implementation

The literal BatchNorm forward pass loops over features, computes each one's mean, then (in a second pass) its variance, then normalises every example:

def batchnorm_naive(x, gamma, beta, eps=1e-5):
    """Training-mode BatchNorm forward with explicit loops over features and examples."""
    N, D = len(x), len(x[0])
    out = [[0.0] * D for _ in range(N)]
    for j in range(D):
        m = sum(x[i][j] for i in range(N)) / N
        v = sum((x[i][j] - m) ** 2 for i in range(N)) / N        # two passes: mean, then variance
        s = math.sqrt(v + eps)
        for i in range(N):
            out[i][j] = gamma[j] * (x[i][j] - m) / s + beta[j]
    return out

It already uses the two-pass variance, which is the important numerical habit. It took 162 ms on a 512 × 256 batch against about 1.2 ms vectorised. Its value is as a reference: it states the per-feature computation with no axes or broadcasting to get wrong.

6. The vectorised layers

class BatchNorm1d:
    def __init__(self, d, momentum=0.1, eps=1e-5):
        self.gamma, self.beta = np.ones(d), np.zeros(d)
        self.running_mean, self.running_var = np.zeros(d), np.ones(d)
        self.momentum, self.eps, self.training = momentum, eps, True

    def forward(self, x):
        if self.training:
            n = len(x)
            if n < 2:                                        # PyTorch raises too: variance is 0
                raise ValueError("BatchNorm needs more than 1 value per feature in training")
            mu, var = x.mean(0), x.var(0)                    # statistics of this batch (biased var)
            self.running_mean = (1 - self.momentum) * self.running_mean + self.momentum * mu
            self.running_var = (1 - self.momentum) * self.running_var + self.momentum * var * n / (n - 1)
        else:
            mu, var = self.running_mean, self.running_var    # frozen statistics at inference
        self.std = np.sqrt(var + self.eps)
        self.xhat = (x - mu) / self.std
        return self.gamma * self.xhat + self.beta

    def backward(self, dy):
        """Training-mode backward. mu and var depend on every row, hence the two correction terms."""
        self.dgamma, self.dbeta = (dy * self.xhat).sum(0), dy.sum(0)
        dxhat = dy * self.gamma
        return (dxhat - dxhat.mean(0) - self.xhat * (dxhat * self.xhat).mean(0)) / self.std

def layer_norm(x, gamma, beta, eps=1e-5):
    mu = x.mean(-1, keepdims=True)
    var = x.var(-1, keepdims=True)
    return gamma * (x - mu) / np.sqrt(var + eps) + beta

def rms_norm(x, gamma, eps=1e-6):
    return gamma * x / np.sqrt((x * x).mean(-1, keepdims=True) + eps)

def dropout(x, p, training, rng):
    if not training or p == 0.0:
        return x
    mask = rng.random(x.shape) >= p
    return x * mask / (1.0 - p)              # inverted: rescale now so inference is a no-op

BatchNorm1d. In training mode, x.mean(0) and x.var(0) compute per-feature statistics over the batch axis (NumPy's var divides by N, the biased estimator, matching the forward pass). The running variance stores var · n/(n − 1), the unbiased estimate, which is what PyTorch's documentation specifies. A batch of one raises an error, as PyTorch does, because its variance is zero and its unbiased variance undefined. The forward pass stores σ̃ and x̂, which is all the backward pass needs. In eval mode, the running statistics replace the batch's.

The backward pass is the compact formula: dγ and dβ sum over the batch; dx̂ = dy·γ; and the input gradient subtracts the batch mean of dx̂ and x̂ times the batch mean of dx̂·x̂, then divides by σ̃. Three array operations, no loops.

layer_norm and rms_norm take statistics over the last axis with keepdims=True, so they work for any leading shape (batch, sequence, heads).

dropout draws a uniform random array, keeps entries with value at least p (probability 1 − p), and divides by 1 − p. In eval mode, or with p = 0, it returns its input untouched.

7. Testing it

The tests check: the class reproduces the hand example's normalised values, running statistics and input gradient, and LayerNorm and RMSNorm reproduce theirs; the naive loops equal the vectorised forward pass with non-trivial γ and β, and a fresh layer's output has zero mean and unit variance per feature; the backward pass matches central differences with a random upstream gradient and random γ; PyTorch's BatchNorm1d in float64 gives the same output, the same running mean and variance after one step (confirming the unbiased running variance) and the same input gradient to 10⁻¹⁰, and its functional layer_norm and rms_norm agree too; running statistics converge to the data's true mean and variance (5 and 4) over 300 batches and eval mode uses them; a batch of one is refused; LayerNorm's output for an example does not depend on the rest of the batch; RMSNorm is invariant to scaling the input by 3.7; the one-pass variance trap; and dropout's expectation and eval-mode identity. Finally the timing.

Comparing running statistics with PyTorch after a single step is a targeted test: it is the only place the biased/unbiased distinction shows up in the forward pass. An implementation that stores the biased variance passes every output and gradient check and still drifts from PyTorch's inference behaviour, exactly the kind of difference that matters when porting a model.

8. Numerical stability traps

Trap 1: the one-pass variance. mean(x²) − mean(x)² is algebraically correct and numerically dangerous. In the test, 1,000 float32 values with mean 10,000 and standard deviation 1: mean(x²) is about 10⁸, representable only to within about 8 in float32, so subtracting mean(x)² (also about 10⁸) leaves rounding noise. The result was 8.0; the two-pass formula gave 1.002. Worse, the one-pass value can come out negative, and √(negative + ε) is NaN. Subtract the mean first, or use Welford's algorithm when you can only stream.

Trap 2: ε and small variances. A feature that is constant in a batch has σ² = 0, and without ε the division is by zero. With ε = 10⁻⁵, the output is 0 for that feature and the gain on a nearly constant feature is bounded by about 316 (1/√ε). In half precision, compute statistics in float32: 10⁻⁵ is representable in float16 only as a subnormal with little precision.

Trap 3: batch size one. In training mode the variance is zero, the normalised value is zero for every feature, and the unbiased variance divides by zero. PyTorch raises an error ("Expected more than 1 value per channel when training"); so does this class.

Trap 4: dropout's scale. Forgetting the 1/(1 − p) makes activations smaller in training than at inference by a factor of 1 − p; the network then sees systematically larger inputs at test time. Applying the scale at inference instead (the original formulation) works only if every inference path remembers to do it.

Trap 5: random state. Dropout masks must differ between steps and between examples; reusing one mask for the batch, or seeding the generator each step with the same value, removes most of the regularising effect. In distributed training, each worker needs a different stream.

Trap 6: momentum convention. PyTorch's momentum = 0.1 means the new batch gets weight 0.1. Some frameworks (Keras) use the opposite convention, momentum 0.99 meaning the old value keeps weight 0.99. Porting with the wrong reading makes running statistics either frozen or jittery.

9. Edge cases worth naming

Convolutional BatchNorm (BatchNorm2d) computes statistics per channel over the batch and both spatial dimensions, so N becomes N·H·W in every formula; the code generalises by reshaping to (N·H·W, C). Sequence data with padding must exclude padded positions from LayerNorm's statistics only if normalising across positions, which LayerNorm does not, but BatchNorm over sequences would. Fine-tuning a pre-trained network on a small dataset often freezes BatchNorm's running statistics (keeping the layer in eval mode) because the new batches are too small or too different to estimate them well. And zero-initialising the last γ of each residual block makes the block start as an identity, a known trick for training very deep residual networks.

Shapes in real models

In a transformer, activations have shape (batch, sequence length, hidden size), for example (8, 2,048, 4,096). LayerNorm and RMSNorm reduce over the last axis only, so each of the 16,384 token vectors is normalised on its own, and the learned scale (and shift) have shape (4,096,), broadcast over the first two axes. That is why the functions here use axis=-1 with keepdims=True: the same code works for (N, d), (B, T, d) or (B, heads, T, d). In a convolutional network, activations are (batch, channels, height, width), and BatchNorm2d reduces over batch, height and width, keeping one mean, variance, scale and shift per channel, so a 64-channel layer has 128 learned parameters and 128 running statistics regardless of image size. Getting the reduction axes wrong is the most common bug when porting a normalisation layer between frameworks or layouts, and a shape assertion on the statistics (one per channel, or one per token) catches it immediately.

10. Complexity

All three normalisers are O(N·D) in time and memory: a few passes over the activations to compute statistics and apply them, and a similar number in the backward pass. They do almost no arithmetic per byte moved, so on GPUs they are memory-bandwidth bound, which is why fused kernels (one pass for statistics, one for the output) matter and why RMSNorm's saved reduction translates into real time. Dropout is O(N·D) too, plus random-number generation; storing the mask for the backward pass costs a bit or a byte per activation. The parameters are tiny: 2·D for BatchNorm and LayerNorm, D for RMSNorm.

11. Talking through the design

In the interview: draw the batch-by-features table and the axis each normaliser uses; write the forward pass with ε, γ, β; explain running statistics and eval mode, with the unbiased variance; write the compact backward pass and explain its two terms as "no gradient along the directions the normalisation removes"; mention the two-pass variance; then dropout with the inverted scale. If time allows, fold a BatchNorm into the previous layer on the whiteboard; it shows you understand that inference-mode normalisation is just an affine map, and it is the transformation every deployment toolchain applies. Close with where each is used: BatchNorm in convolutional networks, LayerNorm and RMSNorm in transformers, dropout mostly in fine-tuning and smaller models.

What BatchNorm actually does for optimisation

The original paper attributed BatchNorm's success to reducing "internal covariate shift", the drifting distribution of each layer's inputs. Later work (Santurkar and colleagues, 2018) found that BatchNorm does not reduce that shift much but makes the loss surface smoother, so gradients are more predictive and larger learning rates are safe. The backward formula shows one mechanism directly: because the input gradient has no component along x̂, gradient steps cannot grow the pre-normalisation activations' scale, which removes a whole class of explosions; and the effective learning rate of the preceding weights shrinks as those weights grow, a self-stabilising effect.

Why transformers use LayerNorm and then RMSNorm

Language models process sequences of different lengths, use small per-device batches of long sequences, and serve requests one at a time. Batch statistics are unstable across padded positions and meaningless at inference, so per-token normalisation over the hidden dimension (LayerNorm) was the natural choice. Zhang and Sennrich then argued that LayerNorm's re-centering is dispensable and its re-scaling does the work; RMSNorm removes the mean computation and the bias, matching LayerNorm's quality while reducing running time by 7% to 64% in their experiments. Llama, Mistral, Gemma and most recent open models use RMSNorm, in pre-norm position, plus a final RMSNorm before the output projection.

Pre-norm and the residual stream

In a post-norm block, y = Norm(x + F(x)), every layer's output is renormalised, and gradients to early layers pass through every normalisation, which in deep stacks makes the earliest updates large and unstable without learning-rate warmup. In a pre-norm block, y = x + F(Norm(x)), the residual stream x passes through untouched, so gradients flow straight back along it. Xiong and colleagues showed pre-norm transformers train well without warmup. The cost is that the residual stream's magnitude grows with depth, which is one reason a final normalisation is added and why some recipes scale residual branches.

GroupNorm, InstanceNorm and the batch-size problem

When per-device batches are small (detection and segmentation with high-resolution images often fit two images per GPU), BatchNorm's statistics are too noisy. Group Normalization splits channels into groups and normalises each example's group over its channels and spatial positions, independent of the batch; InstanceNorm normalises each channel of each example separately (popular in style transfer). Synchronised BatchNorm keeps BatchNorm but all-reduces statistics across devices. Diffusion-model U-Nets typically use GroupNorm for this reason.

Normalising inside attention, and normalisation-free networks

Normalisation keeps appearing in new places. Several recent LLMs apply RMSNorm to the query and key vectors before the attention dot product (QK-norm), which stops attention logits from growing without bound and improves training stability at scale. In the other direction, normalisation-free residual networks replace BatchNorm with careful initialisation and scaled residual branches (plus gradient clipping), matching its accuracy without batch dependence. Both make the same point as this lesson: what normalisation buys is control over activation and gradient scale, and that control can be placed wherever the scale is at risk.

Dropout as approximate ensembling

Each training step with dropout trains a different "thinned" network sharing weights with all others; inference with all units active and the inverted scaling approximates averaging those networks' predictions. Srivastava and colleagues' paper reported large improvements on vision, speech and text benchmarks of the time. Monte Carlo dropout keeps dropout active at inference and averages several stochastic passes to estimate predictive uncertainty. In large-scale pre-training, dropout is usually 0, because a single pass over trillions of tokens does not overfit and dropout slows learning; in fine-tuning on small datasets, rates of 0.05 to 0.1 are common.

RMSNorm's backward pass

With r = √(mean(x²) + ε) and x̂ = x/r, the output is γ·x̂. Nudging one input changes its own normalised value and, through r, rescales every value, but there is no mean to shift. The input gradient is therefore (dx̂ − x̂·mean(dx̂·x̂))/r with dx̂ = dy·γ: the BatchNorm and LayerNorm formula without the mean-subtraction term. It is orthogonal to x̂ (gradient steps do not change the input's overall scale through this path) but, unlike LayerNorm's, it does not sum to zero, because RMSNorm is not invariant to shifting the input. One fewer reduction in both directions is part of why fused RMSNorm kernels are faster.

Welford's algorithm and parallel statistics

To compute a mean and variance in one pass without cancellation, Welford's method keeps a count n, a mean, and M2, the sum of squared deviations from the current mean. Each new value x updates: δ = x − mean; mean += δ/n; M2 += δ·(x − mean); the variance is M2/n. Two partial results (n_a, mean_a, M2_a) and (n_b, mean_b, M2_b) combine as δ = mean_b − mean_a; M2 = M2_a + M2_b + δ²·n_a·n_b/(n_a + n_b). GPU normalisation kernels use exactly this: each thread block computes Welford statistics on its slice, and the partial results are merged, giving one-pass speed with two-pass accuracy.

Where these layers run

BatchNorm in convolutional backbones (ResNets, EfficientNets), usually folded into the preceding convolution's weights for inference; LayerNorm in encoder transformers and many vision transformers; RMSNorm in most recent LLMs, typically as fused kernels; GroupNorm in diffusion U-Nets; dropout in fine-tuning and in smaller supervised models. The arithmetic is trivial; the bugs are about modes, statistics and precision.

Failure modes and symptoms

Evaluation in training mode. Validation metrics are noisy and change with batch size; single-example predictions are garbage (BatchNorm) or random (dropout). Cause: model.train() left on. Fix: model.eval() (and torch.no_grad()) for every evaluation and serving path, with a test that runs the same input twice and expects identical outputs.

Batch-size-dependent quality. A vision model trained with batches of 256 is fine-tuned or served with batches of 4 in training mode (for example during test-time adaptation), and accuracy collapses. Small-batch statistics are noisy estimates of the population ones; the error in the batch mean alone scales like 1/√N. Keep BatchNorm frozen, use eval mode, or switch architectures to a batch-independent normaliser when small batches are unavoidable.

Corrupted running statistics. Accuracy drops after a few odd batches, or after evaluating on out-of-distribution data in training mode. Cause: running averages updated by unrepresentative data. Fix: recompute statistics over a clean pass of training data in training mode with momentum set for a cumulative average, then switch back.

Train/test mismatch from BatchNorm in fine-tuning. A pre-trained network fine-tuned with small batches gets worse. Fix: freeze BatchNorm layers (eval mode, no updates to γ, β, or the statistics), or replace with GroupNorm.

NaN from normalisation in low precision. Variance computed in float16 underflows or cancels, giving NaN after the square root. Fix: compute statistics in float32 inside the kernel, which fused implementations do.

Folding errors at deployment. Inference engines fold BatchNorm into the previous convolution: w' = w·γ/σ̃, b' = (b − μ)·γ/σ̃ + β. Folding with the wrong statistics (batch rather than running) or the wrong ε produces a small, persistent accuracy loss that is hard to trace. Compare the folded and unfolded model's outputs on a fixed input before shipping, and keep that comparison as a regression test. It takes seconds to run.

Folding BatchNorm, worked

At inference BatchNorm is a fixed affine map per feature, so it can be merged into the preceding linear or convolutional layer. Take the hand example's feature after training, with running mean 3, running variance 3.5, γ = 2 and β = 1, preceded by a linear unit z = 0.5·u + 0.2. Then σ̃ = √3.50001 ≈ 1.871, and the folded unit is z′ = (2/1.871)·0.5·u + (2/1.871)·(0.2 − 3) + 1 = 0.535·u − 1.993. One multiply-add replaces a multiply-add, a subtraction, a division, a multiply and an add, and the output is identical to rounding error. Inference engines do this automatically; doing it once by hand is the best way to check that a deployment tool used the running statistics and the right ε.

What to monitor

The running mean and variance of BatchNorm layers over training (sudden jumps flag bad batches), the magnitude of γ per layer, activation statistics before and after normalisation, and the output difference between two identical inference calls (catches dropout or training-mode leaks).

A cost estimate

In a 7-billion-parameter transformer with hidden size 4,096 and 32 layers, each token passes through about 65 RMSNorms of 4,096 values: roughly 270,000 values read, squared, summed, scaled and written, negligible arithmetic next to the layer's 14 billion floating-point operations, but each norm is a separate trip through memory. Unfused, normalisation and other element-wise operations can take a noticeable share of step time; fused into adjacent kernels, they nearly disappear. That memory traffic, not the arithmetic, is what RMSNorm's simplification saves.

The reference for this problem

Ioffe and Szegedy's "Batch Normalization: Accelerating Deep Network Training by Reducing Internal Covariate Shift" (arXiv 1502.03167) is the reference for the core layer. Its abstract reports that applied to a state-of-the-art image classification model, BatchNorm "achieves the same accuracy with 14 times fewer training steps", and that an ensemble reached "4.9% top-5 validation error (and 4.8% test error)" on ImageNet, exceeding human raters. Its inference procedure uses the population statistics with the unbiased variance correction m/(m − 1), which PyTorch implements as documented for BatchNorm1d: "At train time in the forward pass, the variance is calculated via the biased estimator ... However, the value stored in the moving average of the variance is calculated via the unbiased estimator", with defaults ε = 10⁻⁵ and momentum 0.1 and the update rule new = (1 − momentum)·old + momentum·observed. This lesson's tests match PyTorch's output, running statistics and gradient. For RMSNorm, Zhang and Sennrich's paper (arXiv 1910.07467) hypothesises that "re-centering invariance in LayerNorm is dispensable" and reports comparable performance with running time reduced "by 7%∼64% on different models".

Work it out

Write the LayerNorm backward pass for input (N, d) and gradient-check it. How does it relate to the BatchNorm backward above?

Answer

It is the same formula with the axis changed: LayerNorm normalises each row over its d features, so the mean-correction terms are taken over the last axis instead of the batch axis.

def layer_norm_backward(x, gamma, dy, eps=1e-5):
    mu = x.mean(-1, keepdims=True)
    std = np.sqrt(x.var(-1, keepdims=True) + eps)
    xhat = (x - mu) / std
    dxhat = dy * gamma
    dx = (dxhat - dxhat.mean(-1, keepdims=True) - xhat * (dxhat * xhat).mean(-1, keepdims=True)) / std
    return dx, (dy * xhat).sum(0), dy.sum(0)            # dx, dgamma, dbeta

X = rng.normal(size=(3, 6)); gam, bet = rng.normal(size=6), rng.normal(size=6); upl = rng.normal(size=(3, 6))
dxl, dgam, dbet = layer_norm_backward(X, gam, upl)
numl = np.zeros_like(X)
for i in np.ndindex(X.shape):
    xp, xm = X.copy(), X.copy(); xp[i] += 1e-6; xm[i] -= 1e-6
    numl[i] = ((layer_norm(xp, gam, bet) - layer_norm(xm, gam, bet)) * upl).sum() / 2e-6
assert np.allclose(dxl, numl, atol=1e-6)

Reading the formula: the gradient reaching x̂ is projected so that it has zero mean and is orthogonal to x̂ itself, the two directions in which the normalisation removes any effect of the input. That is why normalised layers are insensitive to the scale of their inputs, and why the gradient never pushes the pre-normalisation activations to grow. RMSNorm's backward keeps only the second projection, because it never subtracted the mean.
