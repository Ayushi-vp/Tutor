A food-delivery company predicts how many minutes each order will take, from features such as distance, restaurant, time of day, weather and the courier's recent speed. A linear model misses the interactions (rain matters much more at dinner time), and a single decision tree is too coarse and too unstable. What most teams ship for problems like this, tabular data with a few dozen to a few thousand features, is a gradient-boosted tree ensemble: XGBoost, LightGBM or CatBoost. When XGBoost's authors surveyed the winning solutions published on Kaggle's blog during 2015, 17 of the 29 used it, more than used deep neural networks.

The idea behind it is simple and surprisingly deep. Start with a crude prediction (the average delivery time). Look at the errors. Fit a small tree that predicts those errors, and add a fraction of it to the model. Look at the new errors, fit another small tree, add a fraction, and repeat a few hundred times. Each tree on its own is weak, but every one is aimed squarely at what the model still gets wrong. The reason this works, and the reason it extends to any loss you can differentiate, is that it is gradient descent, carried out on the predictions themselves rather than on a fixed set of weights.

In an ML coding round this problem tests whether you understand that link. Can you say what each tree is fitted to, and why that is a gradient? Can you write the loop so that the training loss provably never goes up, and explain why the validation loss eventually does? Can you explain the learning rate, and why lr = 1 is a bad idea? (In this lesson's test, lr = 1 hit its best validation error of 0.049 after 61 trees and then got worse, while lr = 0.1 kept improving to 0.018.) And can you go one step further, to losses other than squared error, where fitting the gradient gives the tree's shape but not its leaf values?

The lesson builds it from the ground up: the idea in plain words, then the equations of functional gradient descent, then one complete boosting round by hand on four points. It writes a naive booster in plain Python lists, the vectorised version using mc5's cumulative-sum regression tree, and tests that check the hand numbers, the agreement of the two, the pseudo-residuals as true negative gradients, monotone training loss, shrinkage and early stopping, and robustness to outliers with absolute-loss boosting. It closes with the second-order leaf weights and split gain that XGBoost derives, and what changes at the scale of a hundred million rows.

Imagine a team of estimators guessing a delivery time, each allowed to speak only once and only in a simple way. The first says "about 32 minutes for everyone". The second looks only at the first one's mistakes and says "add 6 minutes if the distance is over 4 km, subtract 3 otherwise". The third looks at the mistakes remaining after the first two and says "add 4 minutes if it is raining at dinner time". Each estimator is crude, but each one is talking about what the team still gets wrong, so the sum gets steadily better. That is boosting: a strong model built as a sum of many weak learners, each fitted to the current errors.

The weak learners here are small regression trees from mc5: a handful of yes/no questions ending in leaves that each output a number. The model after m trees is F(x) = F₀ + η·(tree₁(x) + tree₂(x) + … + tree_m(x)), where F₀ is the starting constant and η (eta) is the learning rate, a number like 0.1 that scales each tree down before it is added. Without that scaling, each tree would try to correct all of the remaining error at once, including the noise, and the model would lock in its early guesses. With it, each tree takes a small step, and later trees can revise.

Why call it gradient boosting? Think of the training predictions as a list of numbers, one per example. The loss (say, mean squared error) is a function of that list. Its gradient tells you, for each example, which way to move that example's prediction to reduce the loss: for squared error, the direction is exactly the residual, "actual minus predicted". So "fit a tree to the residuals and add a bit of it" is "take a gradient step on the predictions", except that the step is expressed as a tree, so it also tells you how to move predictions for new inputs the model has never seen. For a different loss, you fit the tree to that loss's gradient instead, called the pseudo-residual, and the same machinery works.

A quick reminder of the building block, since everything rests on it. A regression tree (mc5) splits the rows with yes/no questions chosen to reduce squared error, and each leaf outputs the average target of the training rows that reached it. A depth-3 tree has at most eight leaves, so it can only say eight different numbers: it is a coarse, step-shaped function. That coarseness is the point. A tree too small to memorise the residuals is forced to find the broad patterns in them, and those patterns are what carry over to new data.

Two things make boosting different from the forest of trees in ml10. A random forest grows deep trees independently and averages them, which cancels their noise; boosting grows shallow trees one after another, each depending on all the previous ones, which steadily reduces the model's bias. And because boosting keeps chasing the training errors, it will eventually start fitting noise, so unlike a forest, more trees is not always better: you watch a validation set and stop at the best point.

Where the "team of estimators" picture breaks: real boosting uses hundreds or thousands of trees, each typically with 8 to 64 leaves, and the questions each tree asks are chosen automatically by the split search, not by a person deciding what to look at.

May you reuse a regression tree, or must you write it too? Is there a validation set for early stopping? Do they want row subsampling? Then outline: the initial constant, the loop of pseudo-residuals → tree → shrunken update, a vectorised tree, then tests.

2. The maths in plain words

Gradient descent on a model with weights changes the weights a little in the direction that most reduces the loss. Boosting changes the predictions instead. Imagine the model's predictions on the n training examples as a point in n-dimensional space, and the targets as another point. The loss measures the distance between them in some sense. Its gradient with respect to the predictions has one component per example, saying how the loss would change if that one prediction moved. Moving every prediction a little against its component is a gradient step.

The trouble is that this step is only defined for the training examples, and moving training predictions directly would just memorise them. So boosting approximates the step with a function: fit a small regression tree whose outputs on the training examples are as close as possible (in squared error) to the negative gradient. A small tree cannot match every example individually, so it captures the broad pattern ("predictions for long distances are too low") and applies it to new examples too. Then take a small step along that tree. Repeat.

For squared loss the negative gradient is just the residual, so "fit a tree to the residuals" is literally the gradient step. For absolute loss, the negative gradient is the sign of the residual (+1 if under-predicted, −1 if over-predicted), so the tree learns which examples are under- and over-predicted, regardless of by how much, which is exactly why it ignores outliers. For log-loss in classification, it is y − p, the same expression mc2 derived.

3. The equations

model after m rounds:   F_m(x) = F₀ + η · Σ_{k=1..m} h_k(x)

initial constant:       F₀ = argmin_c Σᵢ L(yᵢ, c)        mean for squared, median for absolute

round m:
  pseudo-residuals      rᵢ = − ∂L(yᵢ, F)/∂F  at F = F_{m−1}(xᵢ)
  fit a tree            h_m ≈ r   (least squares, depth-limited)
  (optionally) set each leaf j to  γ_j = argmin_γ Σ_{i ∈ leaf j} L(yᵢ, F_{m−1}(xᵢ) + γ)
  update                F_m = F_{m−1} + η · h_m

squared loss  L = ½(y − F)²   ⟹  r = y − F             leaf value = mean residual (already optimal)
absolute loss L = |y − F|     ⟹  r = sign(y − F)       leaf value = median residual
log-loss      L = log(1+e^F) − yF  ⟹  r = y − σ(F)      leaf value ≈ Σr / Σσ(F)(1 − σ(F))  (Newton step)

The line "set each leaf to the loss-optimal constant" is the part people forget. The tree is fitted by least squares to the pseudo-residuals, which gives a good partition of the examples. For squared loss the least-squares leaf values are already the optimal step. For other losses they are not, and Friedman's 2001 paper re-solves each leaf for the actual loss: the median of the residuals for absolute loss (his LAD_TreeBoost), and a Newton step for log-loss.

A useful property for testing: with squared loss, full-batch fitting, leaf means and 0 < η ≤ 1, the training loss never increases. The tree's leaf means are the least-squares fit to the residuals, so adding η times them reduces the squared residuals within each leaf by a factor that is at least (1 − η)² for the fitted part, never worse.

Why the training loss cannot go up (squared loss)

The monotone-loss test is not a heuristic; it follows from how the tree is fitted. Fix one leaf, and let its training rows have residuals r₁ … r_k with mean r̄. Before the update their squared error is Σ rᵢ². The tree adds η·r̄ to each prediction, so the new residuals are rᵢ − η·r̄, and their squared error is Σ rᵢ² − 2η·r̄·Σ rᵢ + η²·k·r̄² = Σ rᵢ² − k·r̄²·(2η − η²). For 0 < η ≤ 1, the factor 2η − η² is positive, so every leaf's squared error falls by k·r̄²·η(2 − η), or stays the same if r̄ = 0. Adding up the leaves, the total cannot increase. The same algebra shows what goes wrong at η = 2 (no change at all) and beyond (the loss rises): the step overshoots the leaf mean by more than it started. It also explains the hand example's numbers: the right leaf (k = 1, r̄ = 3) falls by 9 × 0.75 = 6.75 and the left (k = 3, r̄ = −1) by 3 × 0.75 = 2.25, from a total of 14 to 5, which is the MSE drop from 3.5 to 1.25.

4. A worked example by hand: one boosting round

Four points: x = 1, 2, 3, 4, y = 1, 3, 2, 6. Stumps (depth-1 trees), learning rate 0.5, squared loss.

  • Initial constant. F₀ = mean(y) = 12/4 = 3. Training MSE: (4 + 0 + 1 + 9)/4 = 3.5.
  • Pseudo-residuals. r = y − F₀ = −2, 0, −1, 3.
  • Fit the stump to r. Three candidate thresholds, each scored by the SSE of the residuals around their side's mean:
    • 1.5: left {−2} SSE 0; right {0, −1, 3} mean 0.667, SSE 0.444 + 2.778 + 5.444 = 8.667. Total 8.667.
    • 2.5: left {−2, 0} mean −1, SSE 2; right {−1, 3} mean 1, SSE 8. Total 10.
    • 3.5: left {−2, 0, −1} mean −1, SSE 1 + 1 + 0 = 2; right {3} SSE 0. Total 2.
    The best split is 3.5, with leaf values −1 (left) and 3 (right).
  • Shrunken update. F₁ = F₀ + 0.5 × leaf: 3 − 0.5 = 2.5 for x = 1, 2, 3 and 3 + 1.5 = 4.5 for x = 4.
  • New loss. Residuals −1.5, 0.5, −0.5, 1.5, MSE (2.25 + 0.25 + 0.25 + 2.25)/4 = 1.25.

The point at x = 4, badly under-predicted at first, got the biggest correction; the first three moved down together because one stump cannot tell them apart. The learning rate kept every move to half of what the stump suggested. Continue with the new residuals and, in the code's run, the training MSE falls to 0.69, 0.30, 0.20, 0.15 over the next rounds and 0.096 after eight. The first solution block asserts the round-one numbers.

import time
import numpy as np

# The hand-worked example: four points, depth-1 trees (stumps), learning rate 0.5.
x_hand = np.array([1.0, 2.0, 3.0, 4.0])
y_hand = np.array([1.0, 3.0, 2.0, 6.0])

F0 = y_hand.mean()                                       # best constant under squared loss
assert F0 == 3.0
r = y_hand - F0                                          # residual = negative gradient
assert r.tolist() == [-2.0, 0.0, -1.0, 3.0]

def sse(v):
    return ((v - v.mean()) ** 2).sum() if len(v) else 0.0
scores = {t: sse(r[x_hand <= t]) + sse(r[x_hand > t]) for t in (1.5, 2.5, 3.5)}
assert np.allclose([scores[1.5], scores[2.5], scores[3.5]], [26 / 3, 10.0, 2.0])
leaf_L, leaf_R = r[x_hand <= 3.5].mean(), r[x_hand > 3.5].mean()
assert (leaf_L, leaf_R) == (-1.0, 3.0)
F1 = F0 + 0.5 * np.where(x_hand <= 3.5, leaf_L, leaf_R)
assert F1.tolist() == [2.5, 2.5, 2.5, 4.5]
assert np.mean((y_hand - F0) ** 2) == 3.5 and np.mean((y_hand - F1) ** 2) == 1.25

5. The naive booster

The naive version uses Python lists throughout: a stump finder that, for each threshold, splits the residuals into two lists and recomputes both means and SSEs from scratch, and a boosting loop that updates predictions element by element. It handles one feature and stumps only, which is enough to serve as a reference for the vectorised code.

def fit_stump_naive(x, g):
    """Best single split of one feature by recomputing both sides' SSE for every threshold."""
    xs = sorted(set(x))
    best = (sum((v - sum(g) / len(g)) ** 2 for v in g), None, None, None)
    for a, b in zip(xs, xs[1:]):
        t = (a + b) / 2
        L = [gi for xi, gi in zip(x, g) if xi <= t]
        R = [gi for xi, gi in zip(x, g) if xi > t]
        mL, mR = sum(L) / len(L), sum(R) / len(R)
        s = sum((v - mL) ** 2 for v in L) + sum((v - mR) ** 2 for v in R)
        if s < best[0] - 1e-12:
            best = (s, t, mL, mR)
    return best[1:]

def boost_naive(x, y, n_trees, lr):
    """Squared-loss boosting of stumps on one feature, all in Python lists."""
    F = [sum(y) / len(y)] * len(y)
    for _ in range(n_trees):
        g = [yi - fi for yi, fi in zip(y, F)]
        t, mL, mR = fit_stump_naive(x, g)
        if t is None:
            break
        F = [fi + lr * (mL if xi <= t else mR) for xi, fi in zip(x, F)]
    return F

Its stump search is O(n²) per round: up to n − 1 thresholds, each with an O(n) recount. On 2,000 points one stump took about 2 seconds in the test.

6. The vectorised booster

def fit_tree(X, g, depth, min_leaf=5):
    """Least-squares regression tree on targets g; nodes are tuples."""
    n = len(g)
    if depth == 0 or n < 2 * min_leaf:
        return ("leaf", g.mean())
    best = (np.inf, None, None)
    for f in range(X.shape[1]):
        o = np.argsort(X[:, f], kind="stable")
        xs, gs = X[o, f], g[o] - g.mean()                # centre: avoids cancellation in Σg² − (Σg)²/n
        s, s2 = np.cumsum(gs), np.cumsum(gs * gs)
        nl = np.arange(1, n); nr = n - nl
        sse_ = (s2[:-1] - s[:-1] ** 2 / nl) + ((s2[-1] - s2[:-1]) - (s[-1] - s[:-1]) ** 2 / nr)
        sse_[(xs[1:] == xs[:-1]) | (nl < min_leaf) | (nr < min_leaf)] = np.inf
        i = int(sse_.argmin())
        if sse_[i] < best[0]:
            best = (sse_[i], f, (xs[i] + xs[i + 1]) / 2)
    if best[1] is None:
        return ("leaf", g.mean())
    _, f, t = best
    m = X[:, f] <= t
    return ("split", f, t, fit_tree(X[m], g[m], depth - 1, min_leaf),
                           fit_tree(X[~m], g[~m], depth - 1, min_leaf))

def predict_tree(node, X):
    if node[0] == "leaf":
        return np.full(len(X), node[1])
    _, f, t, left, right = node
    m = X[:, f] <= t
    out = np.empty(len(X))
    out[m], out[~m] = predict_tree(left, X[m]), predict_tree(right, X[~m])
    return out

class GradientBoostingRegressor:
    """Friedman's gradient boosting with regression trees.
    loss='squared': fit trees to residuals y − F, leaves are residual means.
    loss='absolute': fit trees to sign(y − F), then set each leaf to the median residual (LAD_TreeBoost)."""

    def __init__(self, n_trees=200, lr=0.1, depth=3, subsample=1.0, loss="squared", min_leaf=5, seed=0):
        self.n_trees, self.lr, self.depth, self.subsample = n_trees, lr, depth, subsample
        self.loss, self.min_leaf, self.seed = loss, min_leaf, seed

    def _leaf_values(self, tree, X, resid):
        """Rebuild the tree with each leaf's value set to the loss-optimal constant step."""
        if tree[0] == "leaf":
            if len(resid) == 0:
                return tree
            return ("leaf", np.median(resid) if self.loss == "absolute" else resid.mean())
        _, f, t, l, r = tree
        m = X[:, f] <= t
        return ("split", f, t, self._leaf_values(l, X[m], resid[m]), self._leaf_values(r, X[~m], resid[~m]))

    def fit(self, X, y, X_val=None, y_val=None):
        X, y = np.asarray(X, float), np.asarray(y, float)
        rng = np.random.default_rng(self.seed)
        self.f0 = np.median(y) if self.loss == "absolute" else y.mean()
        F = np.full(len(y), self.f0)
        self.trees, self.train_loss, self.val_loss = [], [], []
        F_val = None if X_val is None else np.full(len(X_val), self.f0)
        for _ in range(self.n_trees):
            resid = y - F
            g = np.sign(resid) if self.loss == "absolute" else resid      # negative gradient
            rows = rng.random(len(y)) < self.subsample if self.subsample < 1 else np.ones(len(y), bool)
            tree = fit_tree(X[rows], g[rows], self.depth, self.min_leaf)
            if self.loss == "absolute":
                tree = self._leaf_values(tree, X[rows], resid[rows])
            F += self.lr * predict_tree(tree, X)                            # shrunken step in function space
            self.trees.append(tree)
            self.train_loss.append(self._loss(y, F))
            if F_val is not None:
                F_val += self.lr * predict_tree(tree, X_val)
                self.val_loss.append(self._loss(y_val, F_val))
        return self

    def _loss(self, y, F):
        return np.mean(np.abs(y - F)) if self.loss == "absolute" else np.mean((y - F) ** 2)

    def predict(self, X, n_trees=None):
        X = np.asarray(X, float)
        return self.f0 + self.lr * sum(predict_tree(t, X) for t in self.trees[:n_trees])

The tree. fit_tree is mc5's regression-tree split search: sort each feature, take cumulative sums of the targets and their squares, and read off every cut's left and right SSE from Σg² − (Σg)²/n, choosing the smallest. One improvement over mc5's drill: the targets are centred at each node before the cumulative sums. The SSE is unchanged by subtracting a constant, but the two terms of Σg² − (Σg)²/n become small, which avoids catastrophic cancellation when residuals have a large mean (early rounds with a poorly chosen F₀, or targets in the millions). The same 2,000-point stump took 0.8 ms, about 2,500 times faster than the naive search.

The loop. fit sets F₀ (mean or median), then for each round computes the residuals, the pseudo-residuals (residuals for squared loss, their signs for absolute loss), optionally a random row subsample, fits a tree, re-solves the leaves for absolute loss, and adds η × tree to the predictions. It records training loss and, if a validation set is given, validation loss after every tree, which is all you need for early stopping. predict sums the trees, and predict(X, n_trees=k) evaluates the model as it was after k rounds, so the best round can be used without retraining.

LAD leaves. _leaf_values walks the fitted tree with the training rows and replaces each leaf's value with the median of the actual residuals that land there. That is the loss-optimal constant step for absolute error, Friedman's LAD_TreeBoost.

Edge cases worth naming

A constant target makes every residual zero after F₀; every tree is then a single leaf with value 0 and the model is just the mean, which is correct. A feature that is constant offers no splits and is ignored. Very small datasets with min_leaf larger than half the rows produce single-leaf trees, so the model never moves from F₀; the class does not warn, but a production implementation should. Ties between candidate splits (as in round two of the hand example) are broken by the first feature and the first threshold in sorted order, which makes runs reproducible. Missing values are not handled: as in mc5, a NaN compares false with every threshold and would silently go right, so validate inputs first or learn a default direction as XGBoost does.

7. Testing it

The test block checks: the class reproduces the hand round (split at 3.5, predictions 2.5, 2.5, 2.5, 4.5); the naive list booster and the vectorised one agree to 10⁻¹⁰ over 30 rounds on 60 points; the pseudo-residuals equal the negative per-example gradients of half squared error and absolute error, by central finite differences; on a 600-point regression problem (y = sin(x₁) + 0.5x₂² + noise) the training loss never increases and the model explains over 95% of the validation variance; lr = 0.1 reaches a lower best validation loss than lr = 1; and with 2% gross outliers added to the training targets, absolute-loss boosting's validation error is far lower than squared-loss boosting's.

rng = np.random.default_rng(0)

gb1 = GradientBoostingRegressor(n_trees=1, lr=0.5, depth=1, min_leaf=1).fit(x_hand[:, None], y_hand)
assert gb1.trees[0][:3] == ("split", 0, 3.5) and gb1.predict(x_hand[:, None]).tolist() == [2.5, 2.5, 2.5, 4.5]

# 2. The naive list-based booster gives the same predictions as the vectorised one.
xs = rng.uniform(0, 10, 60); ys = np.sin(xs) + 0.1 * rng.normal(size=60)
naive = boost_naive(xs.tolist(), ys.tolist(), n_trees=30, lr=0.3)
vec = GradientBoostingRegressor(n_trees=30, lr=0.3, depth=1, min_leaf=1).fit(xs[:, None], ys).predict(xs[:, None])
assert np.allclose(naive, vec, atol=1e-10)

# 3. Gradient check: the pseudo-residuals are the negative gradients of the losses.
F = rng.normal(size=5); yy = rng.normal(size=5); eps = 1e-6
for loss, neg_grad in (("squared", yy - F), ("absolute", np.sign(yy - F))):
    L = (lambda F_: 0.5 * (yy - F_) ** 2) if loss == "squared" else (lambda F_: np.abs(yy - F_))
    num = -(L(F + eps) - L(F - eps)) / (2 * eps)      # per-example derivative, element-wise
    assert np.allclose(num, neg_grad, atol=1e-6)

# 4. Squared loss, full batch, lr ≤ 1: the training loss never increases; validation has a best round.
def make(n):
    X = rng.uniform(-3, 3, (n, 2))
    return X, np.sin(X[:, 0]) + 0.5 * X[:, 1] ** 2 + 0.1 * rng.normal(size=n)

assert min(gb.val_loss) < min(gb_fast.val_loss)

# 6. Outliers: least absolute deviation boosting is far less disturbed than squared loss.
y_out = y.copy(); y_out[:12] += 40                        # 2% gross outliers in training only

assert err_lad < err_sq

The finite-difference check is the "gradient check" of this problem. A boosting implementation has no weight vector to perturb, but the claim "the pseudo-residual is the negative gradient of the loss with respect to the prediction" is checkable example by example: nudge one prediction by ±ε, measure the loss change, and compare. It catches the most common bug in custom-loss boosting, a sign error (fitting trees to the gradient instead of the negative gradient makes the model walk uphill).

8. Shrinkage, early stopping and the bias-variance picture

Each tree reduces the training loss, so with enough trees the model can fit the training data almost perfectly, noise included. The validation loss tells you when that starts happening. In the test, lr = 1 reached a best validation MSE of 0.049 after 61 trees and got worse afterwards; lr = 0.1 kept improving until about 313 trees, reaching 0.018 (the noise in the targets has variance 0.01, so that is close to the floor), and had crept up to 0.019 by 1,000 trees. Why does shrinkage help so much? A large step commits the model fully to each greedy, noisy tree; many small steps average over many trees' choices, so no single tree's quirks dominate, an effect similar to the averaging in a forest. Friedman found empirically that small learning rates (around 0.1 or less) dramatically improved accuracy, at the cost of more trees, and that is still the standard advice.

Row subsampling (stochastic gradient boosting) adds a different kind of help: each tree sees a random 50-80% of the rows, which decorrelates successive trees and also makes each round cheaper. Column subsampling, sampling a fraction of features per tree or per split, does the same for features and is one of the regularisers the XGBoost paper describes alongside shrinkage.

9. Numerical and practical traps

Trap 1: cancellation in the SSE formula. Described above; centre per node.

Trap 2: the sign of the gradient. Fitting trees to F − y instead of y − F makes every step increase the loss. The monotone-training-loss test catches this in one round.

Trap 3: exploding Newton steps. For log-loss leaves, Σ(y − p)/Σp(1 − p) has a denominator near zero when every example in the leaf has p near 0 or 1. Add a small constant (the drill uses 10⁻¹², XGBoost uses λ) and, in production, cap the step.

Trap 4: an empty leaf when re-solving. When leaves are re-solved on the same sampled rows the tree was fitted on, every leaf holds at least min_leaf of them, so the median or Newton step is well defined. If you re-solve on all rows, or on a different sample, a leaf can end up with no rows; the code then keeps the tree's fitted value instead of taking a median of nothing, which would be NaN.

Trap 5: predicting with the wrong number of trees. Early stopping picks a round, but predict must then use only that many trees. Store the best round with the model.

Trap 6: the initial constant. Starting from 0 instead of the mean wastes the first several trees on learning the mean and, with shrinkage, can take dozens of rounds. Starting from the loss-optimal constant costs nothing.

10. Complexity

Each round fits one tree: with n rows, d features and depth D, the cumulative-sum search costs O(d·n log n) per level for sorting (the sort is the dominant cost), so O(D·d·n log n) per tree, and prediction updates cost O(n·D). Over M rounds the total is O(M·D·d·n log n). Real libraries remove the log factor: XGBoost pre-sorts columns once into blocks (its paper gives O(K·d·‖x‖₀ + ‖x‖₀ log n) for K trees of depth d over ‖x‖₀ non-missing entries), and histogram methods replace sorting with O(n) binning per node. Prediction for one row costs O(M·D) comparisons, a few thousand for a typical model, which is why boosted models serve in microseconds.

11. Talking through the design

In the interview: say "gradient descent in function space" and explain it in one breath (pseudo-residuals are the negative gradient; the tree generalises the step); give the hand round; write the loop with the initial constant, the shrunken update and validation tracking; reuse the cumulative-sum tree; name leaf re-solving for non-squared losses; test monotone training loss and a gradient check; then discuss learning rate, early stopping, subsampling and the second-order view that XGBoost uses.

Second-order boosting: XGBoost's objective

XGBoost replaces the first-order "fit a tree to the gradient" with a second-order expansion. Around the current predictions, each example's loss for an added amount w is approximately L + g·w + ½h·w², where g and h are the first and second derivatives of the loss with respect to the prediction. Add a penalty γT + ½λΣw_j² on the number of leaves T and their values. For a fixed tree structure, each leaf's best value is w* = −G/(H + λ), where G and H sum g and h over the leaf's examples, and the loss falls by ½G²/(H + λ). So a split's gain is ½[G_L²/(H_L + λ) + G_R²/(H_R + λ) − (G_L + G_R)²/(H_L + H_R + λ)] − γ. The split search is the same cumulative-sum scan, accumulating g and h instead of y and y². For squared loss, h = 1 and the gain with λ = 0 reduces to the SSE reduction; for log-loss, the leaf value is the Newton step from the drill. This unification, any twice-differentiable loss through one split formula, is a large part of why XGBoost became the default.

Learning rate and tree count are one knob

Halving the learning rate roughly doubles the number of trees early stopping chooses, and usually improves validation loss slightly, with diminishing returns below about 0.05. So in practice people fix the learning rate from their compute budget (how many trees they can afford to train and serve) and let early stopping set the count, rather than tuning both as if they were independent.

Why λ and γ regularise

λ shrinks leaf values toward zero, more strongly for leaves with little curvature mass H (few examples, or confident examples in log-loss), which is exactly where estimates are noisy. γ is a minimum gain: a split must reduce the loss by more than γ to be kept, which prunes splits that only fit noise. A minimum child weight (a lower bound on H per leaf) is the second-order version of min_samples_leaf.

Huber loss and quantile loss

Huber loss is squared for residuals smaller than δ and linear beyond, so its pseudo-residual is the residual clipped to [−δ, δ]. It behaves like squared loss on ordinary points and like absolute loss on outliers, and Friedman's paper sets δ adaptively as a quantile of the absolute residuals at each round. Quantile loss (the "pinball" loss) has pseudo-residuals of α or α − 1 depending on the residual's sign, and its leaf optimum is the α-quantile of the residuals; boosting with it gives prediction intervals, such as a 90th-percentile delivery time, which is often more useful to a product than the mean.

AdaBoost as a special case

AdaBoost, the original boosting algorithm, reweights misclassified examples and combines classifiers with weights computed from their error rates. Friedman, Hastie and Tibshirani showed that it is exactly forward stagewise additive modelling with the exponential loss e^{−yF} (labels ±1). Gradient boosting with that loss and suitable leaf values reproduces it. This is a good answer to "how are AdaBoost and gradient boosting related?": the same additive, stagewise structure, with gradient boosting allowing any differentiable loss.

Histogram split finding and leaf-wise growth

On large data the sort in each split search dominates. LightGBM bins every feature into at most 255 buckets once; at each node it accumulates G and H per bin in one pass and scans the bins, and it gets the larger child's histogram for free by subtracting the smaller child's from the parent's. It also grows trees leaf-wise, always splitting the leaf with the largest gain anywhere in the tree rather than finishing a level, which reaches lower loss with the same number of leaves but can overfit on small data, hence num_leaves and minimum-data limits. XGBoost's hist mode and scikit-learn's HistGradientBoostingRegressor use the same binning idea.

Monotonic constraints and interpretability

Regulated models often must be monotone in some features: a credit score that rises with income, all else equal. Boosting libraries enforce this by rejecting any split whose child values would violate the required order and by bounding leaf values so that later trees cannot undo it. For explanations, the tree structure allows exact Shapley-value attributions (TreeSHAP) computed in polynomial time, which give each feature's contribution to a single prediction and add up to the prediction minus the baseline F₀. Both are reasons boosted trees remain acceptable in settings where opaque models are not.

Why trees still beat deep learning on tabular data

A 2022 benchmark by Grinsztajn and colleagues across 45 datasets found tree ensembles still ahead of deep models on medium-sized tabular data, and traced it to three properties: trees are not biased toward smooth functions (tabular targets often have sharp jumps), they are robust to uninformative features (a split simply ignores them), and they respect the axis-aligned meaning of individual columns, which rotation-invariant neural networks do not. Those are the same properties that make the tree, rather than a linear model or a neural network, the natural weak learner for boosting.

Where boosted trees run

Fraud and risk scoring, click-through and conversion prediction (often as a stage in a ranking pipeline), search ranking with LambdaMART (boosting with a ranking loss), demand and ETA forecasting, credit scoring, and almost every tabular competition. They are fast to train on a single machine, fast to serve, handle missing values and mixed feature types, and need little preprocessing.

Failure modes and symptoms

Overfitting by tree count. Validation loss rising while training loss falls. Early stopping on a validation set that resembles production (for time-dependent data, a later time period, not a random split) is the fix; random splits on time series make early stopping stop too late.

Leakage amplified. Boosting is excellent at finding and exploiting any feature that encodes the target. A model that is suspiciously good, with one feature dominating gain-based importance, usually has a leak, such as a field filled in after the outcome.

Training/serving skew. A feature computed differently in serving (a missing value encoded as 0 instead of NaN, a different time window) sends rows down different branches. Because trees split sharply, small encoding differences can cause large prediction differences. Log the serving features, replay them through the offline model, and compare.

No extrapolation. A boosted model predicts within the range of training targets; asked about a price or a distance beyond what it has seen, it flattens out. For trends (sales growing over time), detrend first or combine with a linear model.

Calibration drift. Classification models trained with log-loss are roughly calibrated, but early stopping, class weights and subsampling distort probabilities. Check calibration on held-out data and recalibrate if the product uses probabilities.

Serving cost, estimated

A model with 500 trees of depth 6 makes 3,000 comparisons per prediction, each a load and a branch: a few microseconds on a CPU once the features are in memory. The real cost is usually feature retrieval, not the trees. Libraries and compilers (XGBoost's predictor, LightGBM's, Treelite) lay the trees out as flat arrays and evaluate many rows at once, the same flat-array idea as mc5's lock-step predict. Model size is small too: each node stores a feature index, a threshold and two child indices, so the whole model is a few megabytes at most.

What to monitor and tune

Tune in this order: learning rate (fix it smallish, 0.05-0.1), then let early stopping choose the number of trees; then depth or num_leaves and minimum leaf size; then subsampling rates; then λ and γ. Monitor the best iteration across retrains (a sudden change signals a data shift), gain-based and permutation feature importances, the share of missing values per feature, and the prediction distribution in production against training.

Work it out

Switch to binary classification with log-loss. What is the initial prediction, what are the pseudo-residuals, and what should a leaf's value be? Implement it by reusing fit_tree for the tree structure.

Answer

Work in log-odds. Initialise F₀ = log(p̄ / (1 − p̄)). The pseudo-residual is y − p with p = σ(F). The squared-error tree fitted to it gives the structure, but its leaf means are the wrong step size; the Newton step for a leaf is Σ(y − p) / Σp(1 − p) over the rows in that leaf. So re-solve the leaves after fitting.

def sigmoid(z):
    return np.where(z >= 0, 1 / (1 + np.exp(-np.abs(z))), np.exp(-np.abs(z)) / (1 + np.exp(-np.abs(z))))

def newton_leaves(node, X, g, h):
    """Rebuild a tree's leaves with the Newton step Σg / Σh over the rows in each leaf."""
    if node[0] == "leaf":
        return ("leaf", g.sum() / (h.sum() + 1e-12)) if len(g) else node
    _, f, t, l, r = node
    m = X[:, f] <= t
    return ("split", f, t, newton_leaves(l, X[m], g[m], h[m]), newton_leaves(r, X[~m], g[~m], h[~m]))

def boost_logloss(X, y, n_trees=100, lr=0.1, depth=3):
    p0 = y.mean()
    F = np.full(len(y), np.log(p0 / (1 - p0)))
    losses = []
    for _ in range(n_trees):
        p = sigmoid(F)
        tree = fit_tree(X, y - p, depth)                  # structure from the pseudo-residuals
        tree = newton_leaves(tree, X, y - p, p * (1 - p))  # Newton step per leaf
        F += lr * predict_tree(tree, X)
        losses.append(np.mean(np.logaddexp(0, F) - y * F))
    return F, losses

Xc = rng.uniform(-3, 3, (500, 2))
yc = (Xc[:, 0] ** 2 + Xc[:, 1] ** 2 < 4).astype(float)     # a circle: not linearly separable
F, losses = boost_logloss(Xc, yc)
assert losses[-1] < 0.3 * losses[0] and ((F > 0) == yc).mean() > 0.95

This is the mechanism XGBoost generalises: gradient for the structure, gradient over Hessian for the leaf weights, with λ added to the denominator as regularisation. The sigmoid here is the overflow-free form from mc2, and the loss is computed from logits with logaddexp.
