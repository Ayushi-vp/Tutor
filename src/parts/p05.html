The decomposition

For squared error, expected test error at a point splits exactly into bias² + variance + irreducible noise. Bias is the error from the model class being too rigid to represent the truth. Variance is how much the fitted function moves when you resample the training set. Noise is the part no model can remove — label noise, missing features, genuine randomness.

Capacity trades one against the other. A depth-1 tree has huge bias and near-zero variance; a fully grown tree has near-zero bias and huge variance. The classic U-shaped test-error curve is the sum.

How to use it as a diagnostic

  • High train error, high validation error, small gap → underfitting (bias). Add capacity, add features, train longer, weaken regularisation.
  • Low train error, high validation error, big gap → overfitting (variance). More data, stronger regularisation, augmentation, simpler model, early stopping.
  • Both errors near the noise floor → you are done; further work must change the data, not the model.

The modern wrinkle: double descent

Push capacity far past the interpolation threshold (where the model can fit the training set exactly) and test error often falls again. Massively over-parameterised networks land in the second descent, which is why "just make it bigger" works for deep learning in a way it never did for polynomial regression. Saying this out loud signals you have read past the textbook.

Common trapThe decomposition is exact only for squared loss. For 0–1 loss the analogous split is not additive — say "the intuition carries, the algebra does not" rather than claiming a clean decomposition for classification.

What the penalty does

You minimise loss(w) + λ·R(w). With L2 (ridge), R = ||w||²; the gradient contribution is 2λw, proportional to the weight, so it shrinks everything smoothly and never quite reaches zero. With L1 (lasso), R = ||w||₁; the gradient is λ·sign(w), a constant push toward zero regardless of magnitude, so small weights get pushed all the way to exactly zero. L1 therefore selects features; L2 only damps them.

The geometry — the answer they want

Equivalently, you minimise the loss subject to ||w|| ≤ t. The L2 constraint region is a ball; the L1 region is a diamond with corners on the axes. Elliptical loss contours grow until they touch the region, and a diamond's corners stick out — so the first contact is very often exactly at a corner, where some coordinate is zero. A ball has no corners, so contact is generically off-axis.

Everything else that is secretly regularisation

  • Early stopping ≈ L2 for gradient descent on a quadratic loss.
  • Dropout ≈ training an exponential ensemble of subnetworks; an adaptive L2 in expectation.
  • Data augmentation encodes invariances — the strongest regulariser of the lot when the invariance is real.
  • Weight decay in AdamW is decoupled from the adaptive step size — this is precisely why AdamW beats "Adam + L2 in the loss".
  • Label smoothing caps the logit gap and improves calibration.
Interview angle"Your model has 10,000 correlated features and 800 rows." L1 will pick one feature per correlated group arbitrarily and is unstable across resamples; elastic net (L1 + L2) keeps groups together. That instability answer is what separates a memorised answer from a used-it answer.

The update

w ← w − η ∇L(w). The gradient gives the steepest-ascent direction; η decides how far you trust it. On a quadratic with curvature c, the iteration converges only when η < 2/c — above that the step overshoots further than it started and the loss explodes. That single inequality explains almost every "my loss went to NaN" story.

Batch, stochastic, mini-batch

Full-batch gradients are exact and expensive. SGD uses one example — cheap, noisy, and the noise itself acts as a regulariser that helps escape sharp minima. Mini-batch (32–1024, or millions of tokens for LLMs) is the practical middle: enough samples to use the hardware, enough noise to generalise. Larger batches need a proportionally larger learning rate (the linear scaling rule) plus warmup, or the first steps are catastrophic.

The optimisers you must be able to contrast

  • Momentum — accumulates an exponentially-weighted velocity; damps oscillation across a ravine and accelerates along it.
  • RMSProp — divides by a running RMS of the gradient, giving each parameter its own effective step size.
  • Adam — momentum + RMSProp + bias correction. The default for almost everything.
  • AdamW — Adam with weight decay applied directly to the weights rather than folded into the gradient. The standard for transformers.

Schedules

Linear warmup for the first 1–5% of steps (Adam's second-moment estimate is garbage at step 0), then cosine decay to roughly 10% of peak. Ask any LLM training question and this schedule is the expected answer.

One tree

Greedy recursive partitioning: at each node pick the (feature, threshold) that most reduces impurity — Gini or entropy for classification, variance for regression. Trees need no scaling, handle mixed types and non-linearities natively, and are trivially interpretable at depth 3. Alone they are high-variance: change a few rows and the whole structure shifts.

Sequential: each new shallow tree fits the residual errors (formally, the negative gradient of the loss) of the ensemble so far, added with a small learning rate. The curse, stated precisely

Draw points uniformly in d dimensions. As d grows, the ratio (max distance − min distance) / min distance from a query to its neighbours tends to zero. Every point becomes roughly equidistant, so "nearest" stops meaning anything and any index that relies on partitioning space degenerates to a full scan. Volume also concentrates: a unit hypercube's mass sits almost entirely in its corners, and a shell of thickness 0.01 holds most of a hypersphere's volume.

Why embeddings still work at 1536 dimensions

Because real embeddings are not uniform — they live on a much lower-dimensional manifold with strong structure, and cosine similarity measures direction rather than volume. The intrinsic dimension is far below the ambient one. This is the answer to "if the curse is real, how does my vector database function?"

Practical consequences

  • Exact k-NN is O(n·d) per query — fine at 10⁴ vectors, hopeless at 10⁸. Hence ANN indexes: HNSW (graph, high recall, memory-hungry), IVF-PQ (cluster + compress, memory-efficient, lower recall), ScaNN.
  • ANN trades recall for latency. Always report recall@k against an exact brute-force baseline on a sample — "we use HNSW" is not an answer, "HNSW at efSearch 128 gives recall@10 of 0.96 at p95 8ms" is.
  • Normalise vectors if you are using cosine; then inner product and cosine rank identically and you can use the faster kernel.

The mechanism

A network is a directed graph of differentiable ops. The forward pass computes and caches each intermediate activation. The backward pass walks the graph in reverse, and at each node multiplies the incoming gradient by that node's local Jacobian — reverse-mode automatic differentiation. One backward pass gives you the gradient with respect to every parameter at roughly the cost of one forward pass, which is what makes training millions of parameters feasible at all.

What this costs

Memory, not compute. You must keep every activation needed by a backward op, so peak memory scales with batch × sequence × hidden × layers. The standard remedies: gradient checkpointing (store only layer boundaries, recompute the rest — roughly 30% more compute for a large memory saving), mixed precision (bf16 activations), and gradient accumulation to emulate a large batch on small hardware.

Things that break it

  • In-place operations that overwrite a cached activation — the classic PyTorch autograd error.
  • Detached tensors silently cutting the graph, so a whole branch stops learning.
  • Forgetting zero_grad() — gradients accumulate by default, so you are effectively training on a growing sum.

Where it comes from

The gradient at layer l is a product of L − l Jacobians. If their typical singular value is below 1, the product decays geometrically and early layers stop learning; above 1 and it explodes to NaN. Depth turns a small multiplicative bias into an exponential one.

  • Gating — LSTM/GRU cell state is an additive path, the recurrent analogue of a residual.

BatchNorm

Normalises each feature across the batch, then rescales with learned γ, β. Works beautifully for CNNs: it smooths the loss landscape, allows higher learning rates and acts as a regulariser through batch noise. The progression

SGD + momentum: one global learning rate, a velocity buffer. Often generalises best on vision if you are willing to tune the schedule. Adam: per-parameter step sizes from a running estimate of the gradient's first moment (m) and second moment (v), with bias correction for the first few steps. Robust to badly-scaled gradients, which is why it dominates NLP where gradient magnitudes vary hugely across embedding and attention parameters.

Adding λ||w||² to the loss means the decay term also gets divided by √v, so parameters with large gradients get less decay — the opposite of the intent. AdamW decouples it: w ← w − η(m̂/(√v̂+ε) + λw). This is not a detail; it is the reason AdamW is the transformer default.

Adam keeps m and v per parameter. For a 7B model in mixed precision: 14 GB weights (bf16) + 14 GB gradients + 28 GB optimiser states in fp32 + an fp32 master copy ≈ 84 GB before a single activation.   • Locality — nearby pixels are related, so a kernel only looks at a small window.
  • Weight sharing — the same edge detector is useful everywhere, giving translation equivariance and cutting parameters by orders of magnitude.
  • Hierarchy — stacking expands the receptive field; early layers learn edges, deep layers learn objects.

Numbers to have ready

Output size = ⌊(n + 2p − k)/s⌋ + 1. A 3×3 kernel over C_in channels producing C_out channels has 3·3·C_in·C_out + C_out parameters. Two stacked 3×3 layers see the same 5×5 receptive field as one 5×5 layer with fewer parameters and an extra non-linearity — the VGG insight. 1×1 convolutions mix channels without touching space, which is how bottleneck blocks control cost.

Against Vision Transformers

A ViT throws the convolutional prior away and lets attention learn relationships between patches. With enough data (JFT-300M scale) that wins, because the learned relationships beat the hand-coded ones. With ImageNet-scale data alone, CNNs win — the prior is worth a lot of examples. Hybrid designs and heavy augmentation (DeiT) close much of the gap. "Inductive bias substitutes for data" is the sentence to say.

Why they existed

An RNN carries a hidden state forward: h_t = f(Wx_t + Uh_{t−1}). Parameter count is independent of sequence length, and the same weights apply at every step. Backpropagation through time unrolls the recurrence, and the repeated multiplication by U is exactly the vanishing/exploding gradient problem in its purest form.

LSTM and GRU

LSTM adds a cell state updated additively, controlled by forget, input and output gates — the additive path is what preserves gradient over hundreds of steps. GRU merges the forget and input gates into an update gate and drops the separate cell state: fewer parameters, similar quality, faster.

The two failures that killed them

  1. The fixed-size bottleneck. An encoder–decoder had to compress an entire sentence into one vector. Attention was introduced precisely to let the decoder look back at all encoder states — and the transformer is the result of noticing that if attention works, you do not need the recurrence at all.
  2. No parallelism. Step t needs step t−1, so training cannot use a GPU's width. Transformers compute all positions at once — the practical reason they scaled and RNNs did not.
Still worth knowingState-space models (Mamba, S4) revive the recurrent idea with a parallel scan, giving linear-time sequence modelling with long context. If you are asked "what comes after the transformer", that is the informed answer.

Dropout

Randomly zero each unit with probability p during training. Prevents co-adaptation — no unit can rely on a specific partner being present — and approximates averaging an exponential family of subnetworks. At inference, dropout is off; frameworks use inverted dropout (divide by 1−p during training) so no rescaling is needed at test time. Forgetting model.eval() is the single most common evaluation bug in PyTorch, and it also leaves BatchNorm in the wrong mode.

Note that dropout has largely fallen out of favour inside large transformers trained on huge corpora — with a dataset that large, one pass sees each token once and there is little to overfit. It remains standard for fine-tuning on small datasets.

Data augmentation

The strongest regulariser available when the invariance is genuine: flips, crops, colour jitter, mixup and CutMix for images; back-translation, span deletion and paraphrase for text; SpecAugment for audio. Augmenting with an invariance the task does not have (flipping digits, so 6 becomes 9) actively hurts.

Early stopping

Monitor validation loss, keep the best checkpoint, stop after patience epochs. Free, and for a quadratic loss provably similar to L2. Pair it with checkpoint averaging when the validation curve is noisy.

Data parallel

Every device holds a full copy of the model and processes a different shard of the batch; gradients are all-reduced each step. Simple and the default up to the point where the model itself stops fitting. ZeRO / FSDP extends it by sharding optimiser states (stage 1), gradients (stage 2) and parameters (stage 3) across devices, gathering each layer's weights just in time — trading extra communication for a near-linear memory reduction.

Tensor parallel

Split individual matrices across devices — column-parallel then row-parallel through an MLP block so only one all-reduce is needed per block. Very communication-heavy, so it is kept inside a node where NVLink bandwidth is available.

Pipeline parallel

Assign contiguous layer groups to different devices and stream micro-batches through. Cheap communication (activations at boundaries only), but introduces the bubble — idle time while the pipeline fills and drains, roughly (stages − 1)/(micro-batches + stages − 1). More micro-batches shrink it; interleaved schedules shrink it further.

The expected shape of an answer: 3D parallelism — tensor parallel within each 8-GPU node, pipeline parallel across a few node groups, data parallel with ZeRO across the rest; bf16 with fp32 master weights; gradient checkpointing; global batch in the millions of tokens with warmup and cosine decay. Then talk about checkpointing cadence and failure recovery, because on 64 GPUs something fails.
